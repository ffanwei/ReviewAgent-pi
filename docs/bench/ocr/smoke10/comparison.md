# OCR vs review-pi：smoke10 对比

> 同一批 10 条样本、同一个 judge（`deepseek-v4-pro`，3 轮平均）、同一套文件级语义指标。
> OCR：`open-code-review v1.13.10` + `deepseek-v4.1-flash`；review-pi：`0.6.1` + `deepseek-v4.1-flash`。
> smoke10 是 outcome-stratified 开发集（5 条基线有命中 / 5 条基线零命中），不是无偏指标。

## 总体

| 指标 | OCR | review-pi | 差异 |
|---|---:|---:|---:|
| Precision | **0.2517** | **0.2500** | +0.0017 |
| Recall | **0.2900** | **0.2463** | **+0.0437** |
| Balanced | **0.2697** | **0.2477** | **+0.0220** |
| 覆盖 GT | 13.33 / 46 | 11.33 / 46 | +2.0 |
| 生成意见 | 49 | 44 | +5 |
| 总 token（含 cache） | **19,369,707** | **4,113,194** | **4.71×** |
| token（非缓存 input+output） | **2,139,883** | **649,130** | **3.30×** |
| 评审耗时合计 | **2,419s** | **1,838s** | **1.32×** |

> review-pi 的 0.250/0.246/0.248 是 smoke10 的 3 轮基线；全量 108 条的 0.073/0.175/0.103 不适用于这 10 条，仅作参考。

## 解读

1. **precision 几乎一样，OCR 用更多 token 换来更高 recall。**
   OCR +4.4pp recall、+2.2pp balanced，precision 只高 0.17pp；代价是 4.7× 总 token / 3.3× 非缓存 token、1.3× 时间。

2. **OCR 在 5 条上更好，review-pi 在 3 条上更好，2 条打平。**
   - OCR 更好：`gofr`、`spring-ai`、`ragflow`、`cline`，以及 `opencv`（B 0.261 vs 0.255）；
   - review-pi 更好：`lvgl`、`filament`、`linera`；
   - 打平：`osu`、`svelte`（两边都是 0）。

3. **OCR 的 token 高度集中且不保证收益。**
   `svelte` 一条就花了 **8.31M token**，覆盖 0 条 GT；`opencv` 6.93M，覆盖 3 条。两条合计 15.24M，占 OCR 总 token 的 **78.7%**。review-pi 在 `svelte` 上只花 0.37M，结果同样是 0。

4. **小样本，结论是方向性的。**
   10 条 / 46 GT，3 轮 judge 的 B 噪声约 ±0.005–0.01；+0.022 的 balanced 差异在噪声之上，但样本量不足以做稳定排名。smoke10 还是 outcome-stratified 的开发集，不能外推到全量。

5. **版本差异。**
   OCR v1.13.10 与官方 leaderboard 的 v1.3.1/v1.8.7 不同，token/时间不能与官方表逐行对齐；这里只做同环境、同数据、同 judge 的横向对比。

## 结论

在 smoke10 上，**OCR 用约 4.7× 的总 token（3.3× 非缓存）和 1.3× 的时间，换来 +4.4pp recall / +2.2pp balanced，precision 基本持平。** 两者不是简单的谁更好：OCR 更贵、召回略高；review-pi 更便宜，在部分样本上定位更准。
