# 离线估算：excludeGlobs 与意见预算（不重跑 review-pi）

方法：拿已跑完的 review-pi 结果 + 已有 judge 匹配，在**输出侧**过滤/重排后重放覆盖关系。
不调用模型、不重跑 review-pi。注意：这是**输出侧近似**；真正的输入侧过滤会改变模型看到的 diff，
可能改变模型在剩余文件上的行为，精确结果仍需重跑。

## 1. 提议的 excludeGlobs 效果（91 条交集）

| 指标 | baseline | +excludeGlobs | 差异 |
|---|---:|---:|---:|
| 生成意见 | 1242 | 1180 | −62（5.0%） |
| 命中新 GT | 97 | 96 | −1 |
| 覆盖 GT | 106 | 105 | −1 |
| Precision | 0.0781 | 0.0814 | +0.0033 |
| Recall | 0.1803 | 0.1786 | −0.0017 |
| Balanced | 0.1090 | 0.1118 | +0.0028 |
| 有 GT 文件内意见占比 | 21.3% | 22.1% | +0.8pp |

108 条 ok 上同样很小：1242→1419（−70，4.7%），P 0.0725→0.0754，R 0.1746→0.1731，B 0.1025→0.1050。

**原因**：978 条无 GT 意见里，大头是 `.ts/.py/.java/.go/.c/.js/.tsx/.cpp` 等代码文件；提议的 globs 主要命中
`.yml`（52）、锁文件/生成物，且**没有包含通用 `**/*.json`**（只有 package-lock / *.vocab），所以只删掉 62 条。
另外被排除文件里有 4 条 GT，baseline 覆盖了其中 1 条；过滤会损失这 1 条召回。

**结论：excludeGlobs 是噪声卫生，不是本次差距的杠杆。**

## 2. 更有效的离线杠杆：每 PR / 每文件意见预算

按 `severity → confidence` 排序，保留每 PR 前 N 条，并限制每文件最多 M 条；重放覆盖关系：

| 预算 | 保留意见 | Precision | Recall | Balanced | 有 GT 文件内占比 |
|---|---:|---:|---:|---:|---:|
| 无预算（baseline） | 1242 | 0.0781 | 0.1803 | 0.1090 | 21.3% |
| top 10 / file 3 | 622 | 0.1254 | 0.1378 | 0.1313 | 27.7% |
| **top 8 / file 3** | **542** | **0.1347** | 0.1293 | **0.1319** | **30.3%** |
| top 8 / file 2 | 518 | 0.1255 | 0.1156 | 0.1204 | 27.2% |
| top 6 / file 3 | 438 | 0.1484 | 0.1156 | 0.1300 | 33.3% |
| top 4 / file 2 | 302 | 0.1490 | 0.0782 | 0.1026 | 34.4% |

**top 8 / file 3** 把 balanced 从 0.109 提到 0.132（+21%），precision 从 7.8% 提到 13.5%，代价是 recall
18.0% → 12.9%。这比 excludeGlobs 的 +0.003 大一个量级，但仍远低于 OCR 的 0.339。

## 3. 解读

1. **excludeGlobs 单独做，收益很小**：只去掉 5% 意见，指标变化在噪声附近。
2. **预算/排序更接近问题**：它直接压分母，并把意见密度从 13.6 拉向 GT 的 6.5；balanced 提升明显。
3. **两者都不够**：即使 top 8/file 3，有 GT 文件内占比也只有 30.3%（OCR 82.0%），说明还需要**文件靶向/规则层**
   的结构性改造，不能只靠输出裁剪。
4. **精确结果需要重跑**：输入侧 excludeGlobs 会改变 diff 内容和模型注意力；预算如果做成产品输出侧，
   则离线模拟更接近真实，因为预算本来就在输出侧。

## 4. 建议

- 先把**意见预算 + 排序**做成可配置的输出侧能力（离线模拟已显示收益）；
- 再加**反射/过滤**，去掉不动作、非 diff 引入、纯 style 的意见；
- excludeGlobs 作为噪声卫生保留，但不要期待它单独改变指标；
- 规则层/确定性文件选择作为下一阶段的结构性实验。

## 5. 每文件最大意见数单独做：几乎无效

只限制每文件最多 M 条（按 severity/confidence 保留前 M 条），不加每 PR 全局预算：

| 每文件上限 | 保留意见 | Precision | Recall | Balanced |
|---|---:|---:|---:|---:|
| 无上限 | 1242 | 0.0781 | 0.1803 | **0.1090** |
| 1 | 807 | 0.0743 | 0.1139 | 0.0900 |
| 2 | 1050 | 0.0733 | 0.1463 | 0.0977 |
| 3 | 1136 | 0.0783 | 0.1667 | 0.1066 |
| 4 | 1181 | 0.0779 | 0.1718 | 0.1072 |
| 5 | 1206 | 0.0788 | 0.1769 | 0.1090 |
| 6 | 1222 | 0.0786 | 0.1786 | 0.1091 |
| 8 | 1235 | 0.0777 | 0.1786 | 0.1083 |

**结论：单独做 per-file cap 基本无效，甚至略差。** 原因是 review-pi 的 978 条无 GT 意见分布在
686 个 (instance, file) 组合，平均只有约 1.4 条/文件；大多数文件只有 1 条意见，per-file cap 2–3
根本碰不到它们。cap 3 只删掉 106 条（1242→1136），recall 从 0.180 掉到 0.167，precision 几乎不变。

真正有效的是**每 PR 全局预算**：top 8 / file 3 → 542 条，B 0.1319；top 10 / file 3 → 622 条，B 0.1313。
也就是说，**要砍的是“长尾文件上的一条意见”，而不是“同一文件内的第 4 条意见”。**
