# 0063. 规则 Skill 会话缺省总超时 600 s → 1200 s

**状态**：已接受（2026-11-09，用户决策）
**关联**：[ADR-0014](0014-rule-skill-review-pass-after-candidates-phase.md)（规则 Skill 独立会话）、[ADR-0051](0051-llm-call-retry-and-timeout.md)（分层重试与超时）、[ADR-0046](0046-configurable-max-rounds.md)（轮次上限是成本线而不是失败线）、[ADR-0062](0062-one-shot-timeout-default-300s.md)（一次性调用缺省 300 s）
**范围**：本仓 pi 线 0063。只改**缺省值**：`limits.timeouts.skillPassMs`（单个规则 Skill 会话的总超时）从 `600000`（10 分钟）改为 `1200000`（20 分钟）。`reviewTurnMs`（单次请求建立 180 s）、`skillBashMs`、`skillPassLog` 语义、候选合并口径、退出码都不动；显式配置仍然覆盖缺省，合法上限仍为 `3_600_000`。

## Context

规则 Skill 会话是一次**独立的多请求工具循环**（ADR-0014）：种子是 Phase 5 的消息快照，模型在会话里反复调检视工具与 `bash`（跑规则包脚本），直到自己收尾。`skillPassMs` 是这整个会话的硬预算——到点由 `runWithTimeout` 直接判 `session` 失败。

10 分钟的缺省来自单包、单语言、规则条目较少的时期。三个变化让它的余量变薄：

- **大 MR 分片**（ADR-0039）：每片都跑一次完整六阶段 + 规则 Skill；单片输入变大后，规则命中面与工具往返都随之变多；
- **规则包变重**：规则包可以带脚本，模型需要多轮 `bash` 探索（`filter_rules.py --list` → 关键词筛选 → 读取具体规则）；
- **重试依赖外层预算**：会话内单请求重试是 `reviewTurnAttempts`（ADR-0051），但 `skillPassMs` 是整会话总预算，重试不会绕过它——预算太紧时，一次慢请求的两次重试就会把后面的工具轮次挤掉，最终表现为会话级失败而不是请求级失败。

实测 `large-mr` e2e 的规则 Skill 会话约 85 s（7 次请求，最长单请求 47.8 s），10 分钟在本次远未触顶。这项改动是**余量决策**而不是故障复盘：正常路径上超时值只是上限，调大不增加任何耗时；真正的代价只出现在「会话挂死」时，止损点从 10 分钟变成 20 分钟。

## Decision

### 1. 缺省 `skillPassMs` 改为 `1_200_000`

- `DEFAULT_LIMITS.timeouts.skillPassMs` = `1_200_000`；
- `config init` 模板与仓库根 `PiAgent.example.jsonc` 同步（两者仍逐字节相等）；
- 用户显式配置继续覆盖缺省，无迁移动作。

### 2. 合法上限保持不变

`limits.timeouts.skillPassMs` 的合法域仍是 `1000..3600000`。20 分钟是**缺省**，不是新上限；需要更长的环境仍可显式调到 60 分钟。

### 3. 不连带调整 `reviewTurnMs`

`reviewTurnMs` 是**单次请求建立**的超时（流式，只等响应头），与会话总预算正交。把会话预算调大不需要、也不应该同步调大单请求超时——后者调大会拖慢「网关卡在首字节」时的失败发现。

## Options（为什么不是别的）

- **保持 600 s，只写在文档里让用户自己调**：否。规则 Skill 是大 MR 路径的固定组成，10 分钟在重规则包 + 慢网关下会直接判会话失败（且失败后候选整批丢失），让每个用户默认踩一次不划算。
- **改成 30 分钟或 60 分钟**：否。会话挂死时的止损窗口会被拉得过长；20 分钟对正常会话已有十几倍余量，更长需求用显式配置表达。
- **给会话加「无进展检测」而不是调大预算**：否（至少本次不做）。需要定义「进展」信号（新工具结果？新候选？），会引入新的判定口径与审计键；先解决默认余量，再谈自适应。
- **把 `skillPassMs` 拆成「每请求预算 × 请求数」**：否。会话的请求数由模型决定、不可预知；总数预算才是会话级兜底。

## Consequences

- **好**：重规则包 + 大分片 + 慢网关的组合下，规则 Skill 会话不再因为 10 分钟墙钟被整段丢弃；单请求重试有足够空间完成。
- **代价 / 风险**：会话真挂死时，止损从 10 分钟延到 20 分钟；最坏墙钟随之外扩。需要更快失败的环境可显式调低。
- **文档面**：`docs/使用手册-安装与运行.md` 的模板与键表同步；`CONTEXT.md` 的自定义术语按需提及。
- **测试面**：`shared/config.test.ts` 的「缺省模板与运行期缺省同源（防漂移）」断言同步为 `1_200_000`；模板逐字节同源断言继续覆盖 `PiAgent.example.jsonc`。
