# 0103. 三种「零」恢复诚实区分；星级判据只陈述计数

**状态**：已接受（2026-11-18，用户决策）
**关联**：[ADR-0100](0100-unified-summary-shape-except-diff-too-large.md)（四节结构与统一零路径；本 ADR 修订其决策 2 的正文口径）、[ADR-0097](0097-summary-fixed-structure-and-stars.md)（星级判据；本 ADR 修订其判据文案）、[ADR-0057](0057-summary-covers-only-reported-findings.md)（已上报集合是唯一信源；恢复其零上报的诚实口径）、[ADR-0078](0078-review-scope-include-exclude-regex.md)（无可检视文件；恢复其「没检视」语义）、[ADR-0075](0075-diff-too-large-skip-with-report.md)（超大 diff 固定文案不变）
**范围**：本仓 pi 线 0103。只改零路径的说明句 / 星级行与星级判据文案；四节结构、指标、上报时机、退出码、审计键集不变。

## Context

ADR-0100 把三种「零」统一成同一份正文（「本次检视未发现缺陷。」+ ⭐⭐⭐⭐），用户随后发现两处问题：

1. **零意见的四星判据自相矛盾**：`STAR_CRITERIA[4]` 是按「只有 suggestion」写的——「0 条 fatal / major / minor，仅 suggestion 且代码体现防御性设计」。空集合也落四星，于是零意见打印「仅 suggestion」，但意见分布四行全是 0。
2. **另两种零在总结里说得比事实强**：
   - 有意见但全部没上报 → 写「未发现缺陷」+ ⭐⭐⭐⭐；
   - 过滤后无可检视文件 → 同样写「未发现缺陷」+ ⭐⭐⭐⭐，等于把「没检视」评成「没问题」。

另外，三星 / 四星判据里的「代码逻辑正确可合入」「代码体现防御性设计」不是计数能推出的结论，属于主观断言。

## Decision

### 1. 保留四节结构与指标，恢复三种零的诚实正文

三种零共用同一个 `renderStructuredSummary`（结构、变更规模、预算、资源、省略速览节都不变），只在说明句与星级行上区分：

| 零的原因 | 说明句 | 星级行 |
|---|---|---|
| 确实无意见 | `本次检视未发现缺陷。` | `⭐⭐⭐⭐ — 0 条 fatal / major / minor / suggestion（未发现缺陷）` |
| 有意见但全部没上报 | `本次检视未向平台上报任何检视意见。` | `—（未上报任何检视意见，不作星级评价）` |
| 过滤后无可检视文件 | `无可检视文件，跳过检视。` | `—（未检视任何文件，不作星级评价）` |

判定来源：`buildReviewSummary` 以 `unreportedFindings > 0` 区分「确实零意见」与「零上报」；`deliverSkip` 的 `no-reviewable-files` 路径显式传入 `no-reviewable-files`。

### 2. 星级判据只陈述计数

```ts
2: "存在 ≥1 条 major 或 fatal 意见"
3: "0 条 fatal，0 条 major，仅 minor / suggestion"
4: "0 条 fatal / major / minor，仅 suggestion"
零意见："0 条 fatal / major / minor / suggestion（未发现缺陷）"
```

删除「需整改后方可合入」「代码逻辑正确可合入」「代码体现防御性设计」这类无法由计数推出的断言。

### 3. 保持不变

- 超大 diff 的固定文案 `# 检视总结\n\nDiff 超大，跳过检视。`（ADR-0075）；
- 零路径不调用模型；
- 四节结构与 `reviewer` 指标口径；
- 平台侧差异仅体现在总结正文，stdout / stderr / 审计仍保留更细的现场。

## Options（为什么不是别的）

- **维持 ADR-0100 的完全统一**：总结把「没上报 / 没检视」说成「未发现缺陷」，平台无法分辨；用户明确要求修复。否。
- **零上报 / 未检视也保留四星但换说明句**：星级仍表示「代码没问题」，与事实不符。否。
- **零意见不给星级**：与 ADR-0100 的「确实干净 = 四星」冲突；空集合判四星有明确规则。否。
- **判据保留主观结论**：计数无法支撑，且模型只需照抄，错误会被放大。否。

## Consequences

- **好**：总结正文重新与事实一致；平台能区分「真干净 / 没上报 / 没检视」；判据可逐条用分布表验证。
- **代价**：三种零不再是同一段正文，平台若按单一形态解析需要接受三个说明句 / 星级行；结构化模板与指标仍完全一致。
- **测试面**：`review-summary.test.ts`（三种零的说明句与星级、零意见专用判据、二/三/四星判据）、`delivery.test.ts`（无可检视文件的诚实文案）、`bin.process.test.ts`（预过滤全剔 / `--include` 未命中 / 零上报 / 置信度全滤 / tips 全跳过）。
