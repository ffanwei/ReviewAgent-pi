# 0100. 收尾总结形态统一：除超大 diff 外全部走四节模板

**状态**：已接受（2026-11-18，用户决策）
**关联**：[ADR-0097](0097-summary-fixed-structure-and-stars.md)（四节结构与星级硬判据；本 ADR 修订其决策 6 / 8）、[ADR-0057](0057-summary-covers-only-reported-findings.md)（总结只覆盖已上报意见；本 ADR 修订其决策 3 的零上报形态）、[ADR-0078](0078-review-scope-include-exclude-regex.md)（无可检视文件跳过；本 ADR 修订其决策 5 的固定总结）、[ADR-0075](0075-diff-too-large-skip-with-report.md)（超大 diff 跳过）、[ADR-0045](0045-mcp-business-task-tools.md)（收尾总结上报）
**范围**：本仓 pi 线 0100。只改零上报 / 无可检视文件两种总结的 Markdown 形态与指标来源；「已上报集合是唯一信源」（ADR-0057 决策 1/2）、跳过判定、stdout / 退出码 / 审计 / 转录均不变；超大 diff 的固定总结也不变。

## Context

ADR-0097 落地后，收尾总结仍有两种零路径不是四节模板：

- **有 findings 但一条都没上报**：四节结构，但说明句是「本次检视未向平台上报任何检视意见。」，星级写「—（未上报任何检视意见，不作星级评价）」；
- **过滤后无可检视文件**（ADR-0078）：纯文案 `# 检视总结\n\n无可检视文件，跳过检视。`，连「检视总览」都没有。

平台需要按固定结构渲染总结，而这两种形态让消费方必须额外识别分支；同时「无可检视文件」路径其实拿得到变更规模（`main.ts` 在过滤前就算好了 `measureDiffScale`），只是没有下发。

用户于 2026-11-18 决策：**除超大 diff 外，所有收尾总结都总结变更、使用同一格式**。三种「零」（确实无意见 / 有意见但没上报 / 无可检视文件）在总结里不再区分。

## Decision

1. **统一模板**：除 `diff-too-large` 外，`saveReviewSummary` 的正文恒为 ADR-0097 的四节结构——`## 检视总览`（变更规模 / 预算使用 / 资源加载）、`### 意见分布`、`### 高优先级意见速览`、`### 星级评价`。三种零路径省略「高优先级意见速览」节（没有意见可速览），不调用模型。
2. **三种零的正文完全一致**：说明句统一为「本次检视未发现缺陷。」，星级统一按空集合硬判据给 ⭐⭐⭐⭐。不再输出「未向平台上报任何检视意见」，也不再输出「不作星级评价」。
3. **无可检视文件的指标**：
   - 变更规模 = 过滤前 diff 的 `measureDiffScale`（与 ADR-0068 的「变更文件全集」同口径）；不可度量时按既有规则渲染「变更规模不可度量」；
   - 预算使用 = `0 次调用`；
   - 资源加载 = `约 0 tokens`。
   以上由 `deliverSkip` 通过新增的 `metrics` 入参接收，渲染函数与零意见路径共用 `renderZeroFindingSummary`。
4. **超大 diff 仍是固定文案**：`# 检视总结\n\nDiff 超大，跳过检视。`（ADR-0075），不套四节模板。
5. **差异只留在报告之外**：三种零的原因仍可从 stdout 的 `skipped`、stderr 的跳过 / 差额行与 `mcp.json` 区分；总结正文不再承担区分职责。

## Options（为什么不是别的）

- **保留零上报的诚实文案与「不作星级评价」**：平台要维护两种零形态；用户明确要求统一，否。
- **保留无可检视文件的纯文案**：同样让平台多一个分支，且浪费已经算好的变更规模；否。
- **无可检视文件跳过时的指标写「—」**：预算 / 资源确实是 0，写事实比空值可消费；变更规模也确实可度量。否。
- **超大 diff 也套四节模板**：超大 diff 的变更规模可能极难度量，且该路径连 diff 正文都不解析检视；用户明确只保留这一种跳过。否。

## Consequences

- **好**：平台侧只需一套解析；三种零与「有意见」的正文外形一致；无可检视文件路径也带上变更规模。
- **代价 / 风险（明确接受）**：总结正文**不再区分「没检视」「没上报」「确实没问题」**——无可检视文件与上报全失败都会被读成「未发现缺陷 + ⭐⭐⭐⭐」。这是用户 2026-11-18 的显式取舍；差异只能从 stdout `skipped`、stderr 与 `mcp.json` 追溯。ADR-0057 / 0097 原先的「绝不把没上报评成没问题」在**总结正文**层面不再成立。
- **测试面**：`review-summary.test.ts`（零上报与零 finding 同模板）、`delivery.test.ts`（`deliverSkip` 的无可检视文件四节模板与 0 指标）、`bin.process.test.ts`（预过滤全剔 / `--include` 未命中 / 零意见 / 置信度全滤 / tips 全跳过五条链路的正文断言）。全量测试与包级 `tsc -p tsconfig.build.json` 通过。
