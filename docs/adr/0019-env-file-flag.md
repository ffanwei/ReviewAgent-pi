# 0019. 凭据文件显式路径（`--env <file>`）

**状态**：已废止（由 [ADR-0025](0025-user-config-file.md) 取代：`--env` 旗标移除，`.env.local` 不再读取）——原状态：已接受（2026-10-30，用户经四项口径决策）
**关联**：ADR-0010（检视输出恒英文 + 核外投影——`REVIEW_PI_PRESENTATION_ENGINE` 仍按 cwd 解析，本 ADR 不改）、ADR-0011（切流后的生产入口）、ADR-0018（同为「路径类」旗标，取同款 fail-fast 姿态）、`packages/review-pi/src/shared/env-local.ts`（装载语义单源）
**跨仓**：本 ADR 为本仓 pi 线序列 0019；引用 DSH 兄弟仓决策须写全限定语「DSH 线 ADR-XXXX」。

## Context

凭据装载面只有一个入口：`resolve(".env.local")`——**进程 cwd** 的 `.env.local`，缺失即 no-op（可选注入面）。这在单仓单目录运行时很干净，但两个场景会迫使调用方 `cd`：

1. **分发/联调**：分发包放在 A 目录、凭据放在用户目录/B 目录，`--repo` / `--out` 都已是显式路径，唯独凭据文件还被钉在 cwd；
2. **多套凭据并存**（个人 / 团队网关 / CI），希望同一条命令显式挑一个文件，而不是「切目录」或「先 export」。

导出环境变量是另一条路，但脚本里 `KEY=...` 内联会把 key 写进命令历史与进程列表；`.env.local` 文件是既有的安全形态（gitignored、值不回显），缺的只是「文件在哪」这一维。

## Decision

1. **新增 `--env <file>`，只属于 `review` 子命令**。`smoke` / `disposition` 不吃这个旗标（`smoke` 传了 = 未知旗标用法错误；`disposition` 本就不碰凭据装载面）。理由：先解决检视主链路，不顺手扩面。
2. **替代而非合并**：指定后**只**读该文件，不再读 cwd 的 `.env.local`。两份文件「谁覆盖谁」是隐藏规则，不如「指定了就只认这一份」可预测。
3. **相对路径按进程 cwd 解析**，与既有 `.env.local` 的查找基准一致；支持绝对路径。
4. **显式指定但文件不存在 = 环境错误，exit 1**，stderr 一行人话并含路径。缺省路径缺失仍是 no-op。两者语义**故意不同**：显式路径是调用方的意图，拼错却静默 no-op 会让人以为已注入。
5. **读失败（EACCES / EISDIR 等）= exit 1**，与既有 `.env.local` 读失败同档（干净人话、不落堆栈）。
6. **优先级不变**：目标 env 里已有非空值的键不被文件覆盖（显式环境变量 > 文件；文件值为空视同未设置）。这是 `loadEnvLocalFile` 的既有语义，本 ADR 不引入新规则。
7. **空白路径 = 用法错误**（`--env ""` / `--env "  "`）：既不是「用缺省」也不是有效文件，在触碰文件系统前 fail fast。
8. **摘要行报显式路径**：`review-pi: env: <path> found — injected ...`；仍只报键名与坏行行号，**值绝不回显**（沿用 key 纪律）。

## Options（为什么不是别的）

- **`--env KEY=VALUE` 注入形态**：会把 key 写进命令历史/进程列表，正好是要避免的形态；且要回答「多 key、引号、空白」一堆解析问题。放弃。
- **`--env-file` / `--env-local` 命名**：语义更窄或更死（绑定默认文件名）；`--env` 更短且在本仓语境里「env 文件」已由摘要行统一指代。按用户决策取 `--env`。
- **合并 cwd + 指定文件**：出现「后者覆盖前者 / 前者优先」的隐藏规则，且两份文件同时存在时排障成本高。放弃。
- **相对 `--repo` 解析**：`smoke` 没有 `--repo`，基准会不一致；且凭据是「运行者」的属性，不是「被检仓库」的属性。放弃。
- **仅允许绝对路径**：最无歧义，但日常要多敲一长串；相对 cwd 的歧义可以用「摘要行报绝对路径」抵消。
- **缺失静默 no-op**：见决策 4 的反面理由。放弃。

## Consequences

- **正**：凭据文件与 `--repo` / `--out` 一样成为显式路径，调用方不必为凭据 `cd`；分发场景（ADR-0013 / 运行手册）可做到「一条命令 + 一个绝对路径」；多套凭据可并存。
- **负/风险**：
  - **两个装载面语义分叉**：缺省缺失 no-op、显式缺失 exit 1——需要在文档与错误文案里说清（已在手册失败表落一行）。
  - **`--env` 不改变其它相对路径的解析基准**：`REVIEW_PI_PRESENTATION_ENGINE` 仍按 cwd 解析（ADR-0010），别误以为「换 env 文件就换了引擎路径」。
  - **`smoke` 仍只认 cwd**：联调前自检时需要 `cd` 或 export；若后续有真实需求再单独扩面。
- **中性**：不新增环境变量；不改装载器（`loadEnvLocalFile` 只换入参）；审计/RunRecord/stdout 零改动。

## 验收标准

1. `--env <file>` 解析进 `ReviewCliArgs.envFile`；缺席省键；空白值 = 用法错误。
2. `smoke --env ...` = 未知旗标（旗标面不扩）。
3. 进程面：`--env` 指向 cwd 之外的文件时凭据生效（请求带该文件的 key），cwd 的 `.env.local` **不被读取**（诱饵值不进传输层）；stderr 摘要报显式路径且只报键名。
4. `--env` 指向不存在的文件 → exit 1 + 人话错误含路径；指向目录 → exit 1 + 读失败人话；两者 stdout 均为空。
5. 既有行为不变：未传 `--env` 时仍读 cwd 的 `.env.local`（缺失 no-op），显式环境变量仍优先级最高。
