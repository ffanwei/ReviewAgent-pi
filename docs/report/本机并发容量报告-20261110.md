## 4. 单并发资源模型

一次检视 = **2 个常驻 node 进程**（实测进程树，采样瞬时值）：

```text
run.mjs            handles=280  ws=47.9MB   ← 回放器，不计入每 worker
└ bin/review-pi.js handles=187  ws=40.3MB
  └ dist/cli/main.js handles=184 ws=62.3MB
```

`187 + 184 = 371`，与 ramp 的「1 worker = 371 / 2 workers = 742」逐项对上，说明采样树根是 bin、
**回放器那 48 MB / 280 句柄不在统计里**。

| 系数 | 值 | 说明 |
|---|---|---|
| 常驻进程 | 2 / worker | `bin` 是薄启动器（在位检查 + mtime 新鲜度门 + argv/退出码透传，`spawnSync`），业务全在 `dist/cli/main.js`；bin 全程阻塞空转 |
| 峰值 RSS | 123.6 MB / worker | 约 40 MB 是启动器，CLI 本体约 80 MB |
| 句柄 | 371 / worker | 启动器 187 + CLI 184（结构性常数，与延迟档位无关） |
| 本地 CPU | 0.03→0.09 核 / worker | 1 档 0.03 核；64 档 5.89/64 ≈ 0.09 核；单 run 的 harness 计算量约 0.25 core·s（`latency none` 实测 0.96s × 0.26 核） |

> 若真实部署改用 stdio MCP，每 run 还要再加 1 个 MCP server 子进程（v1 是纯 HTTP，ADR-0037 决策 4，
> 不 spawn）；模型调用 `rg` 检索时会有短命子进程，不影响常驻统计。

## 5. 上限判定：四条约束各在哪

| 约束 | 阈值 | 外推上限 | 是否先到 |
|---|---|---|---|
| p95（延迟劣化） | `2 × 11.42s = 22.85s` | **48 通过（1.97×）～ 64 出线（2.31×）之间**，未细分 | **是，64 档触发** |
| 句柄 | 20000 | `20000 / 371 ≈ 53` | 并列先到（64 档 23452） |
| 峰值 RSS | `0.8 × 15.6 GB = 12.5 GB` | `12.5 GB / 123.6 MB ≈ 101` | 否（64 档 7.3 GB） |
| CPU | 8 逻辑核 | 64 档仅 5.89 核（74%），未饱和 | 否 |

**结论：本机上限 = 48 workers（ADR-0048 口径）。** 提升它需要换杠杆，而不是加 worker：

1. **拆掉启动器进程**（bin 直接 import dist，或把新鲜度门移到进程内）：每 run 从 123.6 MB / 371 句柄
   降到约 **80–90 MB / 185 句柄**，内存约束从 ~101 抬到 ~140 并发。
2. **放宽句柄阈值**：20000 是配置护栏，不是系统上限；但要同步确认单进程句柄泄漏与 socket 回收。
3. 降低单 run 的 wall 尾（超时/重试策略、tips 一次性调用的串行等待），能推迟 p95 拐点。

## 6. 口径限制（读数字前必看）

1. **CPU 峰值列不可当上界**：8 档出现 `10.01 核` > 8 逻辑核，是 400ms 采样窗口内进程树累计时间差分的
   尖刺（进程 fork/exit 时基线跳变）。**峰值只看量级，均值才可信**；均值本身也是**下界**
   （worker 退出导致的负增量被丢弃）。
2. **采样器自身有开销**：64 档 192 个进程，`wmic` 全表枚举比 1 档重得多，这部分计入 wall。
3. **锁步突发**：每个 worker 跑同一 trace、同一次调用固定 sleep，同批 worker 几乎同时醒、同时抢核，
   这是**本地 CPU 的最坏情况**；真实到达过程分散，本地压力会低于此。
4. **单场景、单 trace**：只代表「小 diff 单 finding」的检视；`large-mr` 单 run 峰值 RSS 达 **203.7 MB**
   （会话 540 KB），按此推算内存约束降到 `12.5 GB / 203.7 MB ≈ 62` 并发。
5. **数字只在「本机 + fixed 1500ms（seed 42）」下成立**，换机器或换延迟档位不可直接比较。

## 7. 真实并发会有什么差异（要点）

| 维度 | 回放 | 真实 | 方向 |
|---|---|---|---|
| 延迟分布 | 固定 ±20%，同步波 | 长尾、去相关；小 diff 六阶段中位 91.0s（实测 VUL4J） | 本地更宽松；`2×基线` 规则会变成测上游排队 |
| 上游配额 | 不存在 | 每 run 7–22 次调用，48 并发≈每秒数次 | **最可能先撞**：429 + 重试放大 wall |
| 每 run 内存 | 123.6 MB | 长会话/大 diff 200–250 MB | **更紧**：62→50 并发 |
| 句柄 | 371 | 同一套进程树，结构不变 | 可迁移：~53 并发 |
| 本地 CPU | 0.03→5.89 核 | run wall 长 8–10 倍，CPU 更稀疏 | 更宽松 |

**因此**：真实上限大概率由「上游配额」或「每 run 内存」决定，低于本文的 48；本机 48 是
**最坏突发下的本地承载能力**，是上界参考而非真实可达值。
