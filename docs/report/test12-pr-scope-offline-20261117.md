# 排除非修改文件后的 test12 结果（离线重算，不重跑模型）

> 数据来源：2026-11-17 已完成的 test12 运行与 judge 结果，**没有重新调用模型、没有重新 judge**。  
> 做法：把每条生成意见按路径过滤，只保留落在该 PR 真实修改文件集（`merge-base(base, head)..head`）里的意见；
> GT 不变；用原有 judge 的 `hit_new_gt` / `matched_gt_indices` 重算 P/R/B。  
> 本次运行的原始口径见 [`test12-exp-tools-search-code-20261117.md`](test12-exp-tools-search-code-20261117.md)、
> [`test12-small10-data-20261117.md`](test12-small10-data-20261117.md)、
> [`test12-large2-data-20261117.md`](test12-large2-data-20261117.md)。

## 1. 方法与验证

- PR 真实文件集：`git diff --name-only $(git merge-base base_commit head_commit) head_commit`
  - 10 条小 diff：27 个文件
  - 2 条大 diff：20 个文件（ragflow 4 + FreeCAD 16）
- 过滤单位是**意见**，不是文件：只删除 `generated_comments[].path` 不在 PR 文件集里的意见。
- 重算公式：
  - Precision = 保留意见中 `hit_new_gt=true` 的条数 / 保留意见数
  - Recall = 保留意见的 `matched_gt_indices` 并集 / GT 总数
  - Balanced = 2PR/(P+R)
- **验证**：用同一方法在未过滤数据上重算，能精确复现官方指标——OCR 0.510/0.485/0.497、旧 baseline 0.116/0.318/0.170、`current` 0.080/0.227/0.118、本次 0.136/0.288/0.184。因此过滤后的变化只来自“去掉非 PR 文件意见”。
- OCR 的全部意见本来就在 PR 文件集内，过滤前后完全不变。

## 6. 结论

1. **错误 diff 范围是此前 precision 崩塌的主因**：本次 118 条意见中 78 条（66%）来自非 PR 文件，且全部是误报；去掉后 precision 13.6% → 40.0%，recall 不变。
2. **OCR 仍然领先**：修正后本次 B 0.335 vs OCR 0.497；小 diff 0.384 vs 0.471，大 diff 0.100 vs 0.533。
3. **小 diff 相对旧 baseline 的差距仍在**：修正后 B 0.384 vs 0.460，precision 0.385 vs 0.500。这个差距不能再归因于错误范围；但仍是单次运行、单轮 judge，需重复验证。
4. **大 diff 的覆盖问题不是过滤能解决的**：本次过滤后只剩 1 条命中（1/6），`FreeCAD` 仍是 0/13 且被跳过。正确范围下的真实重跑才有可能恢复覆盖。
5. **旧 baseline / `current` 的正确范围数字也一并给出**，避免拿“原始 12 条”继续做跨工具排名。

## 7. 口径限制

1. **这是离线重算，不是重跑**：过滤只删除已有意见，不改变模型在“正确 4/16 文件 diff”上的行为。真实重跑可能产生不同意见、更多覆盖；本报告应理解为“现有结果的精度上界 / 覆盖下界”。
2. `FreeCAD@699b45c` 的跳过与 13 条 GT 损失无法通过过滤恢复。
3. 单次运行、judge 单轮；小样本逐条 B 噪声大。
4. `current` 使用 `findingScope=true` + 分组 + 规则目录，与其它三行配置不同。
5. PR 文件集来自 `merge-base..head`；若平台 diff 语义不同，应以平台 `/files` 返回的文件集为准。
