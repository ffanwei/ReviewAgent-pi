## 6. 去重规则验证

### 6.1 旧规则误杀（v1 实际发生）

v1 的 6 条同根因拦截全部是"同文件 + 同 category + ±5 行"，但被拦候选与已产出意见并非同一根因：

| 样本 | 被拦候选 | 与已产出意见的关系 |
|---|---|---|
| `filament` | F003 79 行，`$originalOrders[0]` 键可能不存在（`ROBUSTNESS-001`） | 与 F001 79 行"丢失主键 tiebreaker"（`CORRECTNESS-001`）不同根因 |
| `gofr` | F003 152 行，`url.PathEscape` 路径二次转义（`CORRECTNESS-003`） | 与 F001 156 行凭据二次转义不同 |
| `cline` | F003 314 行，确认弹窗用 `uri.path` 展示来源（`AUTH-UX-003`） | 与 F001 318 行 Cancel 判断不同 |
| `ragflow` | F003 114 行，`list(set)` 结果不可重现（`DETERMINISM-001`） | 与 F001 114 行闭包捕获循环变量不同 |

对 `filament` F003 做反事实判分（完整 description 直接送 judge）：命中 GT#2 与 GT#3。也就是说旧规则在 v1 上直接造成 2 条 GT 损失。

### 6.2 新规则效果（v2）

- 用 v1 的原始候选集合复放新规则：`filament` / `gofr` / `cline` / `ragflow` 的 F003 **全部保留**，无拦截。
- v2 实际运行中同根因拦截数为 **0**（唯一拦截是 `ragflow` F002 的 `VERIFICATION_FAILED`）。也就是说，这一轮模型没有再产出相邻同根因候选，**新规则没有改变 v2 的输出**。
- v2 的 `filament` 确实从 0/4 回升到 2/4，说明"保留 F003"有效；但其他样本的模型输出/verifier 判定发生变化（`ragflow` F002 被 Phase 6 驳回、`linera` 少命中 1 条），把收益抵消了。

因此：**规则修复是正确的，但 v1→v2 的聚合差异不能归因于去重规则**，而是单轮模型与 judge 噪声。

## 7. 评测噪声

1. **judge 空响应**：v1/v2 首轮各有 2 条意见的 judge 返回空内容（`judge_reason=""`），被框架按未命中处理。重新跑 judge 后：
   - v1 覆盖 GT 14→16，B 0.396→0.443（第二次）→0.454（第三次）；
   - v2 覆盖 GT 14→16，B 0.384→0.428。
2. **judge 单条波动**：v1 的 `three.js` 1329 行意见在隔离重判时命中 GT#5；同一批输出的两次 judge（0.443 / 0.454）覆盖集合也不同（`ragflow` 3→2、`three.js` 4→5）。按隔离重判估算，v1 的 B 上限约 **0.473**。
3. **结论**：v1 与 OCR 的 B 差（0.454 vs 0.471）小于单轮 judge/模型噪声，不能据此判定"v1 一定不如 OCR"；同样，v2 低于 v1 2.6pp 也不足以证明收紧去重变差。

## 8. 结论

1. **收窄范围的方向成立**：v1/v2 的 precision 为 0.682/0.577，远高于 OCR 的 0.528 和旧 baseline 的 0.388；无 GT 文件意见清零；token 只有 OCR 的 37%～38%。
2. **代价是 recall**：0.340 vs OCR/baseline 的 0.426，主要来自 feature-completeness 类问题（IPv6 scope ID、数组长度校验等）和 `FreeCAD` 全灭。
3. **v1 当前综合最优**：B 0.454（judge 隔离重判上限约 0.473），与 OCR 基本持平，消耗仅为 OCR 的约 38%。
4. **收紧去重应保留**：它修掉了已证实的误杀，且用真实候选复放不会误伤；但它的收益需要多轮平均才能体现，本轮被模型输出差异掩盖。
5. **下一步建议**：
   - 大 diff 验证时同时跑 v1/v2 各 1 条，观察范围锚定与去重在大分片下的表现；
   - 若要给 v1/v2 排名，至少 3 轮评审 + 3 轮 judge 取均值，或固定评审输出后多轮 judge 平均。
