# 运行手册：单次检视（唯一形态 = 工具驱动 + 规则 Skill）

> 适用范围：`packages/review-pi`（pi 内核线 Review Runtime）的单案 CLI 路径。
> 定位：**一条命令跑一个 MR**——直接调 `review-pi` CLI，产出审计、运行记录、会话转录与检视意见导出。
> ADR-0024 之后本仓只有**一种检视形态**（工具驱动 + Context Ledger + 规则 Skill）：没有 `--config` 旗标，也没有 A–E 配置矩阵、实验编排、判定链与指标聚合。单次运行即全部产物。

## 1. 命令

在**仓库根目录**执行（cwd 决定 `.env.local` 解析位置与相对路径基准）。

单行形态（推荐，复制即用；PowerShell / cmd / bash 均可）：

```powershell
node packages\review-pi\bin\review-pi.js review --repo .cache\datasets\vul4j-repos\VUL4J-38-ab6cbdc3da --mr .cache\datasets\vul4j-diffs\VUL4J-38.diff --rule-skill-zip packages\review-pi\testdata\rule-skills\general-code-review.zip --strict-rule-skill --issue "Vulnerability CVE-2014-4172 (CWE-74) in apereo/java-cas-client. Fixed by https://github.com/apereo/java-cas-client/commit/ab6cbdc3daa451b4fef89c0bd0f4e6568f3aa9ef." --out runs\f-demo-session-skill-2
```

多行形态（PowerShell 反引号续行；反引号后**不能有空格**）：

```powershell
node packages\review-pi\bin\review-pi.js review `
  --repo .cache\datasets\vul4j-repos\VUL4J-38-ab6cbdc3da `
  --mr .cache\datasets\vul4j-diffs\VUL4J-38.diff `
  --rule-skill-zip packages\review-pi\testdata\rule-skills\general-code-review.zip `
  --strict-rule-skill `
  --issue "Vulnerability CVE-2014-4172 (CWE-74) in apereo/java-cas-client. Fixed by https://github.com/apereo/java-cas-client/commit/ab6cbdc3daa451b4fef89c0bd0f4e6568f3aa9ef." `
  --out runs\f-demo-session-skill-2
```

POSIX（Git Bash / WSL / Linux / macOS，路径分隔符换 `/`）：

```bash
node packages/review-pi/bin/review-pi.js review --repo .cache/datasets/vul4j-repos/VUL4J-38-ab6cbdc3da --mr .cache/datasets/vul4j-diffs/VUL4J-38.diff --rule-skill-zip packages/review-pi/testdata/rule-skills/general-code-review.zip --strict-rule-skill --issue "Vulnerability CVE-2014-4172 (CWE-74) in apereo/java-cas-client. Fixed by https://github.com/apereo/java-cas-client/commit/ab6cbdc3daa451b4fef89c0bd0f4e6568f3aa9ef." --out runs/f-demo-session-skill-2
```

不带任何规则包也能跑（照常检视，stderr 出一行提示、exit 0）；只在需要规则 Skill 检视会话时才传 `--rule-skill-zip` / `--rule-skill`。

### 旗标逐项说明

| 旗标 | 本例取值 | 语义 |
|---|---|---|
| `--repo` | `.cache/datasets/vul4j-repos/VUL4J-38-ab6cbdc3da` | 仓库快照根目录（必需；必须是目录）。约定仓停在 diff 的 **base 侧**——CLI 不 apply diff。 |
| `--mr` | `.cache/datasets/vul4j-diffs/VUL4J-38.diff` | MR diff 文件（必需）。**`caseId` = 文件名去扩展名** → `VUL4J-38`，落盘路径与审计都按它组织。 |
| `--rule-skill-zip` | `packages/review-pi/testdata/rule-skills/general-code-review.zip` | 规则 Skill **zip 包**。**可重复**，执行顺序 = CLI 顺序；缺省扫 `<repo>/.review-rules/*.zip` 全部装载。 |
| `--rule-skill` | （可选）`packages/review-pi/testdata/rule-skills/general-code-review` | 规则 Skill **已解压目录**（ADR-0018）。**可重复**；与 `--rule-skill-zip` 共存时**排在全部 zip 之后**；目录先审计再按内容哈希复制进 run 缓存（不原地当 pack 根）。 |
| `--rule-skill-name` | （可选）`general-code-review` | 包内多 skill 时指定装载哪一个（逐包生效）。 |
| `--strict-rule-skill` | （布尔，无值） | 装载失败即抛错退出；缺省为「降级 + 审计留痕，run 照常」。 |
| `--issue` | CVE 一句话 | MR 议题描述。会**原样**进入初始 user 消息；建议整体用双引号包住（含空格、括号、URL）。 |
| `--out` | `runs\f-demo-session-skill-2` | 落盘根。实际产物在其下的 `review-pi-cli/`（见 §5）。 |
| `--model` | （本例省略） | 缺省 `deepseek-v4-flash`（钉住的评审模型）。生产接入方舟接入点时传 `--model ep-xxxxxxxx`。 |
| `--env` | （本例省略） | 凭据文件显式路径（仅 `review`，ADR-0019）。相对进程 cwd；指定后不再读 cwd 的 `.env.local`；文件不存在 = exit 1。 |
| `--progress` | （本例省略） | 非 TTY 下把阶段/请求/收尾摘要逐行打到 stderr（ADR-0016）；`--no-progress` 显式关闭。 |

退出码：完成（含诚实截断）`0` / 中止或错误 `1`；截断信号在 stdout JSON 的 `truncated=true`，不体现在退出码。stdout 是**单个 JSON 文档**，`.env.local` 摘要与一切诊断走 stderr。任何 `--config` 之类的未知旗标按用法错误 exit 1（不做静默兼容）。

## 2. 前置条件

**全新 clone 的最短路径**（单案 VUL4J-38；逐项细节见下）：

```bash
pnpm install
tar -a -c -f packages/review-pi/testdata/rule-skills/general-code-review.zip -C packages/review-pi/testdata/rule-skills general-code-review
pnpm build:pi && pnpm --filter review-llm build && pnpm --filter review-pi build
# 再写入 .env.local（REVIEWER_API_KEY / REVIEWER_URL），准备好仓库快照与 diff，然后跑 §1 的命令
```

1. **Node ≥ 22**（`packages/review-pi/package.json` 的 `engines`）。
2. **依赖就位**：仓库根 `pnpm install`。
3. **内核构建产物就位且不过期**（bin 的「在位检查 + mtime 新鲜度门」会拒跑，且**不自动重编**）：

   ```bash
   pnpm build:pi                    # vendored pi 四包：telemetry → chord → ai → agent
   pnpm --filter review-llm build   # 共享 LLM 接入缝（源改后必须重建）
   pnpm --filter review-pi build    # 本包 CLI（dist/cli/main.js 是 bin 的 spawn 目标）
   ```

4. **凭据**：仓库根 `.env.local`（gitignored），只需键名：

   ```ini
   REVIEWER_API_KEY=...   # 必需；旧名 DEEPSEEK_API_KEY 作兼容别名（新名优先）
   REVIEWER_URL=...       # 可选；OpenAI 兼容 base URL，需自带 /v1，不带 /chat/completions
   ```

   已有非空环境变量优先于 `.env.local`；装载摘要只报键名与行号，key 值绝不回显。缺 key 在触碰文件系统前 fail fast。

   **让凭据文件不在 cwd**（ADR-0019）：`--env <file>` 指定替代路径（仅 `review`；相对路径按**进程 cwd** 解析）。指定后**只读该文件**，不再读 cwd 的 `.env.local`；显式指定但文件不存在 = 错误 exit 1（不静默降级）。`.env.local` 仍是缺省，不需要该旗标时可完全不管它。

   **输出预算**：设了 `REVIEWER_URL`（网关档）会显式发送 `max_tokens`（缺省 `32768`），覆盖网关的请求默认值——不发送即继承网关默认，实测 2048 会把思维链吃光并静默截断。官方直连（未设 `REVIEWER_URL`）**不发**该键。网关上限较小或被路由到小输出模型时，用 `REVIEWER_MAX_TOKENS=8192` 之类覆盖。

5. **仓库快照与 diff 就位**：本机约定路径是 `.cache/datasets/vul4j-repos/<VUL4J-ID>-<fixSha 前 10 位>/` 与 `.cache/datasets/vul4j-diffs/<VUL4J-ID>.diff`（全部 gitignored）。ADR-0024 已随评测仪器层删除数据物化脚本（原 `pnpm materialize:vul4j`）；**本仓不再自带造数能力**——快照缺失时自备（沿用既有 `.cache/` 快照、或从 DSH 兄弟仓取物化脚本生成）。CLI 只要求 `--repo` 是目录、`--mr` 是可读的 diff 文件。
6. **规则 Skill 包就位**（可选）：`packages/review-pi/testdata/rule-skills/general-code-review.zip`（内含 `SKILL.md`、`rules/*.md`、`scripts/*`）。**zip 不进版本库**（`**/*.zip` 已 gitignore），新 clone 需从源目录重建：

   ```bash
   tar -a -c -f packages/review-pi/testdata/rule-skills/general-code-review.zip -C packages/review-pi/testdata/rule-skills general-code-review
   ```

   （Linux/macOS 用 `zip -r general-code-review.zip general-code-review`，在 `packages/review-pi/testdata/rule-skills` 下执行。）包会在 run 输出根下解压缓存（`<out>/review-pi-cli/.cache/rule-skills/<sha256>/`），**绝不写回被检仓库**；重建后的 zip 内容等价但字节可能不同，`ruleSkill[].digest` 随之变化（不影响检视语义）。

### 可选：同时产出英文与中文检视意见

默认输出**只有英文**（`reviews_en.json` + 英文 stdout）：检视语言是测量常量面，语言不进参数面（ADR-0010），因此没有 `--zh` 之类的旗标。要让**同一次 run** 同时产出英文与中文，唯一开关是给 CLI 进程注入核外翻译引擎模块。

```text
review --out runs/f-demo-zh
        │
        ├── reviews_en.json            （内核写；恒产，英文源）
        └── reviews_tips_zh.json       （CLI 核外投影后写；配了引擎且 tips 合法才产）
```

> `reviews_zh.json` 已**停产**（ADR-0022）：中文交付物只有 `reviews_tips_zh.json` 一份。投影仍然发生（stdout 的 `findings` 是中文并带 `presentation` 留痕），只是不再落一份全文中文文件；旧 run 里留下的 `reviews_zh.json` 会被主动清除。

**1. 构建核外引擎**（源码 `src/presentation/`，产物**不在** `packages/review-pi/dist`）：

```bash
pnpm build:presentation
```

产物 `.tmp-gen/presentation/engine-zh.js`（ESM default export）+ `terminology.js` + `translate-projection.js`。改过 `src/presentation/**` 必须重跑；未构建时引擎加载失败 → 降级英文（见下方「四个坑」）。

**2. 在仓库根 `.env.local` 追加**：

```ini
REVIEW_PI_PRESENTATION_ENGINE=.tmp-gen/presentation/engine-zh.js
# 可选：翻译模型 id。不写 ⇒ 跟随本次 review 的 --model；都没有 ⇒ deepseek-v4-flash
REVIEW_PI_PRESENTATION_MODEL=deepseek-v4-flash
```

- 引擎路径按**进程 cwd** 解析；从仓库根跑就写相对路径，否则写绝对路径（`D:\Project\ReviewAgent-pi\.tmp-gen\presentation\engine-zh.js`）。
- 中文产物只有**一份**：`reviews_tips_zh.json`（ADR-0022）；投影结果只服务 stdout 与这份文件，不再落全文中文副本。
- 翻译模型三级链（ADR-0021）：`REVIEW_PI_PRESENTATION_MODEL` → 本次 `--model` → `deepseek-v4-flash`。**不写这一行**就与检视模型同档（网关只服务 `ep-xxx` 时这是唯一能跑通的形态）；要省成本可显式写一个轻模型。
- 翻译请求**复用** `REVIEWER_URL` / `REVIEWER_API_KEY`（`.env.local` 已装载），不需要额外 key。
- `.env.local` 的任意键都会装载；同名环境变量已存在时优先。

**3. 命令不变**：照 §1 原样跑，不加任何旗标。

**4. 产物**（同一次 run、同一个 `rep-1/`，外加 cwd 里两份便捷副本）：

```text
<out>/review-pi-cli/runs/vul4j/<caseId>/rep-1/
├── reviews_en.json                       # 英文真源（恒产）
└── reviews_tips_zh.json                  # 按文件分组的中文意见（严格 {"files":[...]}，ADR-0017 / ADR-0022）

<你执行命令的目录>/                        # 进程 cwd（ADR-0017 决策 14）
├── reviews_tips_zh.json                  # 与上面那份逐字节相同
└── review-result.json                    # 同一内容的下游约定名
```

stderr 先出一行「呈现投影进行中（自然语言字段译中文）……」；stdout 的 `findings` 为中文并追加 `presentation` 键（`language: "zh"` + 术语表版本 + `findingLinks`）。

cwd 那两份是**便利副本**：写失败（目录只读 / 目标名被占）只打一行 stderr 警告、**exit 仍 0**；本次不产 tips 时它们会被一并删除。若你就在某个 git 仓库根目录跑，记得把它们加进 `.gitignore`。

**分组意见长什么样**（ADR-0017，单条 10 键严格封闭）：

```json
{ "files": [ { "filePath": "cas-client-core/src/main/java/.../AbstractUrlBasedTicketValidator.java",
  "reviewTips": [ { "code": "catch (Exception e) { }", "review": "…。…", "suggestion": "…",
    "category": "ERROR-HANDLING", "subcategory": "", "severity": "Minor", "ruleId": "GEN-SQL-001",
    "lineNum": 167, "source": "rule-reviewer", "confidence": "Low" } ] } ] }
```

映射口径：`severity` 三档（P0→Fatal / P1→Major / P2、P3→Minor）；`confidence` 三档（≥0.8 High / ≥0.5 Medium / 其余 Low）；`source` 看 finding id 是否以 `RULE-CHECK@` 开头；`ruleId` 只在能对上规则包 frontmatter id 时才有值（无规则包恒空）；`subcategory` 恒空；`code` 取 `--repo` 里 `lineNum` 那一行原文；`suggestion` 是**新生成**的建议（每条一次网关调用）。**同文件同行只留首条**（ADR-0023）：一行命中多条 finding 时输出不会重复，被忽略的条目仍可在 `reviews_en.json` / stdout 看到。

**5. 校验**：

```powershell
$tips = 'runs\f-demo-zh\review-pi-cli\runs\vul4j\VUL4J-38\rep-1\reviews_tips_zh.json'
node -e "const d=JSON.parse(require('fs').readFileSync(process.argv[1],'utf8'));console.log(Object.keys(d), d.files.length, d.files.map(f=>f.reviewTips.length))" $tips
# cwd 便捷副本（ADR-0017 决策 14）：两份内容应完全相同
node -e "const fs=require('fs');console.log(fs.readFileSync('reviews_tips_zh.json','utf8')===fs.readFileSync('review-result.json','utf8'))"
```

结构化字段（`id` / `severity` / `category` / `file` / `line` / `evidence` / `rule` / `confidence`）在 en 与 stdout 呈现中**逐字节相同**，只有 `title` / `description` 被翻译；分组意见把这些字段折叠成 10 键（`evidence` 等不进 tips，要以结构化原文为准请看 `reviews_en.json` 或 stdout）。

**四个坑（都是有意设计）**：

- **中文不能事后补**：投影只在 run 收尾发生，没有「读旧 `reviews_en.json` 再译」的命令；要中文就重跑整个 run（成本同一次完整检视）。
- **引擎失败 = 静默降级，不是失败**：加载失败 / 协议不符 / 超时 → stdout 回退英文源 + `presentation.degraded: true` + stderr 一行原因，**退出码仍 0**，并**主动删除**同目录陈旧的 `reviews_tips_zh.json`（以及历史遗留的 `reviews_zh.json`）。看不到中文时先读 stderr，不要怀疑检视产物。
- **tips 是唯一中文产物**（ADR-0022）：形状非法（键集/枚举不符）⇒ 就没有中文文件，stdout 仍中文、exit 0，stderr 出一行「本次未产分组意见（原因）」。
- **耗时**：投影结果服务两个出口（stdout 与 tips 文件复用同一结果，不为写文件再调网关），但**逐字段串行**——长 description 单字段可 >30 s；另有**每条 finding 一次**的 `suggestion` 生成（并发 4、单次 90 s、失败留空串）；CLI 侧总超时按字段数与建议批次推导。

## 3. 一条命令发生了什么

```text
parse args (args.ts)
  → .env.local 装载 (shared/env-local) → 凭据 fail fast (reviewer-endpoint)
  → 读 repo / diff
  → runReview (run/review-run.ts)
       MR 初始上下文 → 六阶段循环（Phase 1–6，工具驱动 + Context Ledger）
       → Phase 5 之后：每个规则 Skill 一个独立会话（种子 = Phase-5 消息快照）
       → 候选门 → 合并 → 判定 → RunRecord + 审计 + 会话转录 + reviews_en.json
  → 呈现投影（可选，仅改 stdout / reviews_tips_zh.json）
  → stdout 单 JSON 文档（ok / caseId / runId / truncated / rounds / toolCalls / findings / auditPath）
```

要点：

- **六阶段是测量常量面**：system prompt、相位指令、七工具 schema 逐字节冻结；消息序列 append-only。
- **cli 固定 `rep: 1`、`experimentId: "review-pi-cli"`**——单次检视没有 rep 采样概念，多跑几次请换 `--out`。
- **规则 Skill 是唯一形态的一部分**：装载成功就用于候选阶段的规则检视；装不到（无显式包且 `<repo>/.review-rules/` 为空）⇒ 照常检视、审计 `ruleSkill: []` / `skillPassLog: []`，stderr 一行提示、exit 0。`--strict-rule-skill` 只在这种情况下把「装不到」升级为错误。

## 4. 规则 Skill 的语义与成本

- **独立会话**：Phase 5 之后为每个规则 Skill 追加一个独立检视会话（ADR-0014），种子是该 run 的 Phase-5 消息快照；skill 之间互不可见，候选在候选门前按 `(file, line, category)` 跨 skill 去重，存活候选并入本轮候选流，Phase 6 一次裁定。
- **多包叠加**：`--rule-skill-zip a.zip --rule-skill-zip b.zip`，执行顺序 = 传入顺序；每包独立会话。
- **zip 与目录混用（ADR-0018）**：`--rule-skill <dir>` 接受**已解压规则包目录**（例如 `packages/review-pi/testdata/rule-skills/general-code-review`），可重复；装载顺序**先全部 zip、再全部目录**（各自按 CLI 顺序）。目录会先审计（符号链接 / 非普通文件 / 总字节超限一律拒绝），再按内容哈希复制到 `<out>/review-pi-cli/.cache/rule-skills/dir-<sha256>/` 后装载——**不原地当 pack 根**，被检仓库零写入。审计 `ruleSkill[]` 里目录形态多一个 `kind: "dir"`（zip 形态省略，历史审计字节不变）。开发迭代规则包时用它省掉重打包；`<repo>/.review-rules/` 仍只认 `*.zip`，不会自动发现子目录。
- **`--strict-rule-skill`**：任一包定位/解压/装载失败即抛错（适 CI / 生产流水线）；缺省降级——失败只写审计 `ruleSkill[].degradedReason`，run 照常完成。
- **N=0**：未传 `--rule-skill-zip` / `--rule-skill` 且 `<repo>/.review-rules/` 为空 ⇒ 无 skill 会话（审计 `ruleSkill: []`、`skillPassLog: []`），主检视照常、exit 0、stderr 一行提示。此时带 `--strict-rule-skill` 会报错（找不到规则包）。显式给了 `--rule-skill` 时，`.review-rules/` 缺席**不再**算整体失败。
- **宿主平台提示（ADR-0020）**：skill 会话的 `bash` 工具描述与首条 user 消息都带一行 `Host platform: …`（含 `win32`/`darwin`/`linux` 与 arch），并说明「无 shell」这条既有边界（Windows 追加 `.cmd/.bat` shim 被拒、优先 `python`；POSIX 追加 `python3` 常在而 `python` 可能缺席）。目的是让模型按**当前 OS** 选命令——同一份规则包在 Windows 与 Linux 上跑，`python3` / `npx` 并不是通用写法。该提示**只进 skill 会话**，主会话工具面与请求字节不变；要核对看 skill 转录里首条 user 消息。
- **成本**：skill 会话**复用 Phase-5 消息快照作为种子**，即把主会话前五阶段历史再发一遍，且每个 skill 各发一遍。实测单案 skill 会话可占整 run 未缓存输入的一半以上，并可能产出 0 条增量候选。这是机制使然不是异常；需要控成本时把 skill 触发收敛到高风险变更（见《Token 优化方案》）。

## 5. 产物在哪

`<out>` 是落盘根，所有内容在其下的 `review-pi-cli/` 子目录（= CLI 的 experimentId）：

```text
<out>/review-pi-cli/
├── runs/vul4j/<caseId>/
│   ├── rep-1.json                                  # RunRecord（baseline / effective / verifier）
│   ├── session-<runId>.json                        # 主会话转录
│   ├── session-<runId>-skill-<name>-r<N>.json      # 每个 skill 会话一条
│   └── rep-1/
│       ├── reviews_en.json                         # 检视意见导出（英文源，恒产）
│       └── reviews_tips_zh.json                    # 分组中文意见（仅当配置了中文投影引擎）
├── audit/vul4j/<caseId>/rep-1/audit/
│   └── <runId>.json                                # 审计：usage / phaseLog / toolCallLog / ledger / ruleSkill / skillPassLog
└── .cache/rule-skills/<sha256>/                    # 规则包解压缓存（zip：归档 sha256，ADR-0014）
    └── dir-<sha256>/                               # 已解压目录的缓存副本（内容哈希，ADR-0018）
```

`runId = <时间戳>-<caseId>`（ADR-0024 去掉了配置段）；转录 / 审计 / `reviews_*.json` 的 `runId` 与之配对。

本例 `<out> = runs\f-demo-session-skill-2`，即：

```text
runs\f-demo-session-skill-2\review-pi-cli\runs\vul4j\VUL4J-38\rep-1.json
runs\f-demo-session-skill-2\review-pi-cli\audit\vul4j\VUL4J-38\rep-1\audit\<runId>.json
```

看结果的三处入口：stdout 的 JSON（findings 摘要 + `auditPath`）、`rep-1/reviews_en.json`（人工阅读）、`audit/.../<runId>.json`（成本与行为核对）。

## 6. 单次结果的读法

- **issue 用数据集原文**：本例 `--issue` 是缩短版（省略了 CWE 全称括号）。数据集原文见 `data/vul4j/*.json` 的 `issueDescription`，逐字复制才与历史基线同口径；改写 issue 属口径污染。
- **diff 用数据集原生文件**：`.cache/datasets/vul4j-diffs/<case>.diff`，不要手写或重新生成。
- **仓停在 base 侧**：CLI 不 apply diff。
- **单次结果 ≠ 基线**：被测模型非确定，单跑落在历史 rep 波动族内即属正常。本仓已无评测判定链（ADR-0024）：没有 judge / 指标聚合 / S-A-B 判定，跨内核对照请在 DSH 兄弟仓复跑。
- **超界 MR**：>10 文件或 >2K 变更行只**告警**不截断（`run/mr-boundary-guard.ts`），结论按 out-of-domain 看待。

## 7. 常见失败与处置

| 现象（stderr） | 原因 | 处置 |
|---|---|---|
| `review-pi: 拒跑——构建产物缺席/过期（腿: …）` | dist 未构建，或 `src` 比 `dist` 新 | 按提示逐腿重建：`pnpm build:pi` / `pnpm --filter review-llm build` / `pnpm --filter review-pi build`。bin **不会**自动重编。 |
| 缺 key 的人话错误 | `.env.local` 不在**当前 cwd**，或键名写错/为空 | 确认从仓库根执行、文件名为 `.env.local`；显式环境变量优先，注意别让空值覆盖。文件在别处时用 `--env <file>`（相对 cwd，仅 review）。 |
| `--env 指定的文件不存在（…）` | 显式路径拼错，或文件没随工作目录带过去 | 改成正确路径或删掉 `--env` 回落到 cwd 的 `.env.local`；该错误是 fail fast，不会「以为注入了」。 |
| `--repo is not a directory` / 读 diff 报 ENOENT | 数据集快照未就位，或路径笔误 | 准备 `.cache/datasets/vul4j-repos/…` 与 `…/vul4j-diffs/….diff`（本仓不再带物化脚本，ADR-0024）；确认目录名带 fixSha 前 10 位。 |
| `unknown flag: --config`（或其它未知旗标） | 配置矩阵已删除（ADR-0024）：检视只有唯一形态 | 去掉该旗标；规则 Skill 用 `--rule-skill-zip` / `--rule-skill`。 |
| 规则包相关抛错（仅 `--strict-rule-skill`） | zip 路径错 / 非 zip / 包内无 `SKILL.md` / 多 skill 需 `--rule-skill-name` / `--rule-skill` 目录不存在或含符号链接 | 去掉 `--strict-rule-skill` 先看审计里的 `ruleSkill[].degradedReason`；多 skill 包用 `--rule-skill-name` 消歧；目录形态用 `--rule-skill`（不是 `--rule-skill-zip`，后者传目录只会得到 EISDIR 降级）。详见 ADR-0018。 |
| `review-pi: 未装载任何规则包（…），照常检视` | 没有显式规则包且 `<repo>/.review-rules/*.zip` 为空 | 这是合法降级（exit 0）；要跑 skill 会话就补 `--rule-skill-zip` / `--rule-skill`。 |
| `--issue` 被截断或参数错位 | 引号未包住（含空格/括号/URL） | 整体双引号；PowerShell 里 `"` 内 `$` 会展开，注意避免 `$` 出现在 issue 文本。 |
| stdout 长时间静默后才出 JSON | 呈现投影逐字段调网关（长 description 可达 30s+/字段） | 正常现象，stderr 有「呈现投影进行中」心跳；不需要中文可去掉引擎变量。 |
| 配了引擎但没产 `reviews_tips_zh.json` | 投影降级（引擎未构建 / 路径按 cwd 解析失败 / 协议不符 / 呈现模型网关不可路由 / 超时），或 tips 形状非法，或本次本就零 finding 但引擎缺 `tips` | 先读 stderr 那行原因；`pnpm build:presentation` 后确认 `REVIEW_PI_PRESENTATION_ENGINE` 相对**进程 cwd** 正确。原因里带 4xx / model not found ⇒ 网关不认这个呈现模型：要么显式写 `REVIEW_PI_PRESENTATION_MODEL`，要么别配（缺省跟随 `--model`，ADR-0021）。详见 §2 末「可选：同时产出英文与中文检视意见」。 |
| 目录里有旧 `reviews_zh.json` | `reviews_zh.json` 已停产（ADR-0022），本次 run 会主动清除同一 `rep-1/` 下的遗留文件 | 看到 stderr「本次不产 reviews_zh.json（中文产物 = reviews_tips_zh.json），已清除陈旧 …」即正常；中文看 `reviews_tips_zh.json`。 |
| cwd 里没有 `review-result.json` | 执行目录副本写不进（cwd 只读 / 目标名被占成目录），或本次本就不产 tips | stderr 会有「执行目录副本写入失败（路径: 原因）」，但 **exit 仍是 0**；真源始终是 run 目录里的 `rep-1/reviews_tips_zh.json`。 |
| 退出码 0 但 `truncated=true` | 诚实截断（轮数/tool 预算） | 不是运行失败；看审计 `truncationReasons`。 |
| `truncationReasons` 含 `MODEL_MAX_TOKENS_REACHED` | 模型输出撞上 `max_tokens` 上界（思维链含在预算内时易发） | 网关档调大 `REVIEWER_MAX_TOKENS`（如 `65536`）；官方直连需显式设该变量才会下发预算。 |
