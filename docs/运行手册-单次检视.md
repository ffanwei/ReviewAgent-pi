# 运行手册：单次检视（唯一形态 = 工具驱动 + 规则 Skill）

> 适用范围：`packages/review-pi`（pi 内核线 Review Runtime）的单案 CLI 路径。
> 定位：**一条命令跑一个 MR**——直接调 `review-pi` CLI，产出审计、运行记录、会话转录与检视意见导出。
> ADR-0024 之后本仓只有**一种检视形态**（工具驱动 + Context Ledger + 规则 Skill），也没有 A–E 配置矩阵、实验编排、判定链与指标聚合。单次运行即全部产物。
> 运行配置（含秘密）在**用户级** `~/.PiAgent/PiAgent.jsonc`（JSONC；ADR-0025），可用 `--config <path>` 指定替代文件；环境变量与 `.env.local` 不再被读取。
> **装好的形态**（`npm i -g review-pi`，ADR-0028）与仓内形态命令完全等价，只把 `node packages/review-pi/bin/review-pi.js` 换成 `review-pi`；§2 的前置构建与 `pnpm install` 只适用于仓内开发。

## 1. 命令

在**仓库根目录**执行（仓内形态；安装形态 `npm i -g review-pi` 可在任意目录执行，只决定相对路径基准）。

单行形态（推荐，复制即用；PowerShell / cmd / bash 均可）：

```powershell
node packages\review-pi\bin\review-pi.js review --repo .cache\datasets\vul4j-repos\VUL4J-38-ab6cbdc3da --mr-diff .cache\datasets\vul4j-diffs\VUL4J-38.diff --rule-skill-zip packages\review-pi\testdata\rule-skills\general-code-review.zip --strict-rule-skill --issue "Vulnerability CVE-2014-4172 (CWE-74) in apereo/java-cas-client. Fixed by https://github.com/apereo/java-cas-client/commit/ab6cbdc3daa451b4fef89c0bd0f4e6568f3aa9ef." --out runs\f-demo-session-skill-2
```

多行形态（PowerShell 反引号续行；反引号后**不能有空格**）：

```powershell
node packages\review-pi\bin\review-pi.js review `
  --repo .cache\datasets\vul4j-repos\VUL4J-38-ab6cbdc3da `
  --mr-diff .cache\datasets\vul4j-diffs\VUL4J-38.diff `
  --rule-skill-zip packages\review-pi\testdata\rule-skills\general-code-review.zip `
  --strict-rule-skill `
  --issue "Vulnerability CVE-2014-4172 (CWE-74) in apereo/java-cas-client. Fixed by https://github.com/apereo/java-cas-client/commit/ab6cbdc3daa451b4fef89c0bd0f4e6568f3aa9ef." `
  --out runs\f-demo-session-skill-2
```

POSIX（Git Bash / WSL / Linux / macOS，路径分隔符换 `/`）：

```bash
node packages/review-pi/bin/review-pi.js review --repo .cache/datasets/vul4j-repos/VUL4J-38-ab6cbdc3da --mr-diff .cache/datasets/vul4j-diffs/VUL4J-38.diff --rule-skill-zip packages/review-pi/testdata/rule-skills/general-code-review.zip --strict-rule-skill --issue "Vulnerability CVE-2014-4172 (CWE-74) in apereo/java-cas-client. Fixed by https://github.com/apereo/java-cas-client/commit/ab6cbdc3daa451b4fef89c0bd0f4e6568f3aa9ef." --out runs/f-demo-session-skill-2
```

不带任何规则包也能跑（照常检视，stderr 出一行提示、exit 0）；只在需要规则 Skill 检视会话时才传 `--rule-skill-zip` / `--rule-skill`。

### 旗标逐项说明

| 旗标 | 本例取值 | 语义 |
|---|---|---|
| `--repo` | `.cache/datasets/vul4j-repos/VUL4J-38-ab6cbdc3da` | 仓库快照根目录（必需；必须是目录）。约定仓停在 diff 的 **base 侧**——CLI 不 apply diff。 |
| `--mr-diff` | `.cache/datasets/vul4j-diffs/VUL4J-38.diff` | 统一 diff 文件（与 `--mr-json` 二选一，恰好给一个）。**`caseId` = 文件名去扩展名** → `VUL4J-38`，落盘路径与审计都按它组织。 |
| `--mr-json` | （替代 `--mr-diff`）`MR-1234.json` | GitCode/GitLab `/files` 接口原样响应（JSON 数组）。**只读每项的 `new_path` 与 `diff`**，其余字段一律忽略；装载期补文件头转统一 diff（ADR-0029）。`caseId` 派生规则同上。 |
| `--rule-skill-zip` | `packages/review-pi/testdata/rule-skills/general-code-review.zip` | 规则 Skill **zip 包**。**可重复**，执行顺序 = CLI 顺序。只认显式输入：不传就没有规则包（不扫描被检视仓库，ADR-0027）。 |
| `--rule-skill` | （可选）`packages/review-pi/testdata/rule-skills/general-code-review` | 规则 Skill **已解压目录**（ADR-0018）。**可重复**；与 `--rule-skill-zip` 共存时**排在全部 zip 之后**；目录先审计再按内容哈希复制进 run 缓存（不原地当 pack 根）。 |
| `--rule-skill-name` | （可选）`general-code-review` | 包内多 skill 时指定装载哪一个（逐包生效）。 |
| `--strict-rule-skill` | （布尔，无值） | 装载失败即抛错退出；缺省为「降级 + 审计留痕，run 照常」。 |
| `--issue` | CVE 一句话 | MR 议题描述。会**原样**进入初始 user 消息；建议整体用双引号包住（含空格、括号、URL）。 |
| `--out` | `runs\f-demo-session-skill-2` | 落盘根。实际产物在其下的 `runs/mr/` 与 `audit/mr/`（见 §5；ADR-0027）。 |
| `--model` | （本例省略） | 缺省取配置 `model.default`（出厂值 `deepseek-v4-flash`）。生产接入方舟接入点时传 `--model ep-xxxxxxxx`。 |
| `--config` | （本例省略） | 配置文件路径（`review` / `smoke` / `config` 全子命令通用；相对路径按进程 cwd 解析）。省略 = `~/.PiAgent/PiAgent.jsonc`（Linux `$HOME` / Windows `%USERPROFILE%`）。 |
| `--progress` | （本例省略） | 非 TTY 下把阶段/请求/工具/skill 事件行打到 stderr（ADR-0016）；`--no-progress` 显式关闭。**收尾那一行运行总结（耗时 / token / 模型调用 / 工具 / Ledger 命中 / 成本）恒定打印**，不受这两个旗标影响（ADR-0030）。 |

退出码：完成（含诚实截断）`0` / 中止或错误 `1`；截断信号在 stdout JSON 的 `truncated=true`，不体现在退出码。stdout 是**单个 JSON 文档**，配置警告与一切诊断走 stderr。`--env` 已移除（ADR-0025）、`--mr` 已拆成 `--mr-diff` / `--mr-json`（ADR-0029），两者传入即确定性错误并给迁移提示；其它未知旗标按用法错误 exit 1（不做静默兼容）。

## 2. 前置条件

**两种形态**（命令等价，区别只在入口与是否需要构建）：

```bash
# A. 安装形态：不 clone 仓、不构建（ADR-0028）
npm i -g review-pi
review-pi review --repo <path> (--mr-diff <diff> | --mr-json <files.json>) --out <dir>

# B. 仓内形态：clone + pnpm install + 构建（下文逐项）
pnpm install
pnpm build:dist
node packages/review-pi/bin/review-pi.js review --repo <path> (--mr-diff <diff> | --mr-json <files.json>) --out <dir>
```

**全新 clone 的最短路径**（单案 VUL4J-38；逐项细节见下）：

```bash
pnpm install
tar -a -c -f packages/review-pi/testdata/rule-skills/general-code-review.zip -C packages/review-pi/testdata/rule-skills general-code-review
pnpm build:pi && pnpm --filter review-llm build && pnpm --filter review-pi build
# 再生成用户级配置 ~/.PiAgent/PiAgent.jsonc（review-pi config init，填 reviewer.apiKey），准备好仓库快照与 diff，然后跑 §1 的命令
```

1. **Node ≥ 22**（`packages/review-pi/package.json` 的 `engines`）。
2. **依赖就位**：仓库根 `pnpm install`。
3. **内核构建产物就位且不过期**（bin 的「在位检查 + mtime 新鲜度门」会拒跑，且**不自动重编**）：

   ```bash
   pnpm build:pi                    # vendored pi 四包：telemetry → chord → ai → agent
   pnpm --filter review-llm build   # 共享 LLM 接入缝（源改后必须重建）
   pnpm --filter review-pi build    # 本包 CLI（dist/cli/main.js 是 bin 的 spawn 目标）
   ```

4. **配置**：用户级 `~/.PiAgent/PiAgent.jsonc`（JSONC，允许注释与尾逗号）。最小可跑形态：

   ```jsonc
   {
     // 配置版本：当前只支持 1，不匹配即 fail fast。
     "version": 1,
     "reviewer": {
       // 模型网关密钥（必需）。审计与日志只报 set / missing，绝不回显值。
       "apiKey": "sk-...",
       // 网关基址：官方直连用 https://api.deepseek.com；OpenAI 兼容网关需自带 /v1。
       "baseUrl": "https://api.deepseek.com",
       // 单次请求输出上限：null = 自动（官方直连不发 max_tokens；网关发 32768）。
       "maxOutputTokens": null
     }
   }
   ```

   `config init` 生成的是完整模板：上表所有键 + 逐项中文注释 + 缺省值（含 `model` / `presentation` / `limits`），可直接照着改。

   生成与查看：

   ```bash
   review-pi config init      # 写缺省模板（已存在则拒绝，--force 覆盖；POSIX 0600）
   review-pi config show      # 脱敏打印生效值 + 来源 + digest
   ```

   完整键表与注释见仓库根 [`PiAgent.example.jsonc`](../PiAgent.example.jsonc)。**秘密只写在该文件里**：`config show`、审计与 stdout 一律只报 `set|missing`，绝不回显值或长度。环境变量（`REVIEWER_*` / `DEEPSEEK_*` / `REVIEW_PI_*`）与 `.env.local` **一律不再读取**——旧文件可用一次性迁移转过来：

   ```bash
   review-pi config init --from-env .env.local
   ```

   **换配置文件**（ADR-0025）：`--config <path>`（`review` / `smoke` / `config` 通用；相对路径按**进程 cwd** 解析）。省略即 `~/.PiAgent/PiAgent.jsonc`；路径不存在 = 全缺省（不报错，但 review/smoke 会打一行 stderr 提示「未找到配置文件」），缺 `reviewer.apiKey` 会在触碰文件系统前 fail fast。

   **输出预算**：配置了 `reviewer.baseUrl`（网关档）且 `maxOutputTokens` 为 `null` 时显式发送 `max_tokens`（缺省 `32768`），覆盖网关的请求默认值——不发送即继承网关默认，实测 2048 会把思维链吃光并静默截断。官方直连（未配 `baseUrl`，或归一化后等于 `https://api.deepseek.com`——scheme/host 大小写与尾斜杠不影响判档，ADR-0026）**不发**该键。网关上限较小或被路由到小输出模型时，把它写成 `8192` 之类。

5. **仓库快照与 diff 就位**：本机约定路径是 `.cache/datasets/vul4j-repos/<VUL4J-ID>-<fixSha 前 10 位>/` 与 `.cache/datasets/vul4j-diffs/<VUL4J-ID>.diff`（全部 gitignored）。ADR-0024 已随评测仪器层删除数据物化脚本（原 `pnpm materialize:vul4j`）；**本仓不再自带造数能力**——快照缺失时自备（沿用既有 `.cache/` 快照、或从 DSH 兄弟仓取物化脚本生成）。CLI 只要求 `--repo` 是目录、`--mr-diff`（或 `--mr-json`）是可读文件。
6. **规则 Skill 包就位**（可选）：`packages/review-pi/testdata/rule-skills/general-code-review.zip`（内含 `SKILL.md`、`rules/*.md`、`scripts/*`）。**zip 不进版本库**（`**/*.zip` 已 gitignore），新 clone 需从源目录重建：

   ```bash
   tar -a -c -f packages/review-pi/testdata/rule-skills/general-code-review.zip -C packages/review-pi/testdata/rule-skills general-code-review
   ```

   （Linux/macOS 用 `zip -r general-code-review.zip general-code-review`，在 `packages/review-pi/testdata/rule-skills` 下执行。）包会在 run 输出根下解压缓存（`<out>/.cache/rule-skills/<sha256>/`），**绝不写回被检仓库**；重建后的 zip 内容等价但字节可能不同，`ruleSkill[].digest` 随之变化（不影响检视语义）。

### 可选：同时产出英文与中文检视意见

默认输出**只有英文**（`reviews_en.json` + 英文 stdout）：检视语言是测量常量面，语言不进参数面（ADR-0010），因此没有 `--zh` 之类的旗标。要让**同一次 run** 同时产出英文与中文，唯一开关是在配置文件里指定核外翻译引擎模块（`presentation.engine`，ADR-0025 后不再读环境变量）。

```text
review --out runs/f-demo-zh
        │
        ├── reviews_en.json            （内核写；恒产，英文源）
        └── reviews_tips_zh.json       （CLI 核外投影后写；配了引擎且 tips 合法才产）
```

> `reviews_zh.json` 已**停产**（ADR-0022）：中文交付物只有 `reviews_tips_zh.json` 一份。投影仍然发生（stdout 的 `findings` 是中文并带 `presentation` 留痕），只是不再落一份全文中文文件；旧 run 里留下的 `reviews_zh.json` 会被主动清除。

**1. 构建核外引擎**（源码 `src/presentation/`，产物**不在** `packages/review-pi/dist`）：

```bash
pnpm build:presentation
```

产物 `.tmp-gen/presentation/engine-zh.js`（ESM default export）+ `terminology.js` + `translate-projection.js`，随后由同一个脚本复制到 `packages/review-pi/presentation/`（`"builtin"` 指向这里，ADR-0026）。改过 `src/presentation/**` 必须重跑；未构建时引擎加载失败 → 降级英文（见下方「四个坑」）。

**2. 在配置文件里开启投影**（`~/.PiAgent/PiAgent.jsonc` 或用 `--config` 指定的文件）：

```jsonc
{
  "presentation": {
    "engine": "builtin"                                // 制品自带引擎；或写路径
  },
  "model": {
    "presentation": "deepseek-v4-flash"               // 可选；null = 跟随本次检视模型
  }
}
```

- **引擎路径三形态（ADR-0026）**：`"builtin"` = 制品自带引擎（源码树里是 `packages/review-pi/presentation/engine-zh.js`；**`config init` 生成的默认值**）；`null` = 不投影（整段省略同此）；路径 = 相对路径按**配置文件所在目录**解析（不是进程 cwd），绝对路径原样。路径指向的模块不存在时，启动期一行 stderr 提示并按「未配置引擎」恒等直通（exit 0，不会白等投影超时）。
- 中文产物只有**一份**：`reviews_tips_zh.json`（ADR-0022）；投影结果只服务 stdout 与这份文件，不再落全文中文副本。
- 翻译模型三级链（ADR-0021）：`model.presentation` → 本次 `--model` → `model.default`。**写 `null`** 就与检视模型同档（网关只服务 `ep-xxx` 时这是唯一能跑通的形态）；要省成本可显式写一个轻模型。
- 翻译请求**复用** `reviewer.baseUrl` / `reviewer.apiKey`（同一份配置），不需要额外 key。

**3. 命令不变**：照 §1 原样跑，不加任何旗标。

**4. 产物**（同一次 run、同一个 `rep-1/`，外加 cwd 里一份便捷副本）：

```text
<out>/runs/mr/<caseId>/rep-1/
├── reviews_en.json                       # 英文真源（恒产）
└── reviews_tips_zh.json                  # 按文件分组的中文意见（严格 {"files":[...]}，ADR-0017 / ADR-0022）

<你执行命令的目录>/                        # 进程 cwd（ADR-0017 决策 14 / ADR-0027）
└── review-result.json                    # 与上面那份逐字节相同的下游约定名副本
```

stderr 先出一行「呈现投影进行中（自然语言字段译中文）……」；stdout 的 `findings` 为中文并追加 `presentation` 键（`language: "zh"` + 术语表版本 + `findingLinks`）。

cwd 那份是**便利副本**：写失败（目录只读 / 目标名被占）只打一行 stderr 警告、**exit 仍 0**；本次不产 tips 时它（以及旧版本写过的同名 `reviews_tips_zh.json`）会被一并删除。若你就在某个 git 仓库根目录跑，记得把 `review-result.json` 加进 `.gitignore`。

**分组意见长什么样**（ADR-0017，单条 10 键严格封闭）：

```json
{ "files": [ { "filePath": "cas-client-core/src/main/java/.../AbstractUrlBasedTicketValidator.java",
  "reviewTips": [ { "code": "catch (Exception e) { }", "review": "…。…", "suggestion": "…",
    "category": "ERROR-HANDLING", "subcategory": "", "severity": "Minor", "ruleId": "GEN-SQL-001",
    "lineNum": 167, "source": "rule-reviewer", "confidence": "Low" } ] } ] }
```

映射口径：`severity` 三档（P0→Fatal / P1→Major / P2、P3→Minor）；`confidence` 三档（≥0.8 High / ≥0.5 Medium / 其余 Low）；`source` 看 finding id 是否以 `RULE-CHECK@` 开头；`ruleId` 只在能对上规则包 frontmatter id 时才有值（无规则包恒空）；`subcategory` 恒空；`code` 取 `--repo` 里 `lineNum` 那一行原文；`suggestion` 是**新生成**的建议（每条一次网关调用）。**同文件同行只留首条**（ADR-0023）：一行命中多条 finding 时输出不会重复，被忽略的条目仍可在 `reviews_en.json` / stdout 看到。

**5. 校验**：

```powershell
$tips = 'runs\f-demo-zh\runs\mr\VUL4J-38\rep-1\reviews_tips_zh.json'
node -e "const d=JSON.parse(require('fs').readFileSync(process.argv[1],'utf8'));console.log(Object.keys(d), d.files.length, d.files.map(f=>f.reviewTips.length))" $tips
# cwd 便捷副本（ADR-0027）：与真源内容应完全相同
node -e "const fs=require('fs');console.log(fs.readFileSync('review-result.json','utf8')===fs.readFileSync(process.argv[1],'utf8'))" $tips
```

结构化字段（`id` / `severity` / `category` / `file` / `line` / `evidence` / `rule` / `confidence`）在 en 与 stdout 呈现中**逐字节相同**，只有 `title` / `description` 被翻译；分组意见把这些字段折叠成 10 键（`evidence` 等不进 tips，要以结构化原文为准请看 `reviews_en.json` 或 stdout）。

**四个坑（都是有意设计）**：

- **中文不能事后补**：投影只在 run 收尾发生，没有「读旧 `reviews_en.json` 再译」的命令；要中文就重跑整个 run（成本同一次完整检视）。
- **引擎失败 = 静默降级，不是失败**：加载失败 / 协议不符 / 超时 → stdout 回退英文源 + `presentation.degraded: true` + stderr 一行原因，**退出码仍 0**，并**主动删除**同目录陈旧的 `reviews_tips_zh.json`（以及历史遗留的 `reviews_zh.json`）。看不到中文时先读 stderr，不要怀疑检视产物。
- **tips 是唯一中文产物**（ADR-0022）：形状非法（键集/枚举不符）⇒ 就没有中文文件，stdout 仍中文、exit 0，stderr 出一行「本次未产分组意见（原因）」。
- **耗时**：投影结果服务两个出口（stdout 与 tips 文件复用同一结果，不为写文件再调网关），但**逐字段串行**——长 description 单字段可 >30 s；另有**每条 finding 一次**的 `suggestion` 生成（并发 `limits.concurrency.suggestion`，缺省 4；单次 `limits.timeouts.presentationRequestMs`，缺省 90 s；失败留空串）；CLI 侧总超时按字段数与建议批次推导（`presentationBufferMs`，缺省 30 s）。

## 3. 一条命令发生了什么

```text
parse args (args.ts)
  → 配置装载 (shared/config → 不可变快照；--config 或 ~/.PiAgent/PiAgent.jsonc) → 凭据 fail fast (reviewer-endpoint)
  → 读 repo / diff
  → runReview (run/review-run.ts)
       MR 初始上下文 → 六阶段循环（Phase 1–6，工具驱动 + Context Ledger）
       → Phase 5 之后：每个规则 Skill 一个独立会话（种子 = Phase-5 消息快照）
       → 候选门 → 合并 → 判定 → RunRecord + 审计（含 config 快照）+ 会话转录 + reviews_en.json
  → 呈现投影（可选，仅改 stdout / reviews_tips_zh.json）
  → stdout 单 JSON 文档（ok / caseId / runId / truncated / rounds / toolCalls / findings / auditPath）
```

要点：

- **六阶段是测量常量面**：system prompt、相位指令、七工具 schema 逐字节冻结；消息序列 append-only。运行期死钉 5 项（`maxRounds=5`、`maxToolCalls=100`、`toolResultBudgetChars=8000`、呈现 `temperature=0`、`reasoningEffort=high`），配置文件里写它们只会得到「已钉死」警告（ADR-0025）。
- **其余上限可配**：超时、并发、MR 边界、归档上限与若干文本截断（包头部字节、检索回显、调用链跳数、工具名/摘要截断）来自配置；换一份配置即可能改变请求体，审计 `config` 快照与 `digest` 用于反查。
- **读一次**：配置在启动时装载为不可变快照，运行中改文件不生效。
- **cli 固定 `rep: 1`**——单次检视没有 rep 采样概念，多跑几次请换 `--out`；产物路径没有实验标识层（`<out>/{runs,audit}/mr/<caseId>/rep-1/`，ADR-0027）。
- **规则 Skill 是唯一形态的一部分**：显式传入的规则包装到就用于候选阶段的规则检视；不传（或装不到）⇒ 照常检视、审计 `ruleSkill: []` / `skillPassLog: []`，stderr 一行提示、exit 0。**不扫描被检视仓库的 `.review-rules/`**（ADR-0027）；`--strict-rule-skill` 只在这种情况下把「装不到」升级为错误。
- **收尾恒有一行账**：检视结束、呈现投影开始之前，stderr 打一行 `✓ 完成 · 耗时 … · 模型调用 … · token 输入/输出/缓存命中 · 工具 …（主会话 + 规则 Skill） · Ledger 命中 …`（ADR-0030）。开不开 `--progress` 都有这一行；token / 工具数与审计同源，Ledger 命中只进这一行、不写审计。

## 4. 规则 Skill 的语义与成本

- **独立会话**：Phase 5 之后为每个规则 Skill 追加一个独立检视会话（ADR-0014），种子是该 run 的 Phase-5 消息快照；skill 之间互不可见，候选在候选门前按 `(file, line, category)` 跨 skill 去重，存活候选并入本轮候选流，Phase 6 一次裁定。
- **多包叠加**：`--rule-skill-zip a.zip --rule-skill-zip b.zip`，执行顺序 = 传入顺序；每包独立会话。
- **zip 与目录混用（ADR-0018）**：`--rule-skill <dir>` 接受**已解压规则包目录**（例如 `packages/review-pi/testdata/rule-skills/general-code-review`），可重复；装载顺序**先全部 zip、再全部目录**（各自按 CLI 顺序）。目录会先审计（符号链接 / 非普通文件 / 总字节超限一律拒绝），再按内容哈希复制到 `<out>/.cache/rule-skills/dir-<sha256>/` 后装载——**不原地当 pack 根**，被检仓库零写入。审计 `ruleSkill[]` 里目录形态多一个 `kind: "dir"`（zip 形态省略，历史审计字节不变）。开发迭代规则包时用它省掉重打包。
- **`--strict-rule-skill`**：任一包定位/解压/装载失败即抛错（适 CI / 生产流水线）；缺省降级——失败只写审计 `ruleSkill[].degradedReason`，run 照常完成。
- **N=0**：未传 `--rule-skill-zip` / `--rule-skill` ⇒ 无 skill 会话（审计 `ruleSkill: []`、`skillPassLog: []`），主检视照常、exit 0、stderr 一行提示。此时带 `--strict-rule-skill` 会报错（`no rule-skill archive given (pass --rule-skill-zip or --rule-skill <dir>)`）。**规则包只认显式输入**：被检视仓库里的 `.review-rules/` 不再自动装载（ADR-0027）。
- **宿主平台提示（ADR-0020）**：skill 会话的 `bash` 工具描述与首条 user 消息都带一行 `Host platform: …`（含 `win32`/`darwin`/`linux` 与 arch），并说明「无 shell」这条既有边界（Windows 追加 `.cmd/.bat` shim 被拒、优先 `python`；POSIX 追加 `python3` 常在而 `python` 可能缺席）。目的是让模型按**当前 OS** 选命令——同一份规则包在 Windows 与 Linux 上跑，`python3` / `npx` 并不是通用写法。该提示**只进 skill 会话**，主会话工具面与请求字节不变；要核对看 skill 转录里首条 user 消息。
- **成本**：skill 会话**复用 Phase-5 消息快照作为种子**，即把主会话前五阶段历史再发一遍，且每个 skill 各发一遍。实测单案 skill 会话可占整 run 未缓存输入的一半以上，并可能产出 0 条增量候选。这是机制使然不是异常；需要控成本时把 skill 触发收敛到高风险变更（见《Token 优化方案》）。

## 5. 产物在哪

`<out>` 是落盘根（**Runs Root**，ADR-0027：没有实验标识层）：

```text
<out>/
├── runs/mr/<caseId>/
│   ├── rep-1.json                                  # RunRecord（baseline / effective / verifier）
│   ├── session-<runId>.json                        # 主会话转录
│   ├── session-<runId>-skill-<name>-r<N>.json      # 每个 skill 会话一条
│   └── rep-1/
│       ├── reviews_en.json                         # 检视意见导出（英文源，恒产）
│       └── reviews_tips_zh.json                    # 分组中文意见（仅当配置了中文投影引擎）
├── audit/mr/<caseId>/rep-1/audit/
│   └── <runId>.json                                # 审计：usage / phaseLog / toolCallLog / ledger / ruleSkill / skillPassLog / config
└── .cache/rule-skills/<sha256>/                    # 规则包解压缓存（zip：归档 sha256，ADR-0014）
    └── dir-<sha256>/                               # 已解压目录的缓存副本（内容哈希，ADR-0018）
```

`runId = <时间戳>-<caseId>`（ADR-0024 去掉了配置段）；转录 / 审计 / `reviews_*.json` 的 `runId` 与之配对。

本例 `<out> = runs\f-demo-session-skill-2`，即：

```text
runs\f-demo-session-skill-2\runs\mr\VUL4J-38\rep-1.json
runs\f-demo-session-skill-2\audit\mr\VUL4J-38\rep-1\audit\<runId>.json
```

> 旧版本写到 `<out>/review-pi-cli/...` 的 run 仍留在盘上可人工查阅，但本版**不读也不写**那个布局（ADR-0027 明确不做兼容）。

看结果的三处入口：stdout 的 JSON（findings 摘要 + `auditPath`）、`rep-1/reviews_en.json`（人工阅读）、`audit/.../<runId>.json`（成本、行为与配置核对；顶层 `config` 记录全量生效值、来源与 `digest`，秘密只记 `set`）。

## 6. 单次结果的读法

- **issue 用数据集原文**：本例 `--issue` 是缩短版（省略了 CWE 全称括号）。数据集原文见 `data/vul4j/*.json` 的 `issueDescription`，逐字复制才与历史基线同口径；改写 issue 属口径污染。
- **diff 用数据集原生文件**：`.cache/datasets/vul4j-diffs/<case>.diff`，不要手写或重新生成。
- **仓停在 base 侧**：CLI 不 apply diff。
- **单次结果 ≠ 基线**：被测模型非确定，单跑落在历史 rep 波动族内即属正常。本仓已无评测判定链（ADR-0024）：没有 judge / 指标聚合 / S-A-B 判定，跨内核对照请在 DSH 兄弟仓复跑。
- **超界 MR**：超过 `limits.boundary.maxFiles` / `maxDiffLines`（缺省 10 文件 / 2000 变更行）只**告警**不截断（`run/mr-boundary-guard.ts`），结论按 out-of-domain 看待；任一维设 `null` 即该维不设界，双维 `null` 则护栏整体停用。

## 7. 常见失败与处置

| 现象（stderr） | 原因 | 处置 |
|---|---|---|
| `review-pi: 拒跑——构建产物缺席/过期（腿: …）` | dist 未构建，或 `src` 比 `dist` 新 | 按提示逐腿重建：`pnpm build:pi` / `pnpm --filter review-llm build` / `pnpm --filter review-pi build`。bin **不会**自动重编。 |
| 缺 key 的人话错误 | 配置文件里 `reviewer.apiKey` 缺失/为空（环境变量与 `.env.local` 已不再读取） | 跑 `review-pi config init` 生成 `~/.PiAgent/PiAgent.jsonc` 并填 key，或 `--config <path>` 指向已有文件；`review-pi config show` 可确认是否 `set`。 |
| `--env 已移除（配置见 --config <file> 或 ~/.PiAgent/PiAgent.jsonc）` | `--env` 在 ADR-0025 中退出 | 用 `--config <path>`；旧 `.env.local` 先用 `review-pi config init --from-env .env.local` 迁移。 |
| `parse error at line N, column M` | 配置文件 JSONC 语法错（多逗号之外的结构问题、未闭合引号等） | 按行列出错位置修正；JSONC 允许注释与尾逗号，但字符串内注释符会被当字面量。 |
| `配置键 … 期望 …（got …）` / `version` 不符 | 类型错、取值越界、`version ≠ 1` | fail fast，不做钳制：按提示改正或删掉该键（缺省值即有效）；`review-pi config show` 可看全量生效值。 |
| 未知键 / 「已钉死」警告 | 写了不认识的键，或写了 A 档死钉项（轮次、工具调用、工具结果预算等） | 警告后继续，行为不变；删掉即可，键表见 [`PiAgent.example.jsonc`](../PiAgent.example.jsonc)。 |
| `配置文件权限过宽` 警告（仅 POSIX） | 文件权限宽于 `0600` | `chmod 600 ~/.PiAgent/PiAgent.jsonc`；只是警告，不影响运行。 |
| `--repo is not a directory` / 读 diff 报 ENOENT | 数据集快照未就位，或路径笔误 | 准备 `.cache/datasets/vul4j-repos/…` 与 `…/vul4j-diffs/….diff`（本仓不再带物化脚本，ADR-0024）；确认目录名带 fixSha 前 10 位。 |
| `unknown flag: --xxx`（其它未知旗标） | 拼写错或传了已移除的旗标 | 对照 §1 旗标表；规则 Skill 用 `--rule-skill-zip` / `--rule-skill`。 |
| 规则包相关抛错（仅 `--strict-rule-skill`） | zip 路径错 / 非 zip / 包内无 `SKILL.md` / 多 skill 需 `--rule-skill-name` / `--rule-skill` 目录不存在或含符号链接 | 去掉 `--strict-rule-skill` 先看审计里的 `ruleSkill[].degradedReason`；多 skill 包用 `--rule-skill-name` 消歧；目录形态用 `--rule-skill`（不是 `--rule-skill-zip`，后者传目录只会得到 EISDIR 降级）。详见 ADR-0018。 |
| `review-pi: 未装载任何规则包（…），照常检视` | 没有显式给 `--rule-skill-zip` / `--rule-skill`（本版不再扫描 `<repo>/.review-rules/`，ADR-0027） | 这是合法降级（exit 0）；要跑 skill 会话就补 `--rule-skill-zip` / `--rule-skill`。 |
| `--issue` 被截断或参数错位 | 引号未包住（含空格/括号/URL） | 整体双引号；PowerShell 里 `"` 内 `$` 会展开，注意避免 `$` 出现在 issue 文本。 |
| stdout 长时间静默后才出 JSON | 呈现投影逐字段调网关（长 description 可达 30s+/字段） | 正常现象，stderr 有「呈现投影进行中」心跳；不需要中文就把 `presentation.engine` 设为 `null`。 |
| 配了引擎但没产 `reviews_tips_zh.json` | 投影降级（引擎未构建 / 协议不符 / 呈现模型网关不可路由 / 超时），或 tips 形状非法，或本次本就零 finding 但引擎缺 `tips` | 先读 stderr 那行原因；`pnpm build:presentation` 后确认 `presentation.engine` 指向存在的模块（相对路径按**配置文件所在目录**解析，或直接用 `"builtin"`，ADR-0026）。原因里带 4xx / model not found ⇒ 网关不认这个呈现模型：要么显式写 `model.presentation`，要么设 `null`（跟随 `--model`，ADR-0021）。详见 §2 末「可选：同时产出英文与中文检视意见」。 |
| `presentation.engine 指向的模块不存在（…），本次按未配置引擎恒等直通` | 引擎路径写错，或还没跑 `pnpm build:presentation` | 构建后重跑；用 `"builtin"` 可避免手写路径。这行**不是失败**：检视照常完成、exit 0，只是本次没有中文投影。 |
| 目录里有旧 `reviews_zh.json` | `reviews_zh.json` 已停产（ADR-0022），本次 run 会主动清除同一 `rep-1/` 下的遗留文件 | 看到 stderr「本次不产 reviews_zh.json（中文产物 = reviews_tips_zh.json），已清除陈旧 …」即正常；中文看 `reviews_tips_zh.json`。 |
| cwd 里没有 `review-result.json` | 执行目录副本写不进（cwd 只读 / 目标名被占成目录），或本次本就不产 tips | stderr 会有「执行目录副本写入失败（路径: 原因）」，但 **exit 仍是 0**；真源始终是 run 目录里的 `rep-1/reviews_tips_zh.json`。 |
| 退出码 0 但 `truncated=true` | 诚实截断（轮数/tool 预算） | 不是运行失败；看审计 `truncationReasons`。 |
| `truncationReasons` 含 `MODEL_MAX_TOKENS_REACHED` | 模型输出撞上 `max_tokens` 上界（思维链含在预算内时易发） | 调大 `reviewer.maxOutputTokens`（如 `65536`）；官方直连需显式设该值才会下发预算（`null` = 自动）。 |
| 打包报 `ERR_PNPM_BIN_CRLF` / `bin/review-pi.js has a shebang line encoding with CRLF` | 工作区行尾漂移：`.gitattributes`（`bin/** text eol=lf`）只管**新检出**，旧工作区里的 CRLF 不会被 `git pull` 重写。属性看似正确、打包却仍拒绝。 | 根治：删掉 `packages/review-pi/bin` 后 `git checkout -- packages/review-pi/bin`。兜底：`prepack`（`scripts/prepare-package.mjs`）会把首行带 CR 的 bin 文件整文件改成 LF 并打提示；`pnpm verify:pack` 也会拦住安装布局里的 CRLF 首行。详见 ADR-0028 决策 5。 |
