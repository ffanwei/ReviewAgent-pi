# 运行手册：单次检视（生产形态 = config F + 规则 Skill）

> 适用范围：`packages/review-pi`（pi 内核线 Review Runtime）的单案 CLI 路径。
> 定位：**日常/生产形态的一条命令跑一个 MR**——直接调 `review-pi` CLI，产出审计、运行记录、会话转录与检视意见导出。
> 区别于实验运行器：`pnpm experiment`（`src/experiment/runner.ts`）是**对照实验**入口，负责多 case × 多 config × 多 rep 的矩阵、judge 判定与指标聚合（`runs/<id>/`）；本手册只跑 **1 个 case × 1 个 config × rep-1**，不跑 judge、不产指标。

---

## 1. 命令（生产形态）

在**仓库根目录**执行（cwd 决定 `.env.local` 解析位置与相对路径基准）。

单行形态（推荐，复制即用；PowerShell / cmd / bash 均可）：

```powershell
node packages\review-pi\bin\review-pi.js review --repo .cache\datasets\vul4j-repos\VUL4J-38-ab6cbdc3da --mr .cache\datasets\vul4j-diffs\VUL4J-38.diff --config F --rule-skill-zip packages\review-pi\testdata\rule-skills\general-code-review.zip --strict-rule-skill --issue "Vulnerability CVE-2014-4172 (CWE-74) in apereo/java-cas-client. Fixed by https://github.com/apereo/java-cas-client/commit/ab6cbdc3daa451b4fef89c0bd0f4e6568f3aa9ef." --out runs\f-demo-session-skill-2
```

多行形态（PowerShell 反引号续行；反引号后**不能有空格**）：

```powershell
node packages\review-pi\bin\review-pi.js review `
  --repo .cache\datasets\vul4j-repos\VUL4J-38-ab6cbdc3da `
  --mr .cache\datasets\vul4j-diffs\VUL4J-38.diff `
  --config F `
  --rule-skill-zip packages\review-pi\testdata\rule-skills\general-code-review.zip `
  --strict-rule-skill `
  --issue "Vulnerability CVE-2014-4172 (CWE-74) in apereo/java-cas-client. Fixed by https://github.com/apereo/java-cas-client/commit/ab6cbdc3daa451b4fef89c0bd0f4e6568f3aa9ef." `
  --out runs\f-demo-session-skill-2
```

POSIX（Git Bash / WSL / Linux / macOS，路径分隔符换 `/`）：

```bash
node packages/review-pi/bin/review-pi.js review --repo .cache/datasets/vul4j-repos/VUL4J-38-ab6cbdc3da --mr .cache/datasets/vul4j-diffs/VUL4J-38.diff --config F --rule-skill-zip packages/review-pi/testdata/rule-skills/general-code-review.zip --strict-rule-skill --issue "Vulnerability CVE-2014-4172 (CWE-74) in apereo/java-cas-client. Fixed by https://github.com/apereo/java-cas-client/commit/ab6cbdc3daa451b4fef89c0bd0f4e6568f3aa9ef." --out runs/f-demo-session-skill-2
```

### 旗标逐项说明

| 旗标 | 本例取值 | 语义 |
|---|---|---|
| `--repo` | `.cache/datasets/vul4j-repos/VUL4J-38-ab6cbdc3da` | 仓库快照根目录（必需；必须是目录）。评测约定仓停在 diff 的 **base 侧**——CLI 不 apply diff。 |
| `--mr` | `.cache/datasets/vul4j-diffs/VUL4J-38.diff` | MR diff 文件（必需）。**`caseId` = 文件名去扩展名** → `VUL4J-38`，落盘路径与审计都按它组织。 |
| `--config` | `F` | `A–F`；缺省 `E`（生产切流档）。`F = E + 规则 Skill`（见 §4）。 |
| `--rule-skill-zip` | `packages/review-pi/testdata/rule-skills/general-code-review.zip` | 规则 Skill 包（config F）。**可重复**，执行顺序 = CLI 顺序；缺省扫 `<repo>/.review-rules/*.zip` 全部装载。 |
| `--strict-rule-skill` | （布尔，无值） | 装载失败即抛错退出；缺省为「降级 + 审计留痕，run 照常」。 |
| `--issue` | CVE 一句话 | MR 议题描述。会**原样**进入初始 user 消息；建议整体用双引号包住（含空格、括号、URL）。 |
| `--out` | `runs\f-demo-session-skill-2` | 落盘根。实际产物在其下的 `review-pi-cli/`（见 §5）。 |
| `--model` | （本例省略） | 缺省 `deepseek-v4-flash`（钉住的评审模型）。生产接入方舟接入点时传 `--model ep-xxxxxxxx`。 |

退出码：完成（含诚实截断）`0` / 中止或错误 `1`；截断信号在 stdout JSON 的 `truncated=true`，不体现在退出码。stdout 是**单个 JSON 文档**，`.env.local` 摘要与一切诊断走 stderr。

## 2. 前置条件

**全新 clone 的最短路径**（单案 VUL4J-38，五条命令一把过；逐项细节见下）：

```bash
pnpm install
pnpm materialize:vul4j -- --vul-ids VUL4J-38
tar -a -c -f packages/review-pi/testdata/rule-skills/general-code-review.zip -C packages/review-pi/testdata/rule-skills general-code-review
pnpm build:pi && pnpm --filter review-llm build && pnpm --filter review-pi build
# 再写入 .env.local（REVIEWER_API_KEY / REVIEWER_URL），然后跑 §1 的命令
```

1. **Node ≥ 22**（`packages/review-pi/package.json` 的 `engines`）。
2. **依赖就位**：仓库根 `pnpm install`。
3. **内核构建产物就位且不过期**（bin 的「在位检查 + mtime 新鲜度门」会拒跑，且**不自动重编**）：

   ```bash
   pnpm build:pi                    # vendored pi 四包：telemetry → chord → ai → agent
   pnpm --filter review-llm build   # 冻结仪器常量单源（源改后必须重建）
   pnpm --filter review-pi build    # 本包 CLI（dist/cli/main.js 是 bin 的 spawn 目标）
   ```

4. **凭据**：仓库根 `.env.local`（gitignored），只需键名：

   ```ini
   REVIEWER_API_KEY=...   # 必需；旧名 DEEPSEEK_API_KEY 作兼容别名（新名优先）
   REVIEWER_URL=...       # 可选；OpenAI 兼容 base URL，需自带 /v1，不带 /chat/completions
   ```

   已有非空环境变量优先于 `.env.local`；装载摘要只报键名与行号，key 值绝不回显。缺 key 在触碰文件系统前 fail fast。

    **输出预算**：设了 `REVIEWER_URL`（网关档）会显式发送 `max_tokens`（缺省 `32768`），覆盖网关的请求默认值——不发送即继承网关默认，实测 2048 会把思维链吃光并静默截断。官方直连（未设 `REVIEWER_URL`）**不发**该键，保持与 DSH 语料逐字节复刻。网关上限较小或被路由到小输出模型时，用 `REVIEWER_MAX_TOKENS=8192` 之类覆盖。

5. **数据集已物化**（首次或换案时）——`--vul-ids` 必填：

   ```bash
   # 单案（够跑一次检视）
   pnpm materialize:vul4j -- --vul-ids VUL4J-38

   # 复现 `data/vul4j/materialized-cases.json`（3 案，需显式 --out 才允许覆盖）
   pnpm materialize:vul4j -- --vul-ids VUL4J-38,VUL4J-52,VUL4J-79 --out data/vul4j/materialized-cases.json

   # 复现 30 案全量评测集
   pnpm materialize:vul4j -- --vul-ids <逗号分隔的 30 个 vulId> --out data/vul4j/target-cases.json
   ```

   产出 `.cache/datasets/vul4j-repos/<VUL4J-ID>-<fixSha 前 10 位>/`、`.cache/datasets/vul4j-diffs/<VUL4J-ID>.diff`、`.cache/datasets/vul4j-tarballs/*.tar.gz`（全部 gitignored）；清单落 `--out`（缺省 `data/vul4j/materialized-cases.json`）。本例两个路径都已存在时无需重跑。走 `api.github.com`（匿名限 60 次/时，30 案请注入 `GITHUB_TOKEN`）；缓存存在即复用，可离线重跑。
6. **规则 Skill 包就位**：`packages/review-pi/testdata/rule-skills/general-code-review.zip`（内含 `SKILL.md`、`rules/*.md`、`scripts/*`）。**zip 不进版本库**（`**/*.zip` 已 gitignore），新 clone 需从源目录重建：

   ```bash
   tar -a -c -f packages/review-pi/testdata/rule-skills/general-code-review.zip -C packages/review-pi/testdata/rule-skills general-code-review
   ```

   （Linux/macOS 用 `zip -r general-code-review.zip general-code-review`，在 `packages/review-pi/testdata/rule-skills` 下执行。）包会在 run 输出根下解压缓存（`<out>/review-pi-cli/.cache/rule-skills/<sha256>/`），**绝不写回被检仓库**；重建后的 zip 内容等价但字节可能不同，`ruleSkill[].digest` 随之变化（不影响检视语义）。

可选：呈现层中文投影引擎（`REVIEW_PI_PRESENTATION_ENGINE`）。配置了才产 `reviews_zh.json` 并把 stdout 呈现档译中文；未配置 = 恒等直通（纯英文），投影失败降级英文且不影响产物与退出码。

## 3. 一条命令发生了什么

```text
parse args (args.ts)
  → .env.local 装载 (shared/env-local) → 凭据 fail fast (reviewer-endpoint)
  → 读 repo / diff
  → runReview (run/review-run.ts)
       Zone B 装配 → 初始消息（MR user + 预取）→ 六阶段循环（Phase 1–6）
       → [config F] Phase 5 之后：每个规则 Skill 一个独立会话（种子 = Phase-5 消息快照）
       → 候选门 → 合并 → 判定 → RunRecord + 审计 + 会话转录 + reviews_en.json
  → 呈现投影（可选，仅改 stdout / reviews_zh.json）
  → stdout 单 JSON 文档（ok / caseId / configId / runId / truncated / rounds / toolCalls / findings / auditPath）
```

要点：

- **六阶段是测量常量面**：system prompt、相位指令、七工具 schema 在 A–F 间逐字节冻结；消息序列 append-only。
- **cli 固定 `rep: 1`、`experimentId: "review-pi-cli"`**——单次检视没有 rep 采样概念，多跑几次请换 `--out`。
- **非 F 配置忽略规则 Skill 旗标**：`--config E`（或 A–D）时即使传了 `--rule-skill-zip`，也不会装载、不会跑 skill 会话（`config.ruleSkill` 为 false）。`--strict-rule-skill` 同理只对 F 生效。

## 4. config F 的语义与成本

- `F = E + ruleSkill`：工具、stablePrefix、Ledger 与 E 相同；差异**只**在 Phase 5 之后追加**独立 skill 检视会话**（ADR-0014）。F 与 E 的 Phase 1–5 请求逐字节相同。
- **多包叠加**：`--rule-skill-zip a.zip --rule-skill-zip b.zip`，执行顺序 = 传入顺序；每包独立会话，skill 之间互不可见；候选在候选门前按 `(file, line, category)` 跨 skill 去重，存活候选并入本轮候选流，Phase 6 一次裁定。
- **`--strict-rule-skill`**：任一包定位/解压/装载失败即抛错（适 CI / 生产流水线）；缺省降级——失败只写审计 `ruleSkill[].degradedReason`，run 照常完成。
- **N=0**：未传 `--rule-skill-zip` 且 `<repo>/.review-rules/` 为空 ⇒ 无 skill 会话，F 与 E 全部请求逐字节相同（审计 `ruleSkill: []`、`skillPassLog: []`）。此时带 `--strict-rule-skill` 会报错（找不到规则包）。
- **成本**：skill 会话**复用 Phase-5 消息快照作为种子**，即把主会话前五阶段历史再发一遍，且每个 skill 各发一遍。实测单案（VUL4J-38/F）skill 会话可占整 run 未缓存输入的一半以上，并可能产出 0 条增量候选。F 的 token 成本显著高于 E 是机制使然，不是异常；需要控成本时优先考虑 E，或把 skill 触发收敛到高风险变更（见《Token 优化方案》）。

## 5. 产物在哪

`<out>` 是落盘根，所有内容在其下的 `review-pi-cli/` 子目录（= CLI 的 experimentId）：

```text
<out>/review-pi-cli/
├── runs/vul4j/<caseId>/<config>/
│   ├── rep-1.json                                  # RunRecord（baseline / effective / verifier）
│   ├── session-<ts>-<config>-<case>.json           # 主会话转录
│   ├── session-<ts>-<config>-<case>-skill-<name>-r<N>.json   # config F：每个 skill 会话一条
│   └── rep-1/
│       ├── reviews_en.json                         # 检视意见导出（英文源，恒产）
│       └── reviews_zh.json                         # 仅当配置了中文投影引擎
├── audit/vul4j/<caseId>/<config>/rep-1/audit/
│   └── <runId>.json                                # 审计：usage / phaseLog / toolCallLog / ledger / ruleSkill / skillPassLog
└── .cache/rule-skills/<sha256>/                    # 规则包解压缓存（不进仓库）
```

本例 `<out> = runs\f-demo-session-skill-2`，即：

```text
runs\f-demo-session-skill-2\review-pi-cli\runs\vul4j\VUL4J-38\F\rep-1.json
runs\f-demo-session-skill-2\review-pi-cli\audit\vul4j\VUL4J-38\F\rep-1\audit\<runId>.json
```

看结果的三处入口：stdout 的 JSON（findings 摘要 + `auditPath`）、`rep-1/reviews_en.json`（人工阅读）、`audit/.../<runId>.json`（成本与行为核对）。

## 6. 评测口径提醒（要复现论文数据时）

- **issue 用数据集原文**：本例 `--issue` 是缩短版（省略了 CWE 全称括号）。数据集原文见 `data/vul4j/*.json` 的 `issueDescription`，逐字复制才与 Phase 2 基线同口径；改写 issue 属口径污染。
- **diff 用数据集原生文件**：`.cache/datasets/vul4j-diffs/<case>.diff`，不要手写或重新生成。
- **仓停在 base 侧**：CLI 不 apply diff。
- **单次结果 ≠ 基线**：被测模型非确定，`rep-1` 单跑落在基线 rep 波动族内即属正常；要判定请走 `pnpm experiment` + judge + 指标链。
- **超界 MR**：>10 文件或 >2K 变更行只**告警**不截断（`run/mr-boundary-guard.ts`），结论按 out-of-domain 看待。

## 7. 常见失败与处置

| 现象（stderr） | 原因 | 处置 |
|---|---|---|
| `review-pi: 拒跑——构建产物缺席/过期（腿: …）` | dist 未构建，或 `src` 比 `dist` 新 | 按提示逐腿重建：`pnpm build:pi` / `pnpm --filter review-llm build` / `pnpm --filter review-pi build`。bin **不会**自动重编。 |
| 缺 key 的人话错误 | `.env.local` 不在**当前 cwd**，或键名写错/为空 | 确认从仓库根执行、文件名为 `.env.local`；显式环境变量优先，注意别让空值覆盖。 |
| `--repo is not a directory` / 读 diff 报 ENOENT | 数据集未物化，或路径笔误 | `pnpm materialize:vul4j`；确认目录名带 fixSha 前 10 位。 |
| 规则包相关抛错（仅 `--strict-rule-skill`） | zip 路径错 / 非 zip / 包内无 `SKILL.md` / 多 skill 需 `--rule-skill-name` | 去掉 `--strict-rule-skill` 先看审计里的 `ruleSkill[].degradedReason`；多 skill 包用 `--rule-skill-name` 消歧。 |
| `--issue` 被截断或参数错位 | 引号未包住（含空格/括号/URL） | 整体双引号；PowerShell 里 `"` 内 `$` 会展开，注意避免 `$` 出现在 issue 文本。 |
| stdout 长时间静默后才出 JSON | 呈现投影逐字段调网关（长 description 可达 30s+/字段） | 正常现象，stderr 有「呈现投影进行中」心跳；不需要中文可去掉引擎变量。 |
| 退出码 0 但 `truncated=true` | 诚实截断（轮数/tool 预算） | 不是运行失败；看审计 `truncationReasons`。 |
| `truncationReasons` 含 `MODEL_MAX_TOKENS_REACHED` | 模型输出撞上 `max_tokens` 上界（思维链含在预算内时易发） | 网关档调大 `REVIEWER_MAX_TOKENS`（如 `65536`）；官方直连需显式设该变量才会下发预算。 |
