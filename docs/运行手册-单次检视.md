# 运行手册：单次检视（唯一形态 = 工具驱动 + 规则 Skill）

> 适用范围：`packages/review-pi`（pi 内核线 Review Runtime）的单案 CLI 路径。
> 定位：**一条命令跑一个 MR**——直接调 `review-pi` CLI，产出审计、运行记录、会话转录与检视意见导出。
> ADR-0024 之后本仓只有**一种检视形态**（工具驱动 + Context Ledger + 规则 Skill），也没有 A–E 配置矩阵、实验编排、判定链与指标聚合。单次运行即全部产物。
> 运行配置（含秘密）在**用户级** `~/.PiAgent/PiAgent.jsonc`（JSONC；ADR-0025），可用 `--config <path>` 指定替代文件；环境变量与 `.env.local` 不再被读取。
> **装好的形态**（`npm i -g @baize/review-pi`，ADR-0035）与仓内形态命令完全等价，只把 `node packages/review-pi/bin/review-pi.js` 换成 `review-pi`；§2 的前置构建与 `pnpm install` 只适用于仓内开发。

## 1. 命令

在**仓库根目录**执行（仓内形态；安装形态 `npm i -g @baize/review-pi` 可在任意目录执行，只决定相对路径基准）。

单行形态（推荐，复制即用；PowerShell / cmd / bash 均可）：

```powershell
node packages\review-pi\bin\review-pi.js review --repo .cache\datasets\vul4j-repos\VUL4J-38-ab6cbdc3da --mr-diff .cache\datasets\vul4j-diffs\VUL4J-38.diff --rule-skill-zip packages\review-pi\testdata\rule-skills\general-code-review.zip --strict-rule-skill --issue "Vulnerability CVE-2014-4172 (CWE-74) in apereo/java-cas-client. Fixed by https://github.com/apereo/java-cas-client/commit/ab6cbdc3daa451b4fef89c0bd0f4e6568f3aa9ef." --taskId f-demo-session-skill-2
```

多行形态（PowerShell 反引号续行；反引号后**不能有空格**）：

```powershell
node packages\review-pi\bin\review-pi.js review `
  --repo .cache\datasets\vul4j-repos\VUL4J-38-ab6cbdc3da `
  --mr-diff .cache\datasets\vul4j-diffs\VUL4J-38.diff `
  --rule-skill-zip packages\review-pi\testdata\rule-skills\general-code-review.zip `
  --strict-rule-skill `
  --issue "Vulnerability CVE-2014-4172 (CWE-74) in apereo/java-cas-client. Fixed by https://github.com/apereo/java-cas-client/commit/ab6cbdc3daa451b4fef89c0bd0f4e6568f3aa9ef." `
  --taskId f-demo-session-skill-2
```

POSIX（Git Bash / WSL / Linux / macOS，路径分隔符换 `/`）：

```bash
node packages/review-pi/bin/review-pi.js review --repo .cache/datasets/vul4j-repos/VUL4J-38-ab6cbdc3da --mr-diff .cache/datasets/vul4j-diffs/VUL4J-38.diff --rule-skill-zip packages/review-pi/testdata/rule-skills/general-code-review.zip --strict-rule-skill --issue "Vulnerability CVE-2014-4172 (CWE-74) in apereo/java-cas-client. Fixed by https://github.com/apereo/java-cas-client/commit/ab6cbdc3daa451b4fef89c0bd0f4e6568f3aa9ef." --taskId f-demo-session-skill-2
```

不带任何规则包也能跑（照常检视，stderr 出一行提示、exit 0）；只在需要规则 Skill 检视会话时才传 `--rule-skill-zip` / `--rule-skill`。

### 命令面总览

`review-pi` 不带子命令时把完整用法打到 **stderr** 并 `exit 1`（没有 `--help` / `--version`，这是设计行为）。四个子命令：

| 子命令 | 用途 | 读配置 / 需要 key |
|---|---|---|
| `review` | 跑一次检视（唯一产出检视结论的路径） | 是 / 是 |
| `smoke` | 网关双探针自检（网关健康 + 模型可达） | 是 / 是 |
| `config` | `init` 写缺省模板、`show` 脱敏打印生效值与来源 | 是 / 否 |
| `export` | 打印 / 复制本次 run 的 session 转录路径（ADR-0036） | **否 / 否**（纯文件系统） |

完整用法（与 CLI 实际输出逐字一致；若两者不一致，以 `review-pi` 的输出为准）：

```text
usage: review-pi review --repo <path> (--mr-diff <diff-file> | --mr-json <files-json>) --taskId <id> [--issue <text>] [--tasks-dir <dir>] [--model <id>] [--config <path>] [--rule-skill-zip <path>[,<path>…]]... [--rule-skill <dir>[,<dir>…]]... [--skill <dir>[,<dir>…]]... [--strict-rule-skill] [--no-progress]
       review-pi smoke [--model <id>] [--config <path>]
       review-pi config <init|show> [--config <path>] [--force] [--from-env <file>] [--json]
       review-pi export [--taskId <id>] [--tasks-dir <dir>] [--path <dir>]
  （smoke = 网关冒烟自检，双探针：网关健康 + 模型可达，输出人话诊断）
  （config init = 写缺省 JSONC；config show = 脱敏打印生效配置与来源）
  （export = 打印主 / skill session 的绝对路径，主在前；--path 复制到目录）

配置（ADR-0025）：~/.PiAgent/PiAgent.jsonc（Linux $HOME / Windows %USERPROFILE%），JSONC。
环境变量不再被读取；--env 已移除（改用 --config）。

review 旗标：
  --repo    <path>       仓库快照根目录（必需）
  --mr-diff <file>       MR diff 文件路径（统一 diff 文本；caseId = 文件名去扩展名）
  --mr-json <file>       GitCode/GitLab 文件变更 JSON（数组，或 {diffs:[…]}）。路径取
                         new_path → filename → file_path → path、正文取 diff → patch（diff
                         为对象时取内层 diff.diff）；其余字段忽略，装载期补文件头转统一 diff。
                         与 --mr-diff 二选一
  --issue   <text>       MR 议题描述（缺省空）
  --taskId  <id>         任务 id（必需）。产物落到 <tasks 根>/<id>/ 下（runs/ + audit/）；
                         只允许单段目录名：不能含路径分隔符、盘符、<>:"|?* 或前导点，
                         Windows 保留设备名（CON / NUL / COM1…）与尾随点同样拒绝
  --tasks-dir <dir>      tasks 根目录覆盖（缺省 ~/.PiAgent/tasks；测试 / CI / 沙箱用），
                         相对路径按 cwd 解析
  --model   <id>         评审模型 id（缺省取配置文件 model.default；自由 id 透传）
  --config  <path>       配置文件显式路径（相对路径按 cwd 解析；缺省用户级路径）
  --rule-skill-zip  <path[,path…]>  规则 Skill zip 显式路径，一次可传多个（逗号分隔，或重复旗标；
                                    顺序 = 执行顺序）。不自动扫描仓库内目录——不传就不装载规则包，ADR-0027
  --rule-skill      <dir[,dir…]>    规则 Skill 已解压目录，一次可传多个；排在全部
                                    --rule-skill-zip 之后；目录先审计再按内容哈希复制进 run 缓存，
                                    符号链接/越界一律拒绝。一个包就是一个 skill（ADR-0034）
  --skill           <dir[,dir…]>    与 --rule-skill 同义（当前视为同一类 Skill）；一次可传多个，
                                    装载时排在全部 --rule-skill 之后
  --strict-rule-skill       规则 Skill 装载失败即报错（缺省降级、run 照常）
  --no-progress             关闭运行进度事件行（缺省打印：阶段 / 模型请求 / 工具调用 /
                            skill 会话；批跑收日志时显式静音）。
                            收尾的一行运行总结恒打印，不受此旗标影响

smoke 旗标：
  --model   <id>         冒烟模型 id（同缺省与校验；端点/key 取配置文件，绝不回显）
  --config  <path>       配置文件显式路径

config 旗标：
  init                   写缺省配置模板（已存在需 --force；POSIX 0600）
  show                   逐键打印生效值与来源（reviewer.apiKey 只显示 set/missing）
  --from-env <file>      init 时从 .env 文件一次性迁移（key / url / 呈现配置）
  --json                 show 输出机器可读 JSON（与审计 config 同形）

export 旗标：
  --taskId  <id>         指定任务 id（缺省读 cwd 的 .review-pi-session.json）
  --tasks-dir <dir>      任务根覆盖（cwd 有索引时以索引里的 tasksDir 为准；否则本旗标 → 缺省根）
  --path    <dir>        把本次 run 的 session 复制到该目录，返回复制后的绝对路径
```

### 1.1 `review` 旗标

| 旗标 | 本例取值 | 语义 |
|---|---|---|
| `--repo` | `.cache/datasets/vul4j-repos/VUL4J-38-ab6cbdc3da` | 仓库快照根目录（必需；必须是目录）。约定仓停在 diff 的 **base 侧**——CLI 不 apply diff。 |
| `--mr-diff` | `.cache/datasets/vul4j-diffs/VUL4J-38.diff` | 统一 diff 文件（与 `--mr-json` 二选一，恰好给一个）。**`caseId` = 文件名去扩展名** → `VUL4J-38`，只作数据字段（`run.json` / 审计 / 转录 `info.title`），不进产物路径。 |
| `--mr-json` | （替代 `--mr-diff`）`MR-1234.json` | GitCode/GitLab `/files` 接口原样响应（数组或 `{diffs:[…]}`）。路径按 `new_path` → `filename` → `file_path` → `path`、正文按 `diff` → `patch` 取第一个非空值（`diff` 为对象时取内层 `diff.diff`），其余字段一律忽略；装载期补文件头转统一 diff（ADR-0029）。`caseId` 派生规则同上。 |
| `--rule-skill-zip` | `packages/review-pi/testdata/rule-skills/general-code-review.zip` | 规则 Skill **zip 包**。**一次可传多个**：逗号列表（`a.zip,b.zip`）或重复旗标，执行顺序 = CLI 顺序 / 列表序。只认显式输入：不传就没有规则包（不扫描被检视仓库，ADR-0027）。**一个包就是一个 skill**（ADR-0034）。 |
| `--rule-skill` | （可选）`packages/review-pi/testdata/rule-skills/general-code-review` | 规则 Skill **已解压目录**（ADR-0018）。一次可传多个（`r1/,r2/` 或重复旗标）；与 `--rule-skill-zip` 共存时**排在全部 zip 之后**；目录先审计再按内容哈希复制进 run 缓存（不原地当 pack 根）。 |
| `--skill` | （可选，同上目录） | 当前与 `--rule-skill` **同义**（同一类 Skill、同一装载链路）；装载时排在全部 `--rule-skill` 之后。 |
| `--strict-rule-skill` | （布尔，无值） | 装载失败即抛错退出；缺省为「降级 + 审计留痕，run 照常」。 |
| `--issue` | CVE 一句话 | MR 议题描述。会**原样**进入初始 user 消息；建议整体用双引号包住（含空格、括号、URL）。 |
| `--taskId` | `f-demo-session-skill-2` | 任务 id（**必需**）。产物落 `<tasks 根>/<taskId>/`（缺省 `~/.PiAgent/tasks/`），其下是 `runs/` 与 `audit/`（见 §5；ADR-0032 / ADR-0033）。只允许单段目录名：不能含 `/` `\`、盘符、前导点、`<>:"|?*`、控制字符，Windows 保留名（`CON` / `NUL` / `COM1`…）与尾随点同样拒绝；允许中文与空格。 |
| `--tasks-dir` | （本例省略） | tasks 根覆盖（缺省 `~/.PiAgent/tasks`；相对路径按 cwd）。只换根，产物仍是 `<tasksDir>/<taskId>/`；测试 / CI / 沙箱用。 |
| `--model` | （本例省略） | 缺省取配置 `model.default`（出厂值 `deepseek-v4-flash`）。生产接入方舟接入点时传 `--model ep-xxxxxxxx`。 |
| `--config` | （本例省略） | 配置文件路径（相对路径按进程 cwd 解析）。省略 = `~/.PiAgent/PiAgent.jsonc`（Linux `$HOME` / Windows `%USERPROFILE%`）。`review` / `smoke` / `config` 通用；**`export` 不认**（见 §1.4）。 |
| `--no-progress` | （本例省略） | **进度事件行缺省打印**（不再按 stderr 是否 TTY 自动判定）；传 `--no-progress` 静音。`--progress` 已移除（ADR-0055），继续传会 `exit 1` 并给迁移提示。**收尾那一行运行总结（耗时 / token / 模型调用 / 工具 / Ledger 命中 / 成本）恒定打印**，不受此旗标影响（ADR-0030）。 |

### 1.2 `smoke` 旗标

| 旗标 | 语义 |
|---|---|
| `--model <id>` | 冒烟模型 id；缺省取配置 `model.default`。端点与 key 取自配置文件，**绝不回显**。 |
| `--config <path>` | 配置文件显式路径（相对路径按 cwd）。 |

`smoke` 只发两条极小的真实请求（`GET /models` + 一次 chat `ping`），`exit 0` = 双探针都通过，`exit 1` = 任一失败（stdout 给人话诊断，含失败探针与建议）。它**不写任何产物**，也不碰 tasks 目录。

### 1.3 `config` 旗标

| 旗标 / 子命令 | 语义 |
|---|---|
| `init` | 写缺省 JSONC 模板（全部键 + 中文注释）。已存在则拒绝，需 `--force` 覆盖（会丢已填 key）；POSIX 下文件 `0600`、目录 `0700`。 |
| `show` | 逐键打印**生效值 + 来源**（`file` / `default`）与 `digest`；`reviewer.apiKey` 只显示 `set` / `missing`，绝不回显值或长度。缺配置文件时打印 `not found` 仍 `exit 0`。 |
| `--config <path>` | 目标配置文件（相对路径按 cwd）。 |
| `--force` | 仅 `init`：覆盖已存在文件。 |
| `--from-env <file>` | 仅 `init`：从旧 `.env` 一次性迁移 key / url / 呈现配置。 |
| `--json` | 仅 `show`：输出机器可读 JSON（与审计 `config` 同形）。 |

### 1.4 `export` 旗标

| 旗标 | 语义 |
|---|---|
| （无） | 读 **cwd** 的 `.review-pi-session.json`，打印主 session + 各 skill session 的绝对路径（单遍：主在前、skill 按装载顺序；分片：`s01 主 → s01 skill → s02 主 → …`） |
| `--taskId <id>` | 不经索引：读 `<tasks 根>/<id>/runs/run.json`，由 `baseline.auditPath` 反推 runId，单遍按 `skillPassLog[].transcriptFile` 取 skill，分片按 `shards[].transcriptFile` 取各片主转录（与 `review` 同口径校验 taskId） |
| `--tasks-dir <dir>` | tasks 根覆盖（相对路径按 cwd）。**判定顺序：cwd 索引里的 `tasksDir` → 本旗标 → 缺省 `~/.PiAgent/tasks`**——同目录有索引时以索引里的绝对根为准，想让本旗标生效请在没有索引的目录执行 |
| `--path <dir>` | 把本次 run 的 session 复制到该目录（相对路径按 cwd；不存在则创建；**平铺、保留原文件名、同名覆盖**），输出改为**复制后**的绝对路径 |

`export` 是**纯文件系统命令**：不加载配置、不需要 `apiKey`、不调模型、不探测 `.env.local`，因此不认 `--config`（传了按未知旗标报错）。它只认**最新一次 run**，且不返回幽灵路径——任一文件不存在即 `exit 1`。

### 1.5 退出码与输出面

| 码 | 场景 |
|---|---|
| `0` | `review` 完成（**含诚实截断** `truncated: true`）；`smoke` 双探针通过；`config init` 写入成功；`config show` 正常（哪怕缺 key）；`export` 成功 |
| `1` | 用法错误（未知旗标 / 缺必需旗标 / 冲突旗标）；配置语法 / 类型 / 版本错；缺 `reviewer.apiKey`；`--config` 指向不存在的文件；`--repo` / diff 读失败；网络或模型错；产物写失败；`--strict-rule-skill` 装载失败；`smoke` 任一探针失败；`export` 缺索引 / 缺任务 / 缺文件 / 索引非法 / 复制失败 |

stdout 是**单个 JSON 文档**（`review`）或纯文本路径（`export`）；配置警告与一切诊断走 stderr。cwd 副本与 session 索引写失败**只警告，不改退出码**。

已移除旗标：`--env`（ADR-0025）、`--mr`（拆成 `--mr-diff` / `--mr-json`，ADR-0029）、`--out`（由 `--taskId` 取代，ADR-0033）、`--rule-skill-name`（一个包就是一个 skill，ADR-0034）——四者传入即确定性错误并给迁移提示；其它未知旗标按用法错误 `exit 1`（不做静默兼容）。

## 2. 前置条件

**两种形态**（命令等价，区别只在入口与是否需要构建）：

```bash
# A. 安装形态：不 clone 仓、不构建（ADR-0035）
npm i -g @baize/review-pi
review-pi review --repo <path> (--mr-diff <diff> | --mr-json <files.json>) --taskId <id>

# B. 仓内形态：clone + pnpm install + 构建（下文逐项）
pnpm install
pnpm build:dist
node packages/review-pi/bin/review-pi.js review --repo <path> (--mr-diff <diff> | --mr-json <files.json>) --taskId <id>
```

**全新 clone 的最短路径**（单案 VUL4J-38；逐项细节见下）：

```bash
pnpm install
tar -a -c -f packages/review-pi/testdata/rule-skills/general-code-review.zip -C packages/review-pi/testdata/rule-skills general-code-review
pnpm --filter @baize/review-pi build
# 再生成用户级配置 ~/.PiAgent/PiAgent.jsonc（review-pi config init，填 reviewer.apiKey），准备好仓库快照与 diff，然后跑 §1 的命令
```

1. **Node ≥ 22**（`packages/review-pi/package.json` 的 `engines`）。
2. **依赖就位**：仓库根 `pnpm install`。
3. **构建产物就位且不过期**（bin 的「在位检查 + mtime 新鲜度门」会拒跑，且**不自动重编**）：

   ```bash
   pnpm --filter @baize/review-pi build    # 本包 CLI（dist/cli/main.js 是 bin 的 spawn 目标）
   ```

   内核四包是 npm 依赖（`@earendil-works/*`，精确锁 `0.85.1`），由 `pnpm install` 落位，没有仓内构建步骤，也不参与 mtime 判鲜（ADR-0035）。

4. **配置**：用户级 `~/.PiAgent/PiAgent.jsonc`（JSONC，允许注释与尾逗号）。最小可跑形态：

   ```jsonc
   {
     // 配置版本：当前只支持 1，不匹配即 fail fast。
     "version": 1,
     "reviewer": {
       // 模型网关密钥（必需）。审计与日志只报 set / missing，绝不回显值。
       "apiKey": "sk-...",
       // 网关基址：官方直连用 https://api.deepseek.com；OpenAI 兼容网关需自带 /v1。
       "baseUrl": "https://api.deepseek.com",
       // 单次请求输出上限：null = 自动（官方直连不发 max_tokens；网关发 32768）。
       "maxOutputTokens": null
     }
   }
   ```

   `config init` 生成的是完整模板：上表所有键 + 逐项中文注释 + 缺省值（含 `model` / `presentation` / `limits`），可直接照着改。

   生成与查看：

   ```bash
   review-pi config init      # 写缺省模板（已存在则拒绝，--force 覆盖；POSIX 0600）
   review-pi config show      # 脱敏打印生效值 + 来源 + digest
   ```

   完整键表与注释见仓库根 [`PiAgent.example.jsonc`](../PiAgent.example.jsonc)。**秘密只写在该文件里**：`config show`、审计与 stdout 一律只报 `set|missing`，绝不回显值或长度。环境变量（`REVIEWER_*` / `DEEPSEEK_*` / `REVIEW_PI_*`）与 `.env.local` **一律不再读取**——旧文件可用一次性迁移转过来：

   ```bash
   review-pi config init --from-env .env.local
   ```

   **换配置文件**（ADR-0025）：`--config <path>`（`review` / `smoke` / `config` 通用；相对路径按**进程 cwd** 解析）。省略即 `~/.PiAgent/PiAgent.jsonc`；路径不存在 = 全缺省（不报错，但 review/smoke 会打一行 stderr 提示「未找到配置文件」），缺 `reviewer.apiKey` 会在触碰文件系统前 fail fast。

   **输出预算**：配置了 `reviewer.baseUrl`（网关档）且 `maxOutputTokens` 为 `null` 时显式发送 `max_tokens`（缺省 `32768`），覆盖网关的请求默认值——不发送即继承网关默认，实测 2048 会把思维链吃光并静默截断。官方直连（未配 `baseUrl`，或归一化后等于 `https://api.deepseek.com`——scheme/host 大小写与尾斜杠不影响判档，ADR-0026）**不发**该键。网关上限较小或被路由到小输出模型时，把它写成 `8192` 之类。

5. **仓库快照与 diff 就位**：本机约定路径是 `.cache/datasets/vul4j-repos/<VUL4J-ID>-<fixSha 前 10 位>/` 与 `.cache/datasets/vul4j-diffs/<VUL4J-ID>.diff`（全部 gitignored）。ADR-0024 已随评测仪器层删除数据物化脚本（原 `pnpm materialize:vul4j`）；**本仓不再自带造数能力**——快照缺失时自备（沿用既有 `.cache/` 快照、或从 DSH 兄弟仓取物化脚本生成）。CLI 只要求 `--repo` 是目录、`--mr-diff`（或 `--mr-json`）是可读文件。
6. **规则 Skill 包就位**（可选）：`packages/review-pi/testdata/rule-skills/general-code-review.zip`（内含 `SKILL.md`、`rules/*.md`、`scripts/*`）。**zip 不进版本库**（`**/*.zip` 已 gitignore），新 clone 需从源目录重建：

   ```bash
   tar -a -c -f packages/review-pi/testdata/rule-skills/general-code-review.zip -C packages/review-pi/testdata/rule-skills general-code-review
   ```

   （Linux/macOS 用 `zip -r general-code-review.zip general-code-review`，在 `packages/review-pi/testdata/rule-skills` 下执行。）包会在任务目录下解压缓存（`<tasks 根>/<taskId>/.cache/rule-skills/<sha256>/`），**绝不写回被检仓库**；重建后的 zip 内容等价但字节可能不同，`ruleSkill[].digest` 随之变化（不影响检视语义）。

### 中文按行建议（`reviews_tips_zh.json`）

默认输出**英文真源**（`reviews_en.json` + 英文 stdout）：检视语言是测量常量面，语言不进参数面（ADR-0010），因此没有 `--zh` 之类的旗标。控制台 **stdout 恒英文**、不做任何翻译（ADR-0065）；中文只作为交付物产出——`reviews_tips_zh.json`，与 MCP `mrReviewResult` 同源。

```text
review --taskId f-demo-zh
        │
        ├── reviews_en.json            （内核写；恒产，英文源）
        └── reviews_tips_zh.json       （片级语义生成；有意见且生成成功时产）
```

> `reviews_zh.json` 已**停产**（ADR-0022）。中文按行建议**不再依赖呈现引擎**（ADR-0065）：业务上报开启时由片级回调生成（与 `mrReviewResult` 同一份语义），业务上报关闭时收尾补一次同源生成（只登记语义、不发报文）。

**1. 不需要构建引擎，也不需要在配置里开启任何开关。** legacy 的 `presentation.engine` 仍可写，但不再驱动控制台翻译或 tips。

**2. 模型与请求**：报文 / 总结 / 语义生成共用 `model.presentation` → `--model` → `model.default` 三级链（ADR-0021），单次请求超时 `limits.timeouts.oneShotMs`（缺省 300 s），重试 `limits.retry.oneShotAttempts`（缺省 3）；复用 `reviewer.baseUrl` / `reviewer.apiKey`，不需要额外 key。

**3. 命令不变**：照 §1 原样跑，不加任何旗标。

**4. 产物**（同一次 run、同一个 `<tasks 根>/<taskId>/runs/`，外加 cwd 里一份便捷副本）：

```text
<tasks 根>/<taskId>/runs/
├── reviews_en.json                       # 英文真源（恒产）
└── reviews_tips_zh.json                  # 按文件分组的中文意见（顶层分组数组，ADR-0017 / ADR-0022）

<你执行命令的目录>/                        # 进程 cwd（ADR-0017 决策 14 / ADR-0027）
└── review-result.json                    # 与上面那份逐字节相同的下游约定名副本
```

stderr 在生成失败 / 逐条未覆盖时会给出人话原因；stdout 的 `findings` **恒为英文**，没有 `presentation` 键（ADR-0065）。

cwd 那份是**便利副本**：写失败（目录只读 / 目标名被占）只打一行 stderr 警告、**exit 仍 0**；本次不产 tips 时它（以及旧版本写过的同名 `reviews_tips_zh.json`）会被一并删除。若你就在某个 git 仓库根目录跑，记得把 `review-result.json` 加进 `.gitignore`。

**分组意见长什么样**（ADR-0017 / ADR-0045 / ADR-0065，单条 12 键严格封闭）：

```json
[ { "filePath": "cas-client-core/src/main/java/.../AbstractUrlBasedTicketValidator.java",
  "reviewTips": [ { "id": "F7", "code": "catch (Exception e) { }", "review": "…。…。影响评估：…", "suggestion": "[重构思路] … 代码示例：```…```",
    "category": "可靠性", "subcategory": "异常处理", "severity": "Suggestion", "level": "Suggestion",
    "ruleId": "GEN-SQL-001", "lineNum": 167, "source": "rule-reviewer", "confidence": "Medium" } ] } ]
```

顶层就是分组数组（没有 `{ "files": … }` 信封）；零 finding 时是 `[]`。

映射口径：`severity` 四档（P0→Fatal / P1→Major / P2→Minor / P3→Suggestion，与 `level` 同值）；`confidence` 三档（≥0.7 High / ≥0.5 Medium / 其余 Low）；`source` 看 finding id 是否以 `RULE-CHECK@` 开头；`ruleId` 只在能对上规则包 frontmatter id 时才有值（无规则包恒空）；`code` 取 `--repo` 里 `lineNum` 那一行原文；`category` / `subcategory` / `review` / `suggestion` 由片级语义生成一次产出（与 `mrReviewResult` 同一份，ADR-0065）。**同文件同行只留首条**（ADR-0023）：一行命中多条 finding 时输出不会重复，被忽略的条目仍可在 `reviews_en.json` / stdout 看到。

**置信度过滤（ADR-0052）**：配置 `limits.confidence.min`（0–1，缺省 `0.5`）会在生成前丢弃 `confidence < min` 的意见——**只影响中文 tips**（`reviews_tips_zh.json` 与 `mrReviewResult.reviewTips`），`reviews_en.json` / stdout 的英文 findings 恒全量。被丢弃条数与阈值写入审计 / `run.json` 的 `tipsFilter`，stderr 在确有丢弃时打一行汇总。想看全量中文意见就把 `min` 设为 `0`；`1` 表示只保留满置信。

**严重级过滤**：配置 `limits.severity.min`（`P0`–`P3`，缺省 `P3` = 不过滤）会在生成前丢弃严重级低于阈值的意见——同样**只影响中文 tips 与 MCP 上报**（`reviews_tips_zh.json` 与 `mrReviewResult.reviewTips`），`reviews_en.json` / stdout / 审计 findings 恒全量。例：`P2` 只保留 P0/P1/P2，丢弃 P3 建议级。被丢弃条数与阈值写入审计 / `run.json` 的 `severityFilter`。

**测试文件跳过检视**：配置 `limits.testFiles.skip`（缺省 `true`）在**检视输入阶段**按文件块整块剔除测试文件（`src/test/`、`test/`、`tests/`、`__tests__/`、`spec/` 目录，以及 `*Test.java`、`*.test.ts`、`test_*.py`、`*_test.go` 等文件名约定）。测试文件不会进入 diff，因此不产 findings、tips 与 MCP 上报；剔除清单写入审计 / `run.json` 的 `mrFilter`（`reason = "test"`），stderr 在确有剔除时打一行汇总。设为 `false` 时测试文件与生产代码同等检视；Phase 5 提示词会按该开关提示模型。

**按 glob 跳过检视（ADR-0069）**：配置 `limits.mrFilter.excludeGlobs`（缺省 `[]` = 不排除）在**检视输入阶段**按文件块整块剔除命中 glob 的文件，例如 `["**/*.md", "docs/**"]`。命中的文件不进 diff、不产 findings / 中文 tips / MCP 意见；它们仍是「变更过的文件」，收尾按 ADR-0068 补一条空 `reviewTips` 的 `mrReviewResult`，不会变成「未检视」。匹配仓库相对 POSIX 路径、大小写不敏感；不含 `/` 的 glob 只比文件名（`*.md` 与 `**/*.md` 等价），`*` / `?` 不跨目录、`**` 跨目录。剔除清单写入审计 / `run.json` 的 `mrFilter`（`reason = "exclude"`）。

**非 diff 区域过滤（ADR-0064）**：配置 `limits.findingScope`（缺省 `enabled: true`、`contextLines: 10`）在**候选拦截链**上只保留落在本遍 diff 变更 hunk 内（或距 hunk 边界不超过 `contextLines` 行）的意见；文件根本不在本遍 diff 的意见直接丢弃。它与上面两类的区别是**作用在 findings 真源**：被拒候选不产 findings、不进中文 tips、不进 MCP 上报，只留审计 `rejections` 与 `rejectionCounts.OUT_OF_SCOPE`。分片模式以片内 diff 为准；空 diff、删除文件、只有 mode 变更的文件 fail-open。想保留同文件远处或未改动文件里的意见，把 `enabled` 设为 `false`；想严格只保 hunk 内，把 `contextLines` 设为 `0`。

**5. 校验**：

```powershell
$tips = "$env:USERPROFILE\.PiAgent\tasks\f-demo-zh\runs\reviews_tips_zh.json"
node -e "const d=JSON.parse(require('fs').readFileSync(process.argv[1],'utf8'));console.log(Array.isArray(d), d.length, d.map(f=>f.reviewTips.length))" $tips
# cwd 便捷副本（ADR-0027）：与真源内容应完全相同
node -e "const fs=require('fs');console.log(fs.readFileSync('review-result.json','utf8')===fs.readFileSync(process.argv[1],'utf8'))" $tips
```

结构化字段（`id` / `severity` / `category` / `file` / `line` / `evidence` / `rule` / `confidence`）在 `reviews_en.json` 与 stdout 中**逐字节相同**；tips 把这些字段折叠成 12 键（`evidence` 等不进 tips，要以结构化原文为准请看 `reviews_en.json` 或 stdout）。

**四个坑（都是有意设计）**：

- **中文不能事后补**：语义生成只在 run 收尾发生，没有「读旧 `reviews_en.json` 再生成」的命令；要新的中文就重跑整个 run（成本同一次完整检视）。
- **生成失败 = 不产 tips，不是运行失败**：片级语义生成失败 / 逐条未覆盖 → 不产 `reviews_tips_zh.json` 并**主动删除**陈旧同名文件（以及历史遗留的 `reviews_zh.json`），stderr 出人话原因，**退出码仍 0**；`reviews_en.json` 与 stdout 完好。
- **零意见 / 全部被过滤**：产 `[]`（这是确定事实，不是生成失败）。
- **耗时**：业务上报开启时零额外调用（片级回调已经生成）；业务上报关闭时收尾多一次一次性调用（只在存在通过过滤的意见时）。不再有「每条 finding 2 次逐字段翻译」的开销。

## 3. 一条命令发生了什么

```text
parse args (args.ts)
  → 配置装载 (shared/config → 不可变快照；--config 或 ~/.PiAgent/PiAgent.jsonc) → 凭据 fail fast (reviewer-endpoint)
  → 解析 repo / diff 路径与 tasks 根 → stderr 回显生效参数（ADR-0043，开跑前）
  → MCP 上报建连（配置了 mcp 时）→ startTask（ADR-0045，读 diff 之前）
  → 读 repo / diff
  → runReview (run/review-run.ts)
       MR 初始上下文 → 六阶段循环（Phase 1–6，工具驱动 + Context Ledger）
       → Phase 5 之后：每个规则 Skill 一个独立会话（种子 = Phase-5 消息快照）
       → 候选门 → 合并 → 判定 → RunRecord + 审计（含 config 快照）+ 会话转录 + reviews_en.json
       → 每片 findings 定型：统一生成调用 → 逐文件 mrReviewResult（每文件必报，ADR-0061）+ 语义登记（ADR-0045）
  → 片级语义生成 / 统一 tips 组装（业务开启时已由回调生成；业务关闭时此处补一次，ADR-0065）
  → 统一 tips 落盘（reviews_tips_zh.json + review-result.json，与 mrReviewResult 同源复用）
  → 固定等待 5 s（最后一条 mrReviewResult → saveReviewSummary，ADR-0053）
  → 总结模型调用（零意见跳过，改发固定文案）→ saveReviewSummary（ADR-0045）
  → 固定等待 5 s（saveReviewSummary → endTask，ADR-0053）
  → endTask（finally，早于事件流 flush）→ stdout 单 JSON 文档（ok / caseId / runId / truncated / rounds / toolCalls / findings / auditPath）
```

要点：

- **六阶段是测量常量面**：system prompt、相位指令、七工具 schema 逐字节冻结；消息序列 append-only。运行期死钉 4 项（`maxToolCalls=100`、`toolResultBudgetChars=8000`、`temperature=0`、`reasoningEffort=high`），配置文件里写它们只会得到「已钉死」警告（ADR-0025）。**轮次上限可配**（`limits.loop.maxRounds`，缺省 3，ADR-0046）：最后一轮强制 complete，轮次耗尽不算截断。
- **其余上限可配**：超时、并发、MR 边界、归档上限与若干文本截断（包头部字节、检索回显、调用链跳数、工具名/摘要截断）来自配置；换一份配置即可能改变请求体，审计 `config` 快照与 `digest` 用于反查。
- **读一次**：配置在启动时装载为不可变快照，运行中改文件不生效。
- **cli 固定 `rep: 1`**——单次检视没有 rep 采样概念，`rep` 不再进入路径/文件名；多跑几次请换 `--taskId`（一个任务目录 = 一次 run；`<tasks 根>/<taskId>/{runs,audit}/`，ADR-0032 / ADR-0033）。
- **规则 Skill 是唯一形态的一部分**：显式传入的规则包装到就用于候选阶段的规则检视；不传（或装不到）⇒ 照常检视、审计 `ruleSkill: []` / `skillPassLog: []`，stderr 一行提示、exit 0。**不扫描被检视仓库的 `.review-rules/`**（ADR-0027）；`--strict-rule-skill` 只在这种情况下把「装不到」升级为错误。
- **大 MR 自动分片**：过滤后 diff 超过 `limits.split.maxShardChars`（缺省 40 万字符）时，按 `diff --git` 文件块**贪心装箱**拆成 N 片，每片串行跑完整六阶段 + 规则 Skill，最后把各片 findings 按 `(file, line, title)` 确定性合并去重并重编号（ADR-0039）。stdout / `run.json` / `reviews_en.json` 仍只有**一份合并结果**，形状不变；stderr 先打一行 `review-pi: 分片检视 N 片（单片上限 … 字符）`，其后每行带 `[sN/M]` 前缀。单片文件块超预算或片数超 `maxShards` ⇒ 预检报错、零模型请求；任一片失败 ⇒ `exit 1` 且不写聚合产物。产物布局见 §5。
- **收尾恒有一行账**：检视结束、中文 tips 生成 / 落盘之前，stderr 打一行 `✓ 完成 · 耗时 … · 模型调用 … · token 输入/输出/缓存命中 · 工具 …（主会话 + 规则 Skill） · Ledger 命中 …`（ADR-0030）。开不开进度事件行都有这一行（`--no-progress` 只静音事件行）；token / 工具数与审计同源，Ledger 命中只进这一行、不写审计。
- **整任务 LLM 总账（ADR-0066）**：进程收尾时在阶段账本之后另打两行 `[usage] 任务总计 | …` 与 `[usage] 一次性明细 | …`，统计**整个任务**的模型调用 / token / 成本——Agent 内（主会话 + 规则 Skill）+ Agent 之后的一次性调用（中文 tips 语义生成、收尾总结、候选修复）。成本按模型分桶计算（tips / 总结可能走 `model.presentation`）。这两行只进 stderr（因此自动进 `runs/review-pi.log`），不改审计 / `run.json` / stdout，也不改变上面那行 `✓ 完成` 的「检视本体」口径；响应未带 usage 的调用仍计次数并在行内标注。
- **参数回显**：**开跑前**（`runReview` 之前、进度投影之前）stderr 先打一块「本次 review 传入参数」——逐行列出 `--repo` / `--mr-diff|--mr-json` / `caseId` / `--issue` / `--taskId` / `--tasks-dir` / `--model` / `--config` / 规则包相关旗标 / `--no-progress` 的**生效值**；相对路径按 cwd 解析成绝对路径，缺省值标注来源，`--issue` 用 JSON 字符串转义。只回显参数、不含 apiKey 等秘密；stdout 仍是单 JSON 文档。提前打印意味着 diff 读取 / 解析失败或模型失败时也能看到本次输入面（ADR-0043）。
- **MCP 上报是旁路**（配置见使用手册 §3.10；ADR-0037 / ADR-0045）：不配置 = 零建连零请求，stdout / 审计 / 退出码逐字节不变。配置了才有两层：进度事件批量外发（`mcp.report.tool`，**可选**——缺席 = 事件通道关闭，最小配置只需 `servers` + `report.server`）+ 业务调用（`mcp.report.task`，缺省开）——`startTask`（读 diff 之前，预检失败也有始有终）→ 每片 `mrReviewResult`（该片意见定型即按文件上报，stderr 一行 `MCP mrReviewResult 已上报 N 文件 / M 条意见`；**该片 diff 触及的每个文件都会上报**，没有意见的传 `reviewTips: []`；有 finding 但片级报文生成失败 / tips 全被校验跳过时也补空列表（ADR-0061 覆盖率优先，失败原因留 stderr 与未覆盖登记；被预过滤剔除的文件（测试 / lockfile / 生成物 / minified / binary）在收尾统一补报一条空 tips——**变更即登记**，ADR-0068，stderr 一行 `MCP mrReviewResult 已补报 N 个变更文件 / 0 条意见`；只有整个 diff 解析不出任何文件路径时才只打一行 stderr、不发空调用）；报文的文件路径 / 源码行 / 行号 / 级别 / 规则 id 由代码确定性组装，模型只出 `category`/`subcategory`/`review`/`suggestion` 四个语义字段，枚举外条目跳过并留痕）→ `saveReviewSummary`（中文意见落盘后，Markdown 总结；**零意见发固定文案 `# 检视总结\n\n本次检视未发现缺陷。`、不调用模型**；有意见时模型失败降级模板）→ `endTask`（finally）。业务调用共 3 次尝试（仅传输 / 超时 / HTTP 5xx 类瞬时失败重试，退避 100 / 400 ms）、失败只落 stderr 一行、**绝不改变退出码**；`taskId` 同值直传 `--taskId`。**业务调用之间有两段固定 5 秒沉降**（ADR-0053，应对服务端异步处理导致前端回调乱序）：最后一条 `mrReviewResult` 之后、`saveReviewSummary` 之前等 5 s；`saveReviewSummary` 结束后、`endTask` 之前再等 5 s（stderr 各有 `MCP 固定等待 5000ms（…）` 一行）。启用业务上报的运行因此固定多约 10 s；业务关闭 / 建连失败 / 未走到总结的失败路径不等待。**握手可降级**（`mcp.servers.*.handshake`，缺省 `auto`）：服务端不认 `initialize` 就转无状态直调（每个 `tools/call` 独立 POST），stderr 一行说明；**统一 tips**：`reviews_tips_zh.json` 与 `mrReviewResult` 始终复用同一份片级语义生成（12 键 = 10 键 + `id` + `level`，与呈现引擎无关；ADR-0065）。业务开启时片级回调已经生成；业务关闭时收尾补一次同源生成（只登记语义、不发报文）。**不再回落呈现引擎**：生成全灭且无可覆盖 → 本次不产 tips 并清陈旧（Q24/Q26：部分失败尽力而为、全灭不产）。每一条未覆盖的 finding 都在 stderr 打一行带具体原因的留痕（`检视意见未获统一生成覆盖（file:line (id)），tips 缺席该条：<原因>`）——片级生成失败会把原因挂到该片全部意见上（`片级语义生成失败：…`），逐条被拒是 `model gave no entry for this finding` / `category … has no fallback mapping`；原因未知时回落 `未登记（原因未知）`。

## 4. 规则 Skill 的语义与成本

- **独立会话**：Phase 5 之后为每个规则 Skill 追加一个独立检视会话（ADR-0014），种子是该 run 的 Phase-5 消息快照；skill 之间互不可见，候选在候选门前按 `(file, line, category)` 跨 skill 去重，存活候选并入本轮候选流，Phase 6 一次裁定。
- **多包叠加**：`--rule-skill-zip a.zip,b.zip` 或 `--rule-skill-zip a.zip --rule-skill-zip b.zip`（等价），执行顺序 = 列表序 / 传入顺序；每包独立会话。包内多个 skill 不再消歧（ADR-0034）：该包按「不合规」降级，正确处置是拆包。**同名 skill 只保留后装载者**（装载序 zip → `--rule-skill` → `--skill`）：用 `--skill` 传入同名目录即可覆盖 `--rule-skill` / zip 的版本。
- **空值口径**：`--rule-skill-zip` / `--rule-skill` / `--skill` 的值位置没有 token，或只有空串 / 纯空白 / 纯逗号（`--skill ""`）⇒ 按「未传」处理，stderr 一行提示、exit 0（ADR-0044）。
- **zip 与目录混用（ADR-0018）**：`--rule-skill <dir>` 接受**已解压规则包目录**（例如 `packages/review-pi/testdata/rule-skills/general-code-review`），一次可传多个（逗号列表或重复旗标）；`--skill <dir>` 当前与它同义，装载顺序为**先全部 zip、再全部 `--rule-skill`、最后全部 `--skill`**（各自按 CLI 顺序 / 列表序）。目录会先审计（符号链接 / 非普通文件 / 总字节超限一律拒绝），再按内容哈希复制到 `<tasks 根>/<taskId>/.cache/rule-skills/dir-<sha256>/` 后装载——**不原地当 pack 根**，被检仓库零写入。审计 `ruleSkill[]` 里目录形态多一个 `kind: "dir"`（zip 形态省略，历史审计字节不变）。开发迭代规则包时用它省掉重打包。
- **`--strict-rule-skill`**：任一包定位/解压/装载失败即抛错（适 CI / 生产流水线）；缺省降级——失败只写审计 `ruleSkill[].degradedReason`，run 照常完成。
- **N=0**：未传 `--rule-skill-zip` / `--rule-skill` / `--skill`（旗标缺值被忽略也落在这里）⇒ 无 skill 会话（审计 `ruleSkill: []`、`skillPassLog: []`），主检视照常、exit 0、stderr 一行提示。此时带 `--strict-rule-skill` 会报错（`no rule-skill archive given (pass --rule-skill-zip or --rule-skill/--skill <dir>)`）。**规则包只认显式输入**：被检视仓库里的 `.review-rules/` 不再自动装载（ADR-0027）。
- **宿主平台提示（ADR-0020）**：skill 会话的 `bash` 工具描述与首条 user 消息都带一行 `Host platform: …`（含 `win32`/`darwin`/`linux` 与 arch），并说明「无 shell」这条既有边界（Windows 追加 `.cmd/.bat` shim 被拒、优先 `python`；POSIX 追加 `python3` 常在而 `python` 可能缺席）。目的是让模型按**当前 OS** 选命令——同一份规则包在 Windows 与 Linux 上跑，`python3` / `npx` 并不是通用写法。该提示**只进 skill 会话**，主会话工具面与请求字节不变；要核对看 skill 转录里首条 user 消息。
- **成本**：skill 会话**复用 Phase-5 消息快照作为种子**，即把主会话前五阶段历史再发一遍，且每个 skill 各发一遍。实测单案 skill 会话可占整 run 未缓存输入的一半以上，并可能产出 0 条增量候选。这是机制使然不是异常；需要控成本时把 skill 触发收敛到高风险变更（见《Token 优化方案》）。

## 5. 产物在哪

`<tasks 根>/<taskId>` 是落盘根（**Runs Root**；ADR-0033 定位置，ADR-0032 定内部形态：一个任务目录就是一次 run 的输出目录，无 case / rep / source 目录层）：

```text
<tasks 根>/<taskId>/
├── runs/
│   ├── run.json                                    # RunRecord（baseline / effective / verifier）
│   ├── session-<ts>.json                           # 主会话转录
│   ├── session-<ts>-skill-<name>-r<N>.json         # 每个 skill 会话一条
│   ├── mcp.json                                    # 四个 MCP 业务调用的输入 / 输出 / 时间（仅业务 tool 开启时产）
│   ├── reviews_en.json                             # 检视意见导出（英文源，恒产）
│   └── reviews_tips_zh.json                        # 分组中文意见（有意见且生成成功时产）
├── audit/
│   └── <ts>.json                                   # 审计：usage / phaseLog / toolCallLog / ledger / ruleSkill / skillPassLog / config
└── .cache/rule-skills/<sha256>/                    # 规则包解压缓存（zip：归档 sha256，ADR-0014）
    └── dir-<sha256>/                               # 已解压目录的缓存副本（内容哈希，ADR-0018）
```

`<ts>` = 首次模型请求时刻（UTC 毫秒，`20261031_101010_123`）；它同时是 stdout 的 `runId`、审计文件名与转录文件名中段，三者可互推。`caseId` 只作为数据字段（`run.json` / 审计 / 转录 `info.title`）保留。

`runs/mcp.json`（ADR-0054）只在 MCP 业务 tool 开启且确有调用时产生：按调用顺序记录 `startTask` / `mrReviewResult`（每文件一条）/ `saveReviewSummary` / `endTask` 的 `input`（MCP `tools/call.arguments` 原样）、`output`（`ok` / 失败 `reason` / 服务端回包 `response`）与 `startedAt` + `durationMs`（含重试总耗时）。它是排障旁路：写失败只落一行 stderr、不改退出码；与 `session-<ts>.json` 同目录，但**不进审计字节**。

**分片检视时**（ADR-0039），顶层只留聚合产物，每片的会话 / 审计 / 片内 `reviews_en.json` 落到独立子目录：

```text
<tasks 根>/<taskId>/
├── runs/
│   ├── run.json                          # 聚合 RunRecord；多出 shards[]（每片 runId / 转录 / 审计 / 用量）
│   ├── mcp.json                          # 四个 MCP 业务调用留痕（顶层一份；片级调用也在其中）
│   ├── reviews_en.json                   # 合并去重后的 findings（只有这一份）
│   └── shards/attempt-<entryTs>/sNN/     # NN = 01、02…（diff 顺序）
│       ├── session-<shardTs>.json        # 本片主会话转录
│       ├── session-<shardTs>-skill-…-rN.json
│       └── reviews_en.json               # 本片原始 findings（供核对合并账）
├── audit/
│   ├── <aggregateTs>.json                # 聚合审计：requests / toolCallLog 为空，shards[] 记每片
│   └── shards/attempt-<entryTs>/sNN/<shardTs>.json
```

- `attempt-<entryTs>` 用 **run 入口的 `startedAt`** 生成，只作目录名，**不是 runId**；每次尝试独占一组目录，重跑不覆盖历史转录。
- 聚合 `runId` = **第 1 片的 `runId`**（stdout 同名）；聚合审计文件名跟它一致。
- 请求 / 工具 / 相位明细在各片审计里；聚合审计只记全局 `mrFilter` / `mrBoundary` / `config` 与 `shards[]` 索引。
- 任一片失败 ⇒ 已成功片的产物保留、聚合 `run.json` / `reviews_en.json` / 顶层审计**一律不写**（不输出部分结果）。

**进程 cwd**（你执行命令的目录）：

```text
<执行目录>/
├── review-result.json          # 分组中文意见的便利副本（产 tips 时写；ADR-0017 / ADR-0027）
└── .review-pi-session.json     # 本次成功 run 的 session 索引（绝对路径；ADR-0036，别提交）
```

索引与 `export` 的用法见下节。

本例 `<taskId> = f-demo-session-skill-2`，缺省根即 `~/.PiAgent/tasks`（本例在 Windows 上即 `%USERPROFILE%\.PiAgent\tasks`），落点是：

```text
<tasks 根>\f-demo-session-skill-2\runs\run.json
<tasks 根>\f-demo-session-skill-2\audit\<ts>.json
```

> 旧版本写到 `<out>/review-pi-cli/...`、`<out>/runs/mr/...` 的 run 仍留在盘上可人工查阅，但本版**不读也不写**那些布局（ADR-0027 / ADR-0032 明确不做兼容）。

看结果的三处入口：stdout 的 JSON（findings 摘要 + `auditPath`）、`<tasks 根>/<taskId>/runs/reviews_en.json`（人工阅读）、`<tasks 根>/<taskId>/audit/<ts>.json`（成本、行为与配置核对；顶层 `config` 记录全量生效值、来源与 `digest`，秘密只记 `set`）。

### 取回 session：cwd 索引与 `review-pi export`

生产用法是在**代码仓目录**里跑 review。成功后 CLI 在**执行目录**写一份隐藏索引 `.review-pi-session.json`（ADR-0036），只含寻址信息、不含检视内容：

```json
{
  "version": 2,
  "taskId": "change-001",
  "tasksDir": "C:\\Users\\Li\\.PiAgent\\tasks",
  "runId": "20261103_112336_401",
  "repo": "D:\\work\\myrepo",
  "updatedAt": "2026-11-03T11:23:36.401Z",
  "mains": [
    "C:\\Users\\Li\\.PiAgent\\tasks\\change-001\\runs\\session-20261103_112336_401.json"
  ],
  "skills": [
    "C:\\Users\\Li\\.PiAgent\\tasks\\change-001\\runs\\session-20261103_112336_401-skill-general-code-review-r1.json"
  ]
}
```

- 路径**一律绝对**；同一目录重复执行**整份覆盖**，不做历史累积（历史转录仍在 tasks 目录，靠 runId 区分）；
- `version: 2`（ADR-0039）：主转录是数组 `mains[]`（单遍长度 1，分片按 `s01 → s02 → …`）；读取端兼容 v1 的单个 `main`，新写一律 v2；
- 失败 run 不写：索引永远指向**上一次成功**的 run；
- 原子写；写失败只打一行 stderr 警告，`exit` 仍 `0`。

`review-pi export` 读这份索引，往 stdout 打**一行**绝对路径（逗号 + 空格分隔）：单遍是「主 session 在前、skill 按装载顺序」；分片按 **`s01 主 → s01 skill → s02 主 → s02 skill → …`**（ADR-0039 决策 13）：

```bash
review-pi export                      # 读 cwd 索引
review-pi export --path ./sessions    # 复制到该目录：平铺、保留原文件名、同名覆盖
review-pi export --taskId change-001  # 不经索引：读 tasks 根下该任务最新一次 run
```

| 旗标 | 语义 |
|---|---|
| `--taskId <id>` | 指定任务（与 `review` 同口径校验）。runId 由 `run.json` 的 `baseline.auditPath` 反推；单遍 skill 按 `skillPassLog[].transcriptFile` 取，分片主转录按 `shards[].transcriptFile` 取 |
| `--tasks-dir <dir>` | tasks 根覆盖；判定顺序 **cwd 索引 `tasksDir` → 本旗标 → 缺省 `~/.PiAgent/tasks`** |
| `--path <dir>` | 复制目标目录（相对 cwd；不存在则创建）。返回值改为**复制后的**目标绝对路径 |

（完整旗标语义与退出码见 §1.4 / §1.5。）

- **不加载配置、不需要 apiKey、不调模型**——纯文件系统命令；配置文件缺席、CI 容器里也能用。
- 只认**最新一次 run**（`run.json` 每次覆盖）；要历史 run 的转录请直接按 runId 去 `runs/` 取。
- 任一 session 文件缺失 / 任务目录不存在 / 索引非法 ⇒ `exit 1` + 人话原因（不返回幽灵路径）；复制失败不回滚已复制的文件。
- 索引是隐藏文件，**别提交进仓库**（在 git 仓库根跑 review 时把它加进 `.gitignore`）。

## 6. 单次结果的读法

- **issue 用数据集原文**：本例 `--issue` 是缩短版（省略了 CWE 全称括号）。数据集原文见 `data/vul4j/*.json` 的 `issueDescription`，逐字复制才与历史基线同口径；改写 issue 属口径污染。
- **diff 用数据集原生文件**：`.cache/datasets/vul4j-diffs/<case>.diff`，不要手写或重新生成。
- **仓停在 base 侧**：CLI 不 apply diff。
- **单次结果 ≠ 基线**：被测模型非确定，单跑落在历史 rep 波动族内即属正常。本仓已无评测判定链（ADR-0024）：没有 judge / 指标聚合 / S-A-B 判定，跨内核对照请在 DSH 兄弟仓复跑。
- **超界 MR**：超过 `limits.boundary.maxFiles` / `maxDiffLines`（缺省 10 文件 / 2000 变更行）只**告警**不截断（`run/mr-boundary-guard.ts`），结论按 out-of-domain 看待；任一维设 `null` 即该维不设界，双维 `null` 则护栏整体停用。输入先经预过滤（lockfile / 生成物 / minified / 二进制整块剔除，审计 `mrFilter` + stderr 一行），过滤后仍超过 `maxDiffChars`（缺省 1.5M 字符）则**直接报错**（不再等模型返回 4xx）。
- **分片检视（大 MR）**：过滤后 diff 超过 `limits.split.maxShardChars` 且 `limits.split.enabled=true` 时自动分片（缺省 40 万字符）。stderr 的 `[sN/M]` 只是片标签，stdout 仍是**整份合并结果**；`run.json` 多出 `shards[]`（每片 runId / 文件数 / 字符数 / 用量 / 转录与审计相对路径）。聚合审计的 `requests` / `toolCallLog` 为**空是预期**——明细在各片审计里。合并按 `(file, line, title)` 去重（file/title 归一化后比较）：跨片重复只留一条，严重度与 confidence 取最高、evidence 并集保序，最后按「文件首次出现顺序 → 行号 → 严重度」重排并重编号 `F001…`；不做模糊聚类、不跨行合并。

## 7. 常见失败与处置

| 现象（stderr） | 原因 | 处置 |
|---|---|---|
| `review-pi: 拒跑——构建产物缺席/过期（腿: …）` / `依赖未安装或无法解析（腿: …）` | 本包 dist 未构建（或 `src` 比 `dist` 新），或内核四包没装进 `node_modules` | 本包腿按提示 `pnpm --filter @baize/review-pi build`；内核腿按提示 `pnpm install`。bin **不会**自动重编。 |
| 缺 key 的人话错误 | 配置文件里 `reviewer.apiKey` 缺失/为空（环境变量与 `.env.local` 已不再读取） | 跑 `review-pi config init` 生成 `~/.PiAgent/PiAgent.jsonc` 并填 key，或 `--config <path>` 指向已有文件；`review-pi config show` 可确认是否 `set`。 |

## 8. 可复跑的 diff 检视技能（仓内）

`.agents/skills/` 下两个技能把「已知真值 → 构造缺陷 diff → 真跑 → 判定」做成可复跑闭环；它们不改变产品运行时，也不是规则 Skill。

| 技能 | 构造方式 | 默认底座 | 默认是否装规则包 |
|---|---|---|---|
| `real-defect-url-injection` | 对真实修复补丁执行 `git apply -R`，重新引入 URL 参数注入（VUL4J-38 / CVE-2014-4172） | `.cache/datasets/vul4j-repos/VUL4J-38-ab6cbdc3da` + `data/vul4j/materialized-cases.json` | 否 |
| `synthetic-defect-resource-leak` | 在夹具副本新增 `service/cmd/config.go`，`os.Open` 后不关闭（GEN-RES-001） | `packages/review-pi/testdata/repos/multilang` | 是（`general-code-review`） |

```bash
node .agents/skills/real-defect-url-injection/scripts/run.mjs
node .agents/skills/synthetic-defect-resource-leak/scripts/run.mjs
```

两者都通过 `.agents/skills/_shared/review-eval.mjs` 调用本仓 `packages/review-pi/bin/review-pi.js`（因此仍受 bin 的 dist 新鲜度门约束），并把 `defect.diff` / `ground-truth.json` / `meta.json` / `stdout.json` / `stderr.log` / `result/{runs,audit}` / `verdict.{json,md}` 归档到 `repo-diff-skill-result/<skill>/<时间戳>/`。归档目录已 gitignore；`--dry-run` 只构造 diff，`--keep-temp` 保留临时副本，`--fail-on-miss` 在未捕获时 exit 2。
