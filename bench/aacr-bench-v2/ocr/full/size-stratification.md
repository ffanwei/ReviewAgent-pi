# 按 PR 规模分层：小 PR 接近，大 PR 差距扩大

数据：91 条交集 / 588 GT，同一 judge、文件级语义指标、单轮。按每个样本的
`change_line_count`、diff 字节数、changed files 数分箱，箱内汇总 P/R/B。

## 1. 按 changed files 数（最强的分层变量）

| changed files | 样本 | GT | review-pi P/R/B | OCR P/R/B | B 差距 |
|---|---:|---:|---|---|---:|
| ≤5 | 23 | 80 | 0.291 / 0.375 / **0.328** | 0.290 / 0.375 / **0.327** | **−0.001** |
| 6–15 | 15 | 83 | 0.268 / 0.398 / 0.320 | 0.337 / 0.373 / 0.354 | +0.034 |
| 16–40 | 13 | 93 | 0.113 / 0.097 / 0.104 | 0.247 / 0.333 / 0.284 | +0.180 |
| >40 | 40 | 332 | 0.030 / 0.102 / **0.046** | 0.332 / 0.377 / **0.353** | **+0.307** |

**≤5 个文件时两者基本打平；>40 个文件时 review-pi 的 B 只有 OCR 的 13%。**

## 2. 按 diff 字节数

| diff size | 样本 | GT | review-pi P/R/B | OCR P/R/B | B 差距 |
|---|---:|---:|---|---|---:|
| <50KB | 41 | 186 | 0.273 / 0.349 / **0.307** | 0.314 / 0.382 / **0.345** | +0.038 |
| 50–200KB | 20 | 144 | 0.053 / 0.118 / 0.073 | 0.271 / 0.340 / 0.302 | +0.229 |
| 200–500KB | 16 | 133 | 0.059 / 0.120 / 0.079 | 0.340 / 0.436 / 0.382 | +0.303 |
| >500KB | 14 | 125 | 0.015 / 0.064 / 0.024 | 0.327 / 0.312 / 0.319 | +0.295 |

小 diff 接近；diff 一过 50KB，差距立刻拉开。

## 3. 按 change_line_count（不是好变量）

| changed lines | 样本 | GT | review-pi P/R/B | OCR P/R/B | B 差距 |
|---|---:|---:|---|---|---:|
| ≤50 | 19 | 76 | 0.081 / 0.237 / 0.121 | 0.371 / 0.316 / 0.341 | +0.220 |
| 51–150 | 27 | 148 | 0.075 / 0.155 / 0.101 | 0.291 / 0.324 / 0.307 | +0.206 |
| 151–400 | 29 | 157 | 0.085 / 0.268 / 0.128 | 0.299 / 0.427 / 0.352 | +0.224 |
| >400 | 16 | 207 | 0.071 / 0.111 / 0.087 | 0.321 / 0.377 / 0.347 | +0.260 |

**按“改动行数”分层，差距在所有箱都差不多（+0.21～+0.26）。** 说明问题不是“代码改得多”，
而是**变更涉及的文件数/上下文广度**（或生成/数据文件把 diff 撑大）。

## 结论

- **小 PR（按 diff 足迹/文件数，不按 changed lines）**：review-pi 与 OCR 基本持平
  （≤5 文件 B 0.328 vs 0.327；<50KB B 0.307 vs 0.345）。
- **大 PR**：差距迅速扩大（>40 文件 B 0.046 vs 0.353；>500KB B 0.024 vs 0.319）。
- 驱动变量是**文件广度/diff 足迹**，不是改动行数。review-pi 在文件一多时会把意见铺到大量
  无 GT 文件，precision 崩掉；OCR 的文件选择/规则/预算让它在多文件场景保持稳定。
- 这也解释了 smoke10/iter20 为什么接近：它们优先选小 diff/短耗时样本，天然落在“接近”区间。

## 边界

- 分箱样本量 13–41，单轮 judge；B 差距方向稳定，但具体数值有噪声。
- `change_line_count` 只反映改动行，不反映文件数/生成物；因此用它做“大 PR”代理会误导。
- 这里的“小 PR”是 benchmark 视角；产品上仍建议按文件数/上下文广度做分组和预算。
- 按 severity 再拆一层见 [`severity-analysis.md`](severity-analysis.md)：P0–P3 只在小 diff 上有区分度，
  大 diff 上三个级别基本打平；P3 贡献约 1/3 的已覆盖 GT，不能按 severity 删除。
