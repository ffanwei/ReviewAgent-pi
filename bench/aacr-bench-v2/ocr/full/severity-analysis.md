# 按 PR 规模看 severity：P0–P3 只在小 diff 上有区分度

数据：AACR-Bench v2 的 91 条 OCR/review-pi 交集，文件级语义匹配，单轮 judge。
severity 是 review-pi 输出里的 `P0–P3`（模型/规则标注）；AACR GT 本身没有严重级字段。
小 diff = `git diff < 50KB`（41 PR / 186 GT）；小 PR = changed files ≤10（33 PR / 116 GT）。
大 diff = `git diff ≥ 50KB`（50 PR / 402 GT）；大 PR = changed files >10（58 PR / 472 GT）。

## 0. 结论

- **小 diff 上 severity 有信号**：P1 precision 41.4% → P2 29.5% → P3 19.8%，
  Cochran-Armitage 趋势检验 **p = 0.014**；小 PR（≤10 文件）同向，P1 50.0% → P2 29.9% → P3 20.3%（p = 0.0098）。
- **大 diff 上 severity 没有信号**：P1 4.0%、P2 3.6%、P3 2.9%，趋势 **p = 0.51**；
  三个级别都在 3%–4%，差距只有 1 个百分点。
- **P0 基本没被用起来**：1242 条意见里只有 4 条 P0（0.3%），不能作为预算/过滤依据。
- **P3 不能删**：P3 独有覆盖在小 diff 是 22/65（33.8%），大 diff 是 15/41（36.6%）。
- **类别混淆**：P3 里可维护/可读性占比高；固定“可靠性”后 P3 并不比 P2 差。排序应
  **category-first，severity 第二**，不要 severity-first。

## 1. severity 分布

| 子集 | 意见数 | P0 | P1 | P2 | P3 |
|---|---:|---:|---:|---:|---:|
| 小 diff <50KB | 227 | 2（1%） | 29（13%） | 95（42%） | 101（44%） |
| 大 diff ≥50KB | 1015 | 2（0%） | 149（15%） | 556（55%） | 308（30%） |
| 小 PR ≤10 文件 | 163 | 2（1%） | 20（12%） | 67（41%） | 74（45%） |
| 大 PR >10 文件 | 1079 | 2（0%） | 158（15%） | 584（54%） | 335（31%） |

大 PR 更偏 P2，小 PR 更偏 P3；P1 占比两边接近（12%–15%），P0 两边都只有 2 条。

## 2. 小 diff（<50KB）：P1 > P2 > P3

| severity | 意见数 | 命中 | Precision | 95% CI | 落在有 GT 文件 | 平均 confidence |
|---|---:|---:|---:|---|---:|---:|
| P0 | 2 | 2 | 100% | 34%–100% | 100% | 0.91 |
| P1 | 29 | 12 | **41.4%** | 26%–59% | 75.9% | 0.81 |
| P2 | 95 | 28 | **29.5%** | 21%–39% | 75.8% | 0.65 |
| P3 | 101 | 20 | **19.8%** | 13%–29% | 64.4% | 0.61 |

- P1 precision 约是 P3 的 **2.1 倍**；
- P1/P2 的 on-GT share 都是约 76%，P3 降到 64.4%；
- P0 只有 2 条且全部命中，不能据此认为 P0 可靠。

## 3. 小 PR（≤10 文件）：结论一致

| severity | 意见数 | 命中 | Precision | 落在有 GT 文件 |
|---|---:|---:|---:|---:|
| P0 | 2 | 2 | 100% | 100% |
| P1 | 20 | 10 | **50.0%** | 80.0% |
| P2 | 67 | 20 | **29.9%** | 79.1% |
| P3 | 74 | 15 | **20.3%** | 73.0% |

P1 → P2 → P3 的下降比按 diff 字节更明显，趋势检验 p = 0.0098。

## 4. 大 diff（≥50KB）：三个级别基本打平

| severity | 意见数 | 命中 | Precision | 落在有 GT 文件 |
|---|---:|---:|---:|---:|
| P0 | 2 | 0 | 0% | 0% |
| P1 | 149 | 6 | **4.0%** | 11.4% |
| P2 | 556 | 20 | **3.6%** | 11.3% |
| P3 | 308 | 9 | **2.9%** | 7.5% |

- P1 和 P2 的 precision、on-GT share 几乎完全一样；
- P3 只低约 1 个百分点；
- 趋势检验 p = 0.51，没有统计信号。

**大 PR 的瓶颈不是 severity，而是文件靶向**：不管标 P1 还是 P3，大多数意见落在没有 GT 的文件上。
这与 [`size-stratification.md`](size-stratification.md) 的结论一致——差距由 changed files / diff 足迹驱动，
不是由“模型判得准不准”驱动。

## 5. 统计检验

| 子集 | P1→P2→P3 趋势 | P1 vs P2 | P2 vs P3 | P1 vs P3 |
|---|---:|---:|---:|---:|
| 小 diff <50KB | **p = 0.014** | p = 0.260 | p = 0.136 | **p = 0.027** |
| 小 PR ≤10 文件 | **p = 0.0098** | p = 0.113 | p = 0.242 | **p = 0.011** |
| 大 diff ≥50KB | p = 0.511 | — | — | — |
| 大 PR >10 文件 | p = 0.625 | — | — | — |
| 全部 91 | p = 0.279 | — | — | — |

解读：

- 小 diff 上的**单调趋势**是显著的，但两两比较只有 **P1 vs P3** 显著；
- P1 vs P2、P2 vs P3 在小样本下都不显著，不能把 P2 当成独立档位；
- 大 diff 上趋势不显著，severity 不能作为过滤/排序的主要依据。

## 6. 类别混淆：P3 的低分不全是 severity 的错

小 diff 上 P3 的类别构成：

| P3 类别 | 条数 |
|---|---:|
| 可维护 | 41 |
| 可读性 | 32 |
| 可靠性 | 17 |
| 可移植 | 5 |
| 安全 | 3 |
| 性能 | 1 |
| 可维护性（变体） | 1 |
| 可测试性 | 1 |
| **合计** | **101** |

P3 里只有 17 条是“可靠性”，大部分是可维护/可读性——这两类本身命中率就低。
固定类别，只看“可靠性”：

| 子集 | severity | 条数 | 命中 | Precision |
|---|---|---:|---:|---:|
| 小 diff，仅可靠性 | P1 | 24 | 11 | **45.8%** |
| 小 diff，仅可靠性 | P2 | 63 | 20 | 31.7% |
| 小 diff，仅可靠性 | P3 | 17 | 6 | **35.3%** |
| 大 diff，仅可靠性 | P1 | 120 | 6 | 5.0% |
| 大 diff，仅可靠性 | P2 | 353 | 10 | 2.8% |
| 大 diff，仅可靠性 | P3 | 41 | 1 | 2.4% |

在可靠性内部，小 diff 的 P3 并不比 P2 差（35.3% vs 31.7%，但 P3 只有 17 条）。
所以 severity 的总体区分度，有一部分来自“P3 里堆了更多可维护/可读性”。

## 7. P3 是召回的重要来源，不能删

| 子集 | 总覆盖 GT | P1+P2 覆盖 | P3 独有覆盖 | P3 占覆盖 | 删 P3 后 recall |
|---|---:|---:|---:|---:|---:|
| 小 diff <50KB | 65 | 43 | **22** | **33.8%** | 0.231（原 0.349） |
| 大 diff ≥50KB | 41 | 26 | **15** | **36.6%** | 0.065（原 0.102） |

**P3 贡献了约三分之一的已覆盖 GT。** 按 severity 一刀切删 P3，会把 recall 分子一起删掉。
这与 [`category-severity-filter.md`](category-severity-filter.md) 的结论一致：severity/category 都不适合做硬过滤。

## 8. P0 的问题

- 91 条 / 1242 条意见中只有 **4 条 P0**，占 0.3%；
- 小 diff 2 条全命中，大 diff 2 条全不中；
- 作为“最高优先级”档位，P0 目前没有实际作用；
- 建议人工抽检这 4 条，确认 P0 的定义是否被正确执行；在完成校准前，不要用 P0 做预算/过滤门槛，
  可暂时并入 P1。

## 9. 建议

1. **小 diff**：severity 可以作为第二层排序信号，但不要把它当独立质量分。推荐
   `category-first → severity → confidence → diff locality → evidence`。
2. **大 diff**：不要按 severity 调过滤阈值；改用 ≤10 文件 / <50KB 分组、文件范围门、每 PR 预算
   （见 [`optimization-plan.md`](optimization-plan.md)、[`budget-tuning.md`](budget-tuning.md)）。
3. **输出预算**：8 个槽不要全给 P1/P2，建议至少留 2–3 个给 P3 / 新文件，否则 recall 会明显下降。
4. **P3 保留**：优化方向应是提高 P3 的文件靶向和失败场景质量，而不是删除 P3。
5. **P0 重新校准**：明确 P0 的触发规则并抽检；校准前不要把 P0 用作硬门槛。

## 10. 边界

- 单轮 judge、文件级语义匹配；severity 是模型/规则自评，不是人工 GT 严重级。
- P0/P1 样本量小（P0 仅 4 条），P1 vs P2、P2 vs P3 的差异不显著；上述 p 值仅作探索性参考。
- 分箱是描述性统计，单轮结果有噪声；方向稳定，具体数值不应过度解读。
- 无 GT 文件上的意见不一定是误报，可能只是 AACR 未标注；precision 是 benchmark 文件级口径。
