# OCR vs review-pi：91 条全量交集

> 交集 = OCR 成功（exit 0）∩ review-pi ok，共 91 条 / 588 GT。
> 同一 judge `deepseek-v4-pro`、同一文件级语义指标、单轮评测。
> OCR：`open-code-review v1.13.10` + `deepseek-v4.1-flash`；review-pi：`0.6.1` + `deepseek-v4.1-flash`。

## 总体

| 指标 | OCR | review-pi | 差异 |
|---|---:|---:|---:|
| Precision | **0.3128** | 0.0781 | **4.01×** |
| Recall | **0.3690** | 0.1803 | **2.05×** |
| Balanced | **0.3386** | 0.1090 | **3.11×** |
| 覆盖 GT | **217 / 588** | 106 / 588 | +111 |
| 生成意见 | **601** | 1242 | −641 |
| 总 token（含 cache） | 198,665,508 | 200,753,912 | 0.99× |
| token（非缓存 input+output） | 29,810,212 | 18,856,824 | 1.58× |
| 评审耗时 | **26,891s** | 43,159s | **0.62×** |

核心结论：**在同一批 91 条样本上，OCR 用更少的意见（601 vs 1242）、相近的总 token、约 0.62 倍的耗时，取得了约 4 倍的 precision、2 倍的 recall 和 3.1 倍的 balanced。** review-pi 的 high-volume 输出没有转化为 GT 覆盖。

## 为什么和 smoke10 的结论不同

smoke10 上两者接近（OCR B 0.2697 vs review-pi 0.2477），但这个 91 条交集上 OCR 大幅领先（0.3386 vs 0.1090）。原因是：

- smoke10 是 **outcome-stratified 的 10 条开发集**：5 条“基线有命中”+5 条“基线零命中”，且优先挑小 diff/短耗时样本；
- 它恰好包含了 review-pi 表现较好的 `lvgl`、`filament`、`linera`，放大了 review-pi 的相对表现；
- 91 条交集覆盖 10 种语言和更大的样本范围，更能代表两者的实际差距。

**因此：smoke10 适合做“改动是否有效”的快速回归，不适合做两者排名；全量交集才是排名依据。**

## 口径与限制

- 交集只包含 **两者都成功**的 91 条；OCR 总成功 113 条，review-pi 总成功 108 条。OCR 在 113 条上的指标为 P 0.303 / R 0.377 / B 0.336。
- OCR 版本 v1.13.10，官方 leaderboard 是 v1.3.1/v1.8.7；不能与官方表逐行对齐。
- 单轮 judge；judge 噪声在 91 条上比 10 条小，但仍不是零。
- token 口径：OCR 的 total tokens 包含 cache read；review-pi 的 token_usage 也同样拆分。总 token 接近，但 review-pi 的 cache read 占比更高，非缓存 token 更少。
- AACR v2 的 GT 77% 是 AI 评论，文件级指标不看行号。

## 结论

在同一批可比的 91 条真实 PR 上，**OCR 明显优于 review-pi**：precision 约 4 倍、recall 约 2 倍、balanced 约 3.1 倍；同时评审耗时只有 review-pi 的 0.62 倍，总 token 基本持平（非缓存 token 1.58 倍）。review-pi 的主要问题是意见量大但命中率低：1242 条意见只覆盖 106 条 GT，而 OCR 601 条意见覆盖 217 条。
