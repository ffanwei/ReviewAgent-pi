## 3. 排序键：category-first 明显最好

| 排序键 | 最优 B | P | R | 最优参数 |

| **cat_sev_conf**（category → severity → confidence） | **0.1392** | 0.1584 | 0.1241 | scope, top6, cap4 |

| conf_sev | 0.1348 | 0.1250 | 0.1463 | scope_config, top10, cap4 |

结论：**先把类别权重放在最前面**（可靠性/安全 3、性能 2、可维护/可移植/可测试 1、可读性 0.5），
再按 severity、confidence；纯 confidence 排序最差。

## 6. 反射过滤（确定性代理）

| 过滤 | 最优 B | 说明 |
|---|---:|---|
| scope（hunk 外丢弃） | 0.1392 | 小幅提升；只影响 40 条 |
| scope_config（+配置/数据文件） | 0.1388 | on-GT 37.1%，略高 |
| config（仅文件排除） | 0.1385 | 与 none 接近 |
| none | 0.1381 | 基线（带排序/预算） |
| desc40（描述长度 <40 丢弃） | 0.1381 | 无变化 |
| style_title（标题含建议/考虑/风格/命名/格式/注释） | 0.1354 | 变差 |
| conf50（confidence <0.5 丢弃） | 0.1318 | 变差 |
| combo（scope+config+conf50+desc40） | 0.1340 | 过度过滤 |

证据条数过滤未能可靠模拟（桥接结果里没有 evidence 字段），未纳入结论。

**结论：确定性反射只能提供很小的增益；真正有效的是排序 + 预算。** 模型级 reflection 未在本次模拟中，
需要单独实验和 token 预算。

## 7. 稳定性（2-fold CV）

按 instance_id hash 分两折（53 / 38）：

| 集合 | baseline B | 最优参数 B |
|---|---:|---:|
| full | 0.1090 | 0.1392 |
| fold A | 0.1157 | 0.1517 |
| fold B | 0.0988 | 0.1208 |

交叉验证：

- 在 A 上调参（scope/cat_sev_conf/top8/cap3）→ 在 B 上 B 0.1096（B 基线 0.0988，**+0.0108**）；
- 在 B 上调参（none/cat_sev_conf/top4）→ 在 A 上 B 0.1222（A 基线 0.1157，**+0.0065**）。

**方向稳定，但全量最优 0.1392 有乐观偏差；held-out 预期约 +0.007–0.011 B。**

## 8. 建议

1. **产品默认候选**：`scope` + `cat_sev_conf` 排序 + **top 8/PR + cap 3/file**（B 0.1376，held-out 约 0.11–0.12）。
2. 若只追求 Balanced：top 6/PR + cap 4（B 0.1392，但 overfit 风险更高）。
3. 若召回优先：top 15/PR + scope_config（B 0.1351，R 0.168）。
4. **不要**只做 per-file cap、只做类别删除、只做 confidence/severity 阈值——已分别验证无效。
5. 输出侧排序/预算不增加模型 token；模型级 reflection 需要额外预算，未在本次模拟中。

## 9. 边界

- 91 条样本、单轮 judge；全量最优有选择偏差，2-fold 结果更可信。
- 输出侧模拟；真实实现若改变输入侧（文件过滤/规则），需要重跑。
- on-GT 最高 35.7%–37.1%，仍远低于 OCR 的 82%；**输出过滤不能单独补上文件靶向/规则层的差距**。
