# F-07 讨论归档

## 2026-11-22 · 开工口径与编号订正

- 编号订正：map 原来把 F-07 挂在「P1-7、V5」；设计文档里阶段压缩是 **P1-6**（E5 三臂 A/B），
  P1-7 是「风险驱动预算」。本节起按 P1-6 记录，风险驱动预算不并入 F-07。
- 为什么做：六阶段里 Phase 1/2 是固定开销；Phase 2 的 `riskClass` 没有任何消费者，
  每个 run/片都白花一个请求。Phase 3 判完 `neededContext` 后，Phase 4 在无需求时仍会
  发一个“无法检索/无更多上下文”的请求，也是纯空转。
- 压缩方式：合并 1+2（一个请求出 summary + riskClass + reason），Phase 3 输出空
  `neededContext` 时跳过 Phase 4。预期每单元 4–5 个请求。
- 审计口径：不改阶段名与顺序，被跳过的阶段写 `requestCount = 0` + note；
  这样下游按 phase 名取数据的脚本不受影响。
- 失败语义：Phase 3 的 `neededContext` 解析不出来时**不跳** Phase 4（fail-open，
  宁可多一个请求，不在证据不足时省检索）。
- 风险字段：v1 只要求输出并写进审计 note，不驱动预算；是否消费由 P1-7 决定。
  如果 P1-7 最终决定删除风险分级，F-07 的合并指令再收敛为只出 summary。
- 验证：先离线单测锁请求数与阶段留痕，再跑 6 阶段 vs compact 的 live A/B；
  验收看 P/R/B ±2pp、请求数下降、分片样本收益按片放大。

## 2026-11-22 · A/B 结果：压缩不成立，质量方向为正但未证实

- S20 主判据（20 条 / 73 GT，两臂 c=5，judge 1 轮）：
  - off：P 31.4% / R 21.9% / B 25.8%，请求 308，token 6.60M，平均 129.7s；
  - compact：P 39.6% / R 27.4% / B 32.4%，请求 306，token 7.70M，平均 151.2s；
  - Δ：P +8.2pp、R +5.5pp、B +6.6pp，token/墙钟各 +16.6%，逐条 5 好 / 3 差 / 12 平，
    bootstrap 的 ΔB 95% CI = −4.3 ~ +15.1pp（跨 0）。
- S10 两对复本方向相反（ΔB −9.9pp / +14.1pp），同臂跨运行波动 10–14pp，
  说明小样本单次不可判；S20 的正向变化也尚未跨出噪声。
- 机制拆解：Phase 2 请求确实全免（S20 省 23 个），但 Phase 1 工具调用从 40 → 84，
  把省下的请求花回去；条件化 Phase 4 在 S20 的 20 条里 **0 次触发**（neededContext 从未为空）。
  因此“少一个固定阶段”在真实流量里没有可测的请求收益。
- 判读：S20 的质量提升更像合并提示诱发了更多 Phase 1 探索（token/墙钟同步 +16.6%），
  不是压缩本身；不满足 F-07 验收（请求下降、token 不升），暂不默认开启。
- 待决：保持 opt-in 归档，或先隔离“Phase 1 探索 vs 合并本身”——给 compact 的 Phase 1
  加“不调用工具、只基于 diff 回答”，复跑 S20 后再决定是否值得保留该机制。
- 证据：`bench/experiments/2026-11-22-f07/README.md`（含 S20 分阶段请求表与 S10 复本）。

## 2026-11-22 · 隔离变量：Phase 1 禁止工具（compact3）

- 改动：COMPACT_UNDERSTANDING 增加「本阶段不要调用工具」；S20 同条件复跑（c=5，judge 1 轮）。
- 结果：Phase 1 请求 84 → 20（每条恰好 1 次），总请求 306 → 271（比 off 308 少 12%），
  token 7.70M → 6.27M（比 off 6.60M 少 5%）。
- 质量：P 42.9% / R 30.1% / B 35.4%，对 off（31.4/21.9/25.8）为 +11.5 / +8.2 / +9.6pp；
  逐条 6 好 / 1 差 / 13 平；ΔB 的 bootstrap 95% CI = +1.35 ~ +15.63pp，跨出 0。
- 解读：前一轮 compact 的质量提升不是单纯“探索变多”——禁止工具后质量仍高、成本还降；
  说明合并 Phase 1+2 本身可能有效（或至少无害），条件化 Phase 4 仍是无效杠杆（0 次触发）。
- 风险：单次运行；墙钟 +18.6% 与 token 下降矛盾；需要一对复本（off + compact3）确认后再决定默认值。

## 2026-11-22 · 决策：默认 compact

- 隔离实验（Phase 1 禁工具）显示压缩可以有真实收益：S20 请求 −12%、token −5%，
  B +9.6pp（95% CI +1.35 ~ +15.63pp），Phase 1 请求从 84 降到 20。
- 与 S10 的方向不一致（两对复本 −9.9/+14.1pp）说明证据仍在噪声边缘；但方向一致为正、
  成本项至少不升，用户确认按默认开启处理。
- 落地：`DEFAULT_LIMITS.loop.stageCompression = "compact"`，配置模板与示例同步；
  保留 `"off"` 作为回滚；ADR-0113 记录证据与风险（墙钟 +18.6% 未解释）。
- 风险记账：后续基准若出现 R 回退或墙钟不可接受，先切回 `off` 再定位；
  条件化 Phase 4 0 次触发，后续作为独立清理项。
