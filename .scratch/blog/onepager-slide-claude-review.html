学 OCR · 语义分组

语义分组：≤10 文件/组、组间并发。为什么：大 MR 按语义聚组，跨文件耦合不被切散，还能并行评审。

--preview：零模型确认会审哪些文件

--resume + manifest：断点续跑、覆盖可解释

学 CodeRabbit · 增量检视

增量检视：只审 merge-base 之后的新提交。为什么：新推送不再全量重跑，省 token / 墙钟，也少重复评论。

PR 原生 + chat：自动评审、摘要、状态

auto-fix + 看板：修复闭环与团队趋势

学 Claude Code · 验证配方

角度清单：A–E + cleanup 五角度

effort + max-findings：一个质量 / 成本旋钮

三态 verdict + 补漏 sweep：PLAUSIBLE 与最后找漏

不照搬
  • 规则默认自动分层
  • 先做席位 SaaS 再补闭环
  • 免验证的 recall 优先
  • findings 只进宿主 UI
  • 为评论数量牺牲证据
一句话

效果上守证据与覆盖、补语义分组；采用上补 PR 增量与成本旋钮；借三家的机制，不借它们的宿主依赖与黑盒。
