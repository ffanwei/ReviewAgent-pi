Design review · review-pi

单会话多策略检视

一笔 MR、一个六阶段、一份 findings。策略按 diff --git 文件块确定性分类，每个块按自己的尺子被检视；全代码 MR 保持逐字节零漂移。

确定性分类 per-kind findingScope 无新增模型调用 逃生口：按 kind 分片

三条不变量

它们同时是验收口径，防止“多策略”退化成一套模糊的混合提示词。

INVARIANT 01

全代码 MR 零漂移

不注入 brief，Zone A、工具 schema、阶段消息、审计字节都与今天一致；既有 code trace 可原样回放。

INVARIANT 02

策略选择确定性

路径 + 配置决定 kind，模型不参与选择。不按 hunk 分类、不嗅探内容，分类结果进审计。

INVARIANT 03

单遍单会话

一次 runAgentReviewLoop、一份 findings。不新增模型调用，不新增编排层；分片仍只作体积逃生口。

每个 kind 换什么

骨架不变，换的是上下文目标、证据形态、示例形态与位置门；Finding 的十三个字段与七类 category 都不动。

维度 code doc skill-doc
上下文 符号 / 引用 / 调用链 引用路径、命令、相关文档、本 MR 代码 运行时工具名 / 配置键 / frontmatter
证据 行号 + 代码摘录 引文 + 目标文件:行 + 读取结果 文档引文 + 运行时文件:行
tips 示例 代码示例 Markdown / 配置 / shell 片段 同 doc
位置门 hunk ± 10 whole-file（文件需在 diff 中） whole-file
严重级 现有 P0–P3 定义 P3 措辞 / P2 过期 / P1 误配置 同 doc
历史文档 — docs/adr/** 按当时口径读，只报内部矛盾 —

配置面

分类规则在 strategy，位置门在既有的 limits.findingScope；缺席即沿用今天的全代码行为。

{
  "strategy": {
    "enabled": true,
    "skillDocGlobs": ["**/SKILL.md"],
    "docGlobs": ["**/*.md", "**/*.mdx", "**/*.rst", "**/*.adoc", "**/README*"],
    "codeGlobs": []
  },
  "limits": {
    "findingScope": {
      "enabled": true,
      "contextLines": 10,
      "docMode": "whole-file"
    }
  }
}

需要拍板

下面六点会改变默认行为或边界纪律；确认后这份图就可以落成 ADR 与实施票。

  • 默认开关：strategy.enabled 缺省 true，还是显式 opt-in？
  • docMode 缺省：whole-file，还是保守的 context？
  • doc-only 轮次：压到 1 轮，还是沿用 maxRounds 的 3？
  • 未变更文件：「文档未更新」是否保持 OUT_OF_SCOPE？
  • 命令核对：接受静态核对，还是加第八个工具 / 带 bash 的文档 Skill？
  • 历史文档：清单里按路径写特例，还是单独分一个 kind？
